## 1. 什么场景需要平台能力

Flutter 能画界面、能发网络请求、能写本地存储，但它**运行在 Dart VM 的沙箱里**，碰不到系统的相机、蓝牙、传感器、推送服务。企业 App 的以下需求，全部要跨出 Dart 世界：

| 需求 | 涉及的原生能力 | 典型插件 |
| --- | --- | --- |
| 推送 | 厂商推送 SDK、通知栏 | 极光/个推/厂商 SDK |
| 扫码 | 相机 + 解码库 | mobile_scanner |
| 定位 | GPS/基站/WiFi 定位 | geolocator |
| 生物识别 | 指纹/FaceID/人脸 | local_auth |
| 支付 | 微信/支付宝 SDK | fluwx / tobias |
| 厂商适配 | 通知通道、电池白名单、厂商商店 | 各自为战，无统一插件 |
| WebView | 内置浏览器内核 | webview_flutter |

写过 H5 的同学可以这么理解：Dart 之于原生，就像 JS 之于浏览器内核——你能操作 DOM，但调不了摄像头底层的曝光参数，得靠浏览器暴露的 `getUserMedia`。Flutter 里这个"浏览器暴露的 API"就是 Platform Channel（平台通道）。

## 2. 优先级方法论：先找插件，再谈手写

**核心原则：能在 pub.dev 上搜到维护良好的官方或高星插件，就不要自己写原生。**

这不是偷懒，是工程判断。手写原生意味着同时维护 Kotlin + Swift 两套代码、自己处理各厂商兼容性、自己踩 API 版本坑，一个三人 Flutter 团队养不起"每个原生功能都自研"的成本。

### 2.1 插件选型 checklist

按顺序核对，任何一条不过关就要谨慎：

1. **支持平台**：看 pub.dev 的 Platforms 徽标，确认覆盖你的目标平台（后续要上 Web/桌面端尤其注意）。
2. **维护活跃度**：最近发布时间（超 1 年未更新要警惕）、issue 回复情况、是否适配最新稳定版。
3. **文档质量**：README 有完整示例、CHANGELOG 清晰记录 Breaking Change。
4. **issue 区**：搜目标机型/厂商关键词（"xiaomi" "huawei"），看有没有未解决的硬伤。
5. **依赖健康**：`flutter pub deps` 看传递依赖是否冲突（Kotlin/Gradle 版本冲突是企业高频坑）。

**反面案例**：某团队用了一个两年没更新的扫码插件，Android 13 上相机权限申请直接失效，被迫在发版前一周自己 fork 修——这种事故就是选型时欠的债。

**什么时候才该自己写原生？** 业务强相关且无通用插件（自研播放器内核、安全键盘）；插件维护停滞且 fork 成本 < 替换成本；性能敏感需要原生线程高频回调（相机预览帧处理）。

## 3. Platform Channel 原理

### 3.1 三种通道

| 通道 | 通信模型 | 适用场景 | H5 心智对照 |
| --- | --- | --- | --- |
| MethodChannel | 方法调用 + 返回值（含异常） | 大多数场景：调原生方法拿结果 | JSBridge 的 `window.native.callHandler(name, args, callback)` |
| EventChannel | 数据流（原生 -> Dart 单向订阅） | 传感器、电量、位置持续更新 | `addEventListener('deviceorientation', ...)` |
| BasicMessageChannel | 双向消息收发 | 自定义编解码的高频通信 | `iframe` + `postMessage` 互相丢消息 |

### 3.2 消息编解码

通道数据走标准编解码器（StandardMessageCodec），支持 null、bool、int（64 位）、double、String、List/Map（可嵌套）、Uint8List 等二进制类型。**不支持 Dart 自定义类对象**——想传对象要么手动转 Map，要么用 Pigeon（第 5 节）。

### 3.3 架构图

```
┌───────────────────────────── Flutter App ─────────────────────────────┐
│   Dart 层（UI 线程 / 主 isolate）                                     │
│   ┌──────────────┐   ┌──────────────┐   ┌───────────────────┐         │
│   │MethodChannel │   │EventChannel  │   │BasicMessageChannel│         │
│   └──────┬───────┘   └──────┬───────┘   └────────┬──────────┘         │
│          │      二进制序列化（StandardCodec）      │                    │
├──────────┼──────────────────┼───────────────────┼─────────────────────┤
│          ▼                  ▼                   ▼      平台通道层      │
│   ┌─────────────────────────────────────────────────┐                │
│   │     平台主线程（Android Main / iOS Main）        │                │
│   │   Kotlin: MethodChannel.setMethodCallHandler    │                │
│   │   Swift:   FlutterMethodChannel(...)            │                │
│   └──────────────────────┬──────────────────────────┘                │
│   ┌──────────────────────▼──────────────────────────┐                │
│   │      系统服务（相机/定位/传感器/推送）            │                │
│   └─────────────────────────────────────────────────┘                │
└───────────────────────────────────────────────────────────────────────┘
```

### 3.4 线程模型（重要）

- Dart 端 handler 默认跑在 **UI 线程**（主 isolate），回调里可以直接 `setState`。
- 原生端 handler 默认跑在**平台主线程**（Android Main / iOS Main）。**不要在 handler 里做耗时操作**，会卡原生 UI 甚至 ANR——耗时的活开子线程/协程，做完再回主线程回传结果。

## 4. 手写一个完整的 MethodChannel

需求：获取设备电池电量 + 弹原生 Toast。虽然 pub.dev 有 battery_plus / fluttertoast，但这两个例子足够简单，适合把三端代码跑通——企业里你总会遇到要手写的场景。

### 4.1 错误码约定（企业规范）

先定规矩再写代码。错误码统一收敛在一个 Dart 文件，Dart/Android/iOS 三端共用同一套数值：

```dart
// lib/platform/channel_error_codes.dart
/// 平台通道错误码统一管理
/// 规则：五位数字，前两位表示模块，后三位表示具体错误
/// 三端（Dart/Kotlin/Swift）必须使用同一套 code，message 可本地化
class ChannelErrorCodes {
  ChannelErrorCodes._();

  static const String unimplemented = '10001'; // 通用：该平台不支持此能力
  static const String invalidArgs = '10002'; // 通用：参数错误
  static const String nativeError = '10003'; // 通用：原生处理异常（兜底）
  static const String batteryReadFailed = '20001'; // 设备模块：电量读取失败
  static const String toastShowFailed = '20002'; // 设备模块：Toast 展示失败
}
```

原生端抛错时 `code` 必须引用同一套值——可在原生侧也建常量类，或靠 code review 保证同步。

### 4.2 Dart 端

```dart
// lib/platform/device_channel.dart
import 'package:flutter/foundation.dart';
import 'package:flutter/services.dart';

import 'channel_error_codes.dart';

/// 设备能力通道：电池电量 + 原生 Toast
class DeviceChannel {
  DeviceChannel._();

  /// 通道名：企业规范——按模块命名，避免冲突
  static const MethodChannel _channel = MethodChannel('com.company.app/device');

  /// 获取电池电量（0~100），失败抛 DeviceChannelException
  static Future<int> getBatteryLevel() async {
    try {
      return await _channel.invokeMethod<int>('getBatteryLevel') ?? -1;
    } on PlatformException catch (e) {
      // 统一转成业务异常向上抛，别让 UI 层直接摸 PlatformException
      throw DeviceChannelException(code: e.code, message: e.message ?? '读取电量失败');
    } on MissingPluginException {
      // 通道未注册（热重载后原生侧没重启，或 Add-to-App 宿主没注册）
      throw DeviceChannelException(
        code: ChannelErrorCodes.unimplemented,
        message: '当前平台未实现该能力',
      );
    }
  }

  /// 弹原生 Toast（短时长）
  static Future<void> showToast(String message) async {
    try {
      await _channel.invokeMethod<void>('showToast', {'message': message});
    } on PlatformException catch (e) {
      debugPrint('showToast 失败: ${e.code} ${e.message}');
      rethrow;
    }
  }
}

/// 平台通道业务异常
class DeviceChannelException implements Exception {
  DeviceChannelException({required this.code, required this.message});

  final String code;
  final String message;

  @override
  String toString() => 'DeviceChannelException($code): $message';
}
```

UI 侧调用示例：

```dart
// lib/pages/device_demo_page.dart（节选）
import '../platform/device_channel.dart';

Future<void> loadBattery() async {
  try {
    final level = await DeviceChannel.getBatteryLevel();
    debugPrint('当前电量：$level%'); // 实际项目 setState 更新界面
  } on DeviceChannelException catch (e) {
    debugPrint('读取失败: ${e.code} ${e.message}'); // 展示错误提示或降级
  }
}
// 按钮触发：FilledButton(onPressed: loadBattery, child: Text('获取电量'))
```

### 4.3 Android 端（Kotlin）

```kotlin
// android/app/src/main/kotlin/com/company/app/MainActivity.kt
package com.company.app

import android.os.BatteryManager
import android.content.Context
import android.widget.Toast
import io.flutter.embedding.android.FlutterActivity
import io.flutter.embedding.engine.FlutterEngine
import io.flutter.plugin.common.MethodChannel

class MainActivity : FlutterActivity() {
    private val channelName = "com.company.app/device"

    override fun configureFlutterEngine(flutterEngine: FlutterEngine) {
        super.configureFlutterEngine(flutterEngine)

        MethodChannel(flutterEngine.dartExecutor.binaryMessenger, channelName)
            .setMethodCallHandler { call, result ->
                when (call.method) {
                    // BatteryManager 读电量是轻量操作，主线程可直接做；重活必须开协程
                    "getBatteryLevel" -> {
                        val bm = getSystemService(Context.BATTERY_SERVICE) as BatteryManager
                        val level = bm.getIntProperty(BatteryManager.BATTERY_PROPERTY_CAPACITY)
                        if (level in 0..100) result.success(level)
                        else result.error("20001", "电池信息读取失败", null)
                    }
                    "showToast" -> {
                        val message = call.argument<String>("message")
                        if (message == null) {
                            result.error("10002", "缺少 message 参数", null)
                            return@setMethodCallHandler
                        }
                        Toast.makeText(applicationContext, message, Toast.LENGTH_SHORT).show()
                        result.success(null)
                    }
                    else -> result.notImplemented()
                }
            }
    }
}
```

**Android 侧注意点**：`result` 只能回调一次，分支里已经 `result.error(...)` 后必须 `return`，否则双回调会崩溃。

### 4.4 iOS 端（Swift）

```swift
// ios/Runner/AppDelegate.swift
import UIKit
import Flutter

@UIApplicationMain
@objc class AppDelegate: FlutterAppDelegate {
  override func application(
    _ application: UIApplication,
    didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
  ) -> Bool {

    if let controller = window?.rootViewController as? FlutterViewController {
      let channel = FlutterMethodChannel(
        name: "com.company.app/device",
        binaryMessenger: controller.binaryMessenger
      )

      channel.setMethodCallHandler { [weak self] (call, result) in
        switch call.method {
        case "getBatteryLevel":
          // batteryLevel 在模拟器上恒为 -1，真机才有值
          UIDevice.current.isBatteryMonitoringEnabled = true
          let level = UIDevice.current.batteryLevel
          if level >= 0 {
            result(Int(level * 100))
          } else {
            result(FlutterError(code: "20001", message: "电池信息不可用", details: nil))
          }
        case "showToast":
          guard let args = call.arguments as? [String: Any],
                let message = args["message"] as? String else {
            result(FlutterError(code: "10002", message: "缺少 message 参数", details: nil))
            return
          }
          self?.showToast(message: message, result: result)
        default:
          result(FlutterMethodNotImplemented)
        }
      }
    }

    return super.application(application, didFinishLaunchingWithOptions: launchOptions)
  }

  /// iOS 没有系统级 Toast，用 UIAlertController 模拟（真实项目建议 Dart 侧画 Toast）
  private func showToast(message: String, result: @escaping FlutterResult) {
    guard let controller = window?.rootViewController else {
      result(FlutterError(code: "20002", message: "找不到根视图控制器", details: nil))
      return
    }
    let alert = UIAlertController(title: nil, message: message, preferredStyle: .alert)
    controller.present(alert, animated: true)
    DispatchQueue.main.asyncAfter(deadline: .now() + 1.5) { alert.dismiss(animated: true) }
    result(nil)
  }
}
```

**iOS 侧注意点**：`@UIApplicationMain` 在新版 Xcode 可换成 `@main`，以工程模板为准；电量在模拟器上恒为 -1，UI 要区分提示。

### 4.5 三端联调的坑

- **热重载不生效**：改了原生代码必须**完全停止 App 重新编译运行**，热重载只对 Dart 生效——新手最高频的"我明明改了为什么不生效"。
- 通道名拼写三端必须完全一致，定义成常量并写进团队 wiki。

## 5. Pigeon：类型安全的 Channel

手写字符串通道的问题：方法名/参数 key 拼错编译期不报错；参数类型靠 `call.argument<T>()`，空安全全靠自觉；三端没有单一事实来源（single source of truth）。

大型项目推荐 [pigeon](https://pub.dev/packages/pigeon)：用 Dart 写接口定义，代码生成器产出三端类型安全的绑定代码：

```dart
// pigeons/device_api.dart
// 注意：这是"接口定义"文件，不是业务代码
import 'package:pigeon/pigeon.dart';

@HostApi()
abstract class DeviceApi {
  /// 获取电池电量
  int getBatteryLevel();

  /// 弹 Toast
  void showToast(String message);
}
```

配置 build.yaml 后执行 `dart run pigeon`，生成 Dart 接口实现、Kotlin 抽象类、Swift 协议。原生侧实现生成的抽象类/协议并注册，方法签名与类型全由生成代码保证，改接口时三端编译期同时报错。**企业建议**：超过 3 个方法的通道一律走 Pigeon，手写通道只留给一次性小需求。

## 6. 高频原生插件实战

### 6.1 扫码：mobile_scanner

```yaml
# pubspec.yaml
dependencies:
  mobile_scanner: ^5.2.3  # 版本以 pub.dev 实际为准
```

```dart
// lib/pages/scan_page.dart
import 'package:flutter/material.dart';
import 'package:mobile_scanner/mobile_scanner.dart';

class ScanPage extends StatefulWidget {
  const ScanPage({super.key});

  @override
  State<ScanPage> createState() => _ScanPageState();
}

class _ScanPageState extends State<ScanPage> {
  final MobileScannerController _controller = MobileScannerController();

  @override
  void dispose() {
    // 控制器必须释放，否则相机持续占用，下次进入黑屏
    _controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('扫码')),
      body: MobileScanner(
        controller: _controller,
        onDetect: (BarcodeCapture capture) {
          final value = capture.barcodes.firstOrNull?.rawValue;
          if (value == null) return;
          _controller.stop(); // 扫到先停，防止连续回调弹多次
          Navigator.pop(context, value);
        },
      ),
    );
  }
}
```

**企业坑点**：

- **相机权限联动**：mobile_scanner 自带权限申请，但 Android 需在 `AndroidManifest.xml` 声明 `<uses-permission android:name="android.permission.CAMERA"/>`，iOS 需在 Info.plist 加 `NSCameraUsageDescription` 并写清用途（审核必看）。企业规范做法：入口处先用 permission_handler 检查权限（见[11-企业级通用能力](11-企业级通用能力.md)），被拒给引导页而不是直接进扫码页黑屏。
- 连续扫码场景（仓库盘点）要自己防抖：`onDetect` 一秒可能回调多次。
- 低端 Android 机对焦慢，加"手电筒"按钮（`_controller.toggleTorch()`）能显著降低抱怨。

### 6.2 定位：geolocator

```dart
// lib/services/location_service.dart
import 'package:geolocator/geolocator.dart';

class LocationService {
  /// 获取一次当前位置（权限先行的企业入口）
  static Future<Position> getCurrent() async {
    // 权限三连：服务开关 -> 定位权限 -> 永久拒绝检查
    if (!await Geolocator.isLocationServiceEnabled()) {
      throw Exception('定位服务未开启，请到系统设置中打开');
    }
    var permission = await Geolocator.checkPermission();
    if (permission == LocationPermission.denied) {
      permission = await Geolocator.requestPermission();
      if (permission == LocationPermission.denied) {
        throw Exception('定位权限被拒绝');
      }
    }
    if (permission == LocationPermission.deniedForever) {
      throw Exception('定位权限被永久拒绝，请到系统设置中手动开启');
    }
    return await Geolocator.getCurrentPosition(
      // 企业默认 balanced 兼顾精度与功耗；导航场景才用 bestForNavigation
      desiredAccuracy: LocationAccuracy.balance,
    );
  }
}
```

**企业坑点**：

- **后台定位是另一个世界**：需要 Android 前台服务（FOREGROUND_SERVICE + location 类型）和 iOS 的 `UIBackgroundModes: location`；iOS 审核严格审查 `NSLocationAlwaysAndWhenInUseUsageDescription` 的业务理由，描述含糊直接拒审。
- **省电策略**：国产 ROM（小米/华为/OPPO）的省电模式会杀后台定位，企业方案是引导用户加电池优化白名单（跳设置页方案各厂商不同，以厂商文档为准）。
- 高频定位用 `Geolocator.getPositionStream`（内部是 EventChannel，正好复习第 3 节），别起 Timer 轮询。
- Android 12+ 的粗略/精确定位等权限 API 细节以官方文档为准。

### 6.3 生物识别：local_auth

```dart
// lib/services/biometric_service.dart
import 'package:local_auth/local_auth.dart';

class BiometricService {
  static final LocalAuthentication _auth = LocalAuthentication();

  /// 设备是否支持生物识别
  static Future<bool> isAvailable() async {
    return await _auth.canCheckBiometrics || await _auth.isDeviceSupported();
  }

  /// 发起生物识别校验
  static Future<bool> authenticate() async {
    return await _auth.authenticate(
      localizedReason: '请验证身份以继续操作', // iOS 弹窗正文，Android 部分机型副标题
      options: const AuthenticationOptions(
        stickyAuth: true, // 验证中切后台，回来继续而不是直接失败
        biometricOnly: true, // 只允许生物识别，不允许设备密码兜底（金融类常开）
      ),
    );
  }
}
```

**企业坑点（上架重灾区）**：

- **iOS 必须配置** `NSFaceIDUsageDescription`（Info.plist），不配置调用 FaceID **直接崩溃**——不是降级，是 crash。文案要写清用途如"用于快速登录和支付确认"。
- **Android 差异**：走系统 BiometricPrompt（androidx.biometric），Manifest 需加 `<uses-permission android:name="android.permission.USE_BIOMETRIC"/>`；指纹弹窗样式跟随 Activity 主题，Flutter 默认主题下可能样式异常，建议在 `styles.xml` 配置相关主题（属性以 AndroidX 官方文档为准）。
- 权限文案（localizedReason）要接 i18n，不能硬编码中文——海外审核会挑这个问题（见[11-企业级通用能力](11-企业级通用能力.md)）。
- `biometricOnly: true` 时部分华为老机型（无生物识别硬件）直接失败，登录页必须保留"密码登录"降级入口。

### 6.4 通知：flutter_local_notifications

```dart
// lib/services/local_notification_service.dart
import 'package:flutter/foundation.dart';
import 'package:flutter_local_notifications/flutter_local_notifications.dart';

class LocalNotificationService {
  static final FlutterLocalNotificationsPlugin _plugin =
      FlutterLocalNotificationsPlugin();

  static Future<void> init() async {
    // Android：图标必须是 drawable 资源；iOS：请求权限
    const androidSettings = AndroidInitializationSettings('@mipmap/ic_launcher');
    const darwinSettings = DarwinInitializationSettings(
      requestAlertPermission: true,
      requestBadgePermission: true,
      requestSoundPermission: true,
    );
    await _plugin.initialize(
      const InitializationSettings(android: androidSettings, iOS: darwinSettings),
      onDidReceiveNotificationResponse: (response) {
        // 点击通知回到 App 时触发（App 存活时）
        // 企业规范：这里只做路由跳转分发，不写业务逻辑
        debugPrint('点击通知: ${response.payload}'); // 约定 JSON：{"route": "/order/123"}
      },
    );
  }

  /// 展示一条本地通知（常用于前台收到消息的自定义提示）
  static Future<void> show(String title, String body, {String? payload}) async {
    const androidDetails = AndroidNotificationDetails(
      'message_channel', // 通道 ID：Android 8.0+ 必须指定
      '消息通知', // 通道名称：用户在系统设置里能看到
      importance: Importance.high,
      priority: Priority.high,
    );
    await _plugin.show(
      DateTime.now().millisecondsSinceEpoch ~/ 1000, // 通知 ID，用于取消/更新
      title,
      body,
      const NotificationDetails(
        android: androidDetails,
        iOS: DarwinNotificationDetails(),
      ),
      payload: payload,
    );
  }
}
```

**企业坑点**：

- **Android 13（API 33）+ 运行时通知权限**：`POST_NOTIFICATIONS` 是运行时权限，用户拒绝后通知会**静默丢弃**（不报错！）。企业规范：初始化后主动 `_plugin.checkPermissions()`，被拒则引导去系统设置。"为什么有的用户收不到通知"排查半天往往就是它。
- Android 8.0+ 的通知通道（Notification Channel）一旦创建，重要性等属性不能代码修改，只能引导用户去系统设置改——**通道规划一次定好**（消息/下载/营销分开，让用户可分别关闭）。
- iOS 前台收到通知默认不展示横幅，需要额外处理展示策略。

## 7. WebView：承载 H5 与双向通信

企业里 WebView 的定位很明确：**高频变化的运营页（活动、优惠券、协议）用 H5，稳定的核心流程用 Flutter 原生页面**。

```yaml
dependencies:
  webview_flutter: ^4.10.0  # 版本以 pub.dev 为准
```

```dart
// lib/pages/web_page.dart
import 'dart:convert';
import 'package:flutter/material.dart';
import 'package:webview_flutter/webview_flutter.dart';

/// 通用 WebView 容器页
/// 对照 H5 心智：JS 对象注入 ≈ 微信 JSSDK 的 wx.xxx()
/// PostMessage ≈ iframe 的 window.parent.postMessage
class WebPage extends StatefulWidget {
  const WebPage({super.key, required this.url, this.title = ''});

  final String url;
  final String title;

  @override
  State<WebPage> createState() => _WebPageState();
}

class _WebPageState extends State<WebPage> {
  late final WebViewController _controller;

  @override
  void initState() {
    super.initState();
    _controller = WebViewController()
      ..setJavaScriptMode(JavaScriptMode.unrestricted) // 默认禁 JS，必须显式打开
      ..setNavigationDelegate(
        NavigationDelegate(
          // 拦截跳转：限制站内域名，防止重定向到钓鱼页
          onNavigationRequest: (request) {
            final host = Uri.parse(request.url).host;
            return host.endsWith('yourcompany.com')
                ? NavigationDecision.navigate
                : NavigationDecision.prevent;
          },
        ),
      )
      // JS 对象注入：H5 通过 FlutterBridge.postMessage 调原生能力
      ..addJavaScriptChannel(
        'FlutterBridge',
        onMessageReceived: (JavaScriptMessage message) {
          _handleJsCall(message.message);
        },
      )
      ..loadRequest(Uri.parse(widget.url));
  }

  /// 处理 H5 发来的调用（协议自定，建议 JSON-RPC 风格）
  void _handleJsCall(String raw) {
    try {
      final data = jsonDecode(raw) as Map<String, dynamic>;
      final method = data['method'] as String?;
      switch (method) {
        case 'getToken':
          // Dart -> H5 回传结果：调用 H5 侧挂载的全局回调
          _controller.runJavaScript(
            'window.onFlutterResult && onFlutterResult(${jsonEncode({
                  'method': 'getToken',
                  'data': 'mock-token-123',
                })})',
          );
        case 'close':
          Navigator.of(context).pop();
        default:
          debugPrint('未知 JS 调用: $method');
      }
    } catch (e) {
      debugPrint('JS 消息解析失败: $e');
    }
  }

  @override
  Widget build(BuildContext context) {
    return PopScope(
      // 返回键处理：H5 有内部路由栈时先让 H5 后退，退到底再关页面
      canPop: false,
      onPopInvokedWithResult: (didPop, _) async {
        if (didPop) return;
        if (await _controller.canGoBack()) {
          await _controller.goBack();
        } else {
          Navigator.of(context).pop();
        }
      },
      child: Scaffold(
        appBar: AppBar(title: Text(widget.title)),
        body: WebViewWidget(controller: _controller),
      ),
    );
  }
}
```

配套的 H5 侧代码（给前端同学看的对照）：

```html
<script>
  // H5 调原生：对照 window.wx.config 之后的 wx.xxx()
  function callNative(method, params = {}) {
    if (window.FlutterBridge) {
      FlutterBridge.postMessage(JSON.stringify({ method, params }));
    }
  }
  // 接收原生回传
  window.onFlutterResult = function (res) { console.log('原生回传:', res); };
  callNative('getToken');
</script>
```

**企业坑点**：

- **Cookie 同步差异（经典坑）**：Android 的平台 WebView Cookie 与原生网络库分开管理；iOS 的 WKWebView Cookie 更是独立空间。H5 依赖 Cookie 登录态时，方案是加载前注入 JS 写 Cookie（`document.cookie`），或让 H5 走 URL 参数/token 鉴权。**不要**指望"原生登录了 H5 就自动登录"。
- **返回键**：不处理 `PopScope`，按返回键直接退出整个 WebView，H5 内部路由（Vue Router 历史栈）全丢——用户投诉"我怎么点返回就退出了"。
- **支付回调**：H5 发起支付后，结果页往往需要 App 侧通知，用 JS Channel 回调比轮询 H5 靠谱；微信支付回跳 App 要处理生命周期恢复（见第 9 节）。
- 国产浏览器内核 WebView（X5 等）需换实现，webview_flutter 官方仅支持 Android/iOS/macOS/Web。

## 8. Add-to-App：存量原生 App 的渐进式迁移

很多企业的现实是：有一个跑了五年的原生 App，想引入 Flutter 但不可能推倒重来。这就是 Add-to-App（把 Flutter module 嵌入原生工程）。

```bash
# 创建 flutter module（注意是 module 不是 application）
flutter create --template=module my_flutter_module
# 生成 .android/ 与 .ios/ 只读宿主工程，仅用于调试
```

原生工程接入要点（详细步骤以官方文档为准）：

- **Android**：`settings.gradle` 引入 module，用 `FlutterActivity` / `FlutterFragment` 启动；多引擎场景用 `FlutterEngineGroup` 复用引擎，内存开销小得多。
- **iOS**：`Podfile` 引入 module，用 `FlutterEngine` + `FlutterViewController` 挂载。

Dart 侧入口约定：

```dart
// my_flutter_module/lib/main.dart
import 'package:flutter/material.dart';

@pragma('vm:entry-point')
// 多引擎场景：每个入口必须标记，防止 tree-shaking 裁掉
void main() {
  runApp(const MyApp());
}
```

### 企业迁移的正确姿势

我的观点，直接给结论：

1. **从"非核心 + 高频改版"页面切入**：营销活动页、会员中心、帮助中心——改版频繁、对启动性能不敏感、出问题影响面可控。
2. **不要先迁移首页/支付页**：首页要启动速度（Flutter 引擎冷启动有成本），支付页要绝对稳定，放到团队经验丰富之后。
3. **每迁移一个页面，同步建立 Platform Channel 协议**（登录态、埋点、跳转路由），这些协议是两个世界的"API 契约"，按第 4.1 节规范管理。
4. **CI 要双端跑**：构建链路复杂度翻倍（Flutter 编译产物 + 原生构建），没 CI 别碰；团队 < 5 人且原生页面只有十几个，先评估值不值得。

## 9. App 前后台监听：实现"切后台超时重新解锁"

企业安全需求典型样本：金融/办公类 App 要求"切后台超过 X 分钟，回来后必须重新验证（指纹/手势）"。Flutter 3.13+ 提供了 `AppLifecycleListener`，比老的 `WidgetsBindingObserver.didChangeAppLifecycleState` 好用（老 API 的枚举值随版本有过调整，新项目直接用新 API）：

```dart
// lib/services/app_lock_service.dart
import 'dart:async';
import 'package:flutter/material.dart';

/// 全局 App 锁定服务：切后台超时后要求重新解锁
/// 用法：main() 里 runApp 前创建并 init()，UI 层监听 isLocked 切换锁屏页
class AppLockService with ChangeNotifier {
  AppLockService({this.timeout = const Duration(minutes: 3)});

  /// 超时阈值，企业规范常配 3~5 分钟
  final Duration timeout;

  bool _locked = false;
  bool get isLocked => _locked;

  Timer? _backgroundTimer;
  DateTime? _backgroundAt;

  late final AppLifecycleListener _listener;

  void init() {
    _listener = AppLifecycleListener(
      onHide: _onHide,
      onShow: _onShow,
    );
  }

  void _onHide() {
    // App 完全不可见（iOS 上 onHide 先于 pause，Android 顺序有差异，以官方文档为准）
    _backgroundAt = DateTime.now();
    _backgroundTimer = Timer(timeout, () {
      _locked = true; // 超时仍未回前台 -> 锁定
      notifyListeners();
    });
  }

  void _onShow() {
    _backgroundTimer?.cancel();
    _backgroundTimer = null;
    final away = _backgroundAt == null
        ? Duration.zero
        : DateTime.now().difference(_backgroundAt!);
    _backgroundAt = null;
    if (away >= timeout) {
      _locked = true;
      notifyListeners();
    }
    // 注意：_locked 为 true 时不要自动解锁，解锁由解锁页调 unlock() 触发
  }

  /// 解锁成功后由解锁页调用
  void unlock() {
    _locked = false;
    notifyListeners();
  }

  @override
  void dispose() {
    _listener.dispose();
    _backgroundTimer?.cancel();
    super.dispose();
  }
}
```

挂到全局：

```dart
// lib/main.dart
import 'package:flutter/material.dart';

import 'pages/lock_screen.dart';
import 'services/app_lock_service.dart';

final appLock = AppLockService(timeout: const Duration(minutes: 3));

void main() {
  appLock.init();
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return AnimatedBuilder(
      animation: appLock,
      builder: (context, _) {
        return MaterialApp(
          // HomePage 为业务首页（略）；锁屏时整体替换为 LockScreen
          home: appLock.isLocked ? const LockScreen() : const HomePage(),
        );
      },
    );
  }
}
```

```dart
// lib/pages/lock_screen.dart
import 'package:flutter/material.dart';

import '../main.dart';
import '../services/biometric_service.dart';

class LockScreen extends StatelessWidget {
  const LockScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            const Text('出于安全考虑，请重新验证身份'),
            const SizedBox(height: 24),
            FilledButton(
              onPressed: () async {
                if (await BiometricService.authenticate()) {
                  appLock.unlock();
                }
              },
              child: const Text('指纹解锁'),
            ),
          ],
        ),
      ),
    );
  }
}
```

**企业注意点**：

- `onHide`/`onShow`/`onInactive`/`onPaused`/`onResume`/`onDetach` 的触发时序在 Android 和 iOS 上**不完全一致**（iOS 的 inactive 阶段：来电、下拉通知栏都会触发）。锁定需求只关心"完全不可见"和"重新可见"，用 `onHide`/`onShow` 足够，别依赖过细时序。
- 真实项目里锁屏页要有"手势解锁"降级（生物识别不可用时），并把 `isLocked` 接入路由（GoRouter redirect）而不是简单替换 `home`。
- 部分国产 ROM 后台回收后再点开是**冷启动**，`_locked` 状态会丢。企业做法：把 `_backgroundAt` 持久化（shared_preferences），启动时判断"上次退后台距今是否超时"。
