## 一、选型总览：先想清楚再动手

### 1.1 六种方案一张表

| 方案 | 本质 | 数据类型 | 性能 | 加密 | 迁移成本 | 前端心智对照 |
|---|---|---|---|---|---|---|
| shared_preferences | 平台 KV（XML / NSUserDefaults） | 基本类型 | 启动全量加载 | ❌ | 无 schema，改 key 靠自觉 | localStorage |
| flutter_secure_storage | 平台安全区 | 字符串 | 每次 IO，较慢 | ✅ Keystore/Keychain | 无 schema | 无直接对照（平台替你保管的凭证） |
| Hive | 纯 Dart KV 数据库 | 任意（TypeAdapter） | 读写极快 | ❌（有加密扩展） | TypeAdapter 序号管理 | localStorage 增强版（支持对象） |
| sqflite | SQLite（移动端原生库） | 关系型，SQL | 复杂查询强 | ❌（自行扩展） | **onUpgrade，最规范** | IndexedDB / WebSQL |
| Isar | 现代化 NoSQL（Dart 原生） | 对象/全文索引 | 极快 | ✅ 内置 | 生成代码管理 schema | IndexedDB（面向对象） |
| 文件（path_provider） | 裸文件 | 任意字节 | 取决于大小 | ❌ | 全靠自己 | File System Access API |

版本与 API 以 pub.dev 为准（Isar 近年维护状态有波动，选型前确认当前包状态）。

### 1.2 与前端的心智对照

写过前端的你最容易掉的两个坑：

1. **把 shared_preferences 当 localStorage 用**。localStorage 是同步 API，`shared_preferences` 是**异步**的——`getString()` 返回 `Future`，build 里没法直接 await。这是第二节要解决的核心问题。
2. **拿 Hive 当 IndexedDB**。Hive 是 KV，没有查询能力；需要"按条件查、分页、聚合报表"的数据，对应物不是 Hive，是 sqflite / Isar。

### 1.3 企业默认组合（直接给观点）

```
默认组合：flutter_secure_storage（token / 敏感配置）
        + shared_preferences（轻量偏好设置）
        + Hive（业务缓存、离线兜底数据）
        + sqflite（结构化数据：聊天记录、订单流水、报表）
        + path_provider（下载文件、图片缓存）
```

理由：每样东西放在"性价比最高"的位置——token 图安全不图速度；偏好设置图简单；缓存图快；结构化数据图查询与迁移。**宁可多引入一两个包，也不要一种方案硬扛所有场景**——见过用 shared_preferences 存 5MB JSON 字符串的项目，启动直接多花 800ms。

## 二、shared_preferences：轻量偏好设置

### 2.1 基本用法与两个陷阱

```dart
import 'package:shared_preferences/shared_preferences.dart';

// 写：看似同步，实际是异步入盘
await prefs.setString('theme', 'dark');
// 读：返回 Future —— 陷阱一：异步 API，build 里没法直接用
final prefs = await SharedPreferences.getInstance();
final theme = prefs.getString('theme') ?? 'light';
```

**陷阱一：不能同步读。** 每个读取点都 `await` 意味着到处 async——一个读取点没什么，二十个就烂掉了，所以必须封装"初始化后同步读"。

**陷阱二：启动竞态。** `main()` 里还没 await 完就跑到页面里读值，拿到 null，首帧主题/语言闪一下（用户看到的"白屏后跳变"多半是这个）。解法：**await 完初始化再 runApp**。

两条纪律：**类型受限**（仅 int/double/bool/String/List<String>，存 Map 得 jsonEncode——那时你该直接考虑 Hive）；**不存大对象与敏感信息**（全量加载进内存 + 明文落盘）。

### 2.2 封装 PrefsRepository：初始化后同步读

```dart
// lib/core/storage/storage_keys.dart
/// 全项目 key 的唯一登记处。
/// 禁止业务代码里写裸字符串 key——半年后没人知道 'k_u_info' 是什么，也没人敢删。
abstract final class StorageKeys {
  // ---- 偏好设置（shared_preferences）----
  static const String themeMode = 'pref.theme.mode';
  static const String locale = 'pref.locale';
  static const String firstLaunch = 'pref.first.launch';
  static const String userId = 'pref.user.id';
  // ---- 安全存储（flutter_secure_storage）----
  static const String accessToken = 'secure.token.access';
  static const String refreshToken = 'secure.token.refresh';
  // ---- Hive box 名 ----
  static const String userBox = 'box.user';
  static const String cacheBox = 'box.cache';
}
```

```dart
// lib/core/storage/prefs_repository.dart
import 'package:shared_preferences/shared_preferences.dart';
import 'storage_keys.dart';

/// 偏好设置仓库：
/// - main() 里 await init() 完成后，全项目同步读写；
/// - 读走内存，零异步开销；写"先更内存后落盘"。
class PrefsRepository {
  PrefsRepository._(this._prefs);
  static PrefsRepository? _instance;

  static PrefsRepository get instance {
    final ready = _instance;
    if (ready == null) {
      throw StateError('未初始化：请先在 main() 中 await PrefsRepository.init()');
    }
    return ready;
  }

  static Future<PrefsRepository> init() async =>
      _instance ??= PrefsRepository._(await SharedPreferences.getInstance());

  /// 测试注入口
  static void overrideForTests(SharedPreferences mock) {
    _instance = PrefsRepository._(mock);
  }

  final SharedPreferences _prefs;

  // ---------- 读：同步 ----------
  String get themeMode => _prefs.getString(StorageKeys.themeMode) ?? 'system';
  String get locale => _prefs.getString(StorageKeys.locale) ?? 'zh-CN';
  bool get isFirstLaunch => _prefs.getBool(StorageKeys.firstLaunch) ?? true;

  // ---------- 写：无需 await，落盘内部管理 ----------
  Future<void> setThemeMode(String mode) => _prefs.setString(StorageKeys.themeMode, mode);
  Future<void> setLocale(String locale) => _prefs.setString(StorageKeys.locale, locale);
  Future<void> markLaunched() => _prefs.setBool(StorageKeys.firstLaunch, false);

  /// 退出登录清"用户维度"偏好（主题等全局项保留）
  Future<void> clearUserPrefs() => _prefs.remove(StorageKeys.userId);
}
```

```dart
// lib/main.dart（节选）
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  // 顺序很重要：存储初始化完成后才 runApp，彻底消灭启动竞态
  final prefs = await PrefsRepository.init();
  final secure = await SecureTokenStore.create(); // 见第三节
  runApp(ProviderScope(
    overrides: [prefsRepositoryProvider.overrideWithValue(prefs)],
    child: const MyApp(),
  ));
}
```

## 三、flutter_secure_storage：Token 与敏感配置

### 3.1 为什么 token 不能放 shared_preferences

`shared_preferences` 在 Android 是**明文 XML**，在 iOS 是明文 plist——root / 越狱 / 备份提取都能直接读走。refresh token 等同于"长期登录凭证"，泄露后攻击者在别的设备上就能一直续 token。

`flutter_secure_storage` 把数据交给平台安全区：**Android Keystore**（AES 密钥由硬件 TEE/StrongBox 生成且不可导出）与 **iOS Keychain**（系统级加密，设备锁屏密钥保护）。前端对照：相当于浏览器把 Cookie 放进 `HttpOnly + Secure` 由平台保管，而不是自己 `localStorage.setItem('token', ...)`。

### 3.2 SecureTokenStore：完成网络层的抽象

[07-网络层设计](07-网络层设计.md) 留下的 `TokenStore` 抽象，在这里给生产实现：

```dart
// lib/core/storage/secure_token_store.dart
import 'package:flutter_secure_storage/flutter_secure_storage.dart';
import '../network/token_store.dart';
import 'storage_keys.dart';

/// Token 的安全存储实现（Keystore / Keychain）
class SecureTokenStore implements TokenStore {
  SecureTokenStore._(this._storage, this._cached);
  final FlutterSecureStorage _storage;

  /// 内存缓存：secure_storage 每次读都是平台通道 IO（毫秒级），
  /// 而 accessToken 每个请求都要读，必须挡住高频 IO
  final Map<String, String?> _cached;

  /// 启动预加载进内存：main() await 一次，之后读全走内存
  static Future<SecureTokenStore> create() async {
    const storage = FlutterSecureStorage(
      aOptions: AndroidOptions(encryptedSharedPreferences: true),
      iOptions: IOSOptions(accessibility: KeychainAccessibility.first_unlock),
    );
    return SecureTokenStore._(storage, {
      StorageKeys.accessToken: await storage.read(key: StorageKeys.accessToken),
      StorageKeys.refreshToken: await storage.read(key: StorageKeys.refreshToken),
    });
  }

  @override
  String? get accessToken => _cached[StorageKeys.accessToken];
  @override
  String? get refreshToken => _cached[StorageKeys.refreshToken];

  @override
  Future<void> save({required String accessToken, required String refreshToken}) async {
    // 先写内存后落盘：落盘失败也不影响本次会话
    _cached[StorageKeys.accessToken] = accessToken;
    _cached[StorageKeys.refreshToken] = refreshToken;
    await _storage.write(key: StorageKeys.accessToken, value: accessToken);
    await _storage.write(key: StorageKeys.refreshToken, value: refreshToken);
  }

  @override
  Future<void> clear() async {
    _cached[StorageKeys.accessToken] = null;
    _cached[StorageKeys.refreshToken] = null;
    await _storage.deleteAll();
  }
}
```

三个企业细节：

1. **同步读接口**：`TokenStore.accessToken` 是 getter（同步），因为 07 篇的鉴权拦截器在 `onRequest` 里现读现注入——"异步存储 + 启动预加载 + 内存缓存"是成全它的标准组合拳；
2. **`first_unlock` 可访问性**：设备首次解锁后即可读，避免锁屏时收到推送读不到 token；金融类可用更严格策略；
3. 其他敏感配置（第三方 secret、设备指纹）同样只进这里，**永远不进 shared_preferences**。

## 四、Hive：业务缓存与离线兜底

### 4.1 为什么缓存选 Hive

Hive 是纯 Dart 实现的 KV 数据库：写入纯内存 + 后台落盘，读取快、无平台通道开销，自带 TypeAdapter 支持任意对象。**适合"整块读取、按 key 命中"的业务缓存**——用户信息、首页配置、feed 首屏兜底。不适合"按条件查询"——那是第五节 sqflite 的地盘。

```yaml
dependencies:
  hive: ^2.x
  hive_flutter: ^1.x
dev_dependencies:
  hive_generator: ^2.x
  build_runner: ^2.x
```

### 4.2 box 管理

```dart
// lib/core/storage/hive_boxes.dart
import 'package:hive_flutter/hive_flutter.dart';
import 'storage_keys.dart';

/// box 统一开关：调用方永远拿"已经打开的 box"。
/// 规则：所有 box 在 main() 一次打开、全程复用——
/// 反复 open/close 是常见误用，既慢又易状态不一致。
class HiveBoxes {
  HiveBoxes._();
  static Box<T> user<T>() => Hive.box<T>(StorageKeys.userBox);
  static Box<T> cache<T>() => Hive.box<T>(StorageKeys.cacheBox);

  /// main() 中调用
  static Future<void> init() async {
    await Hive.initFlutter();
    // 先注册 Adapter 再 openBox，顺序反了写入时会抛 "Adapter not registered"
    Hive.registerAdapter(UserCacheEntityAdapter());
    await Hive.openBox(StorageKeys.userBox);
    await Hive.openBox(StorageKeys.cacheBox);
  }
}
```

### 4.3 TypeAdapter：用生成器

存自定义对象需要 TypeAdapter，推荐 `hive_generator` 生成：

```dart
// lib/features/user/data/local/user_cache_entity.dart
import 'package:hive/hive.dart';
part 'user_cache_entity.g.dart';

/// 缓存实体：只放 UI 兜底需要的字段。不要把领域模型直接塞进缓存——
/// 领域模型演进会牵连缓存结构，实体独立演进最稳。
@HiveType(typeId: 1)
class UserCacheEntity {
  UserCacheEntity({required this.id, required this.name, this.avatar = ''});
  @HiveField(0) final int id;
  @HiveField(1) final String name;
  @HiveField(2) final String avatar;
}
```

```bash
dart run build_runner build --delete-conflicting-outputs
```

两条纪律：`typeId` 发布后不改；**新增字段必须用新的 `@HiveField(n)` 序号**，删除老字段也保留序号空洞——序号就是 Hive 的"迁移机制"，复用已删序号会读出错数据（未知字段会被忽略，序号复用不会）。

### 4.4 与 Repository 结合：缓存用户信息

```dart
// lib/features/user/data/user_cache_repository.dart
import '../../../core/storage/hive_boxes.dart';
import 'local/user_cache_entity.dart';

/// 用户信息缓存仓库：写穿（write-through），读兜底
class UserCacheRepository {
  Future<void> save(UserCacheEntity user) async =>
      HiveBoxes.user<UserCacheEntity>().put(user.id.toString(), user);

  Future<UserCacheEntity?> read(int userId) async =>
      HiveBoxes.user<UserCacheEntity>().get(userId.toString());

  Future<void> clearAll() async =>
      HiveBoxes.user<UserCacheEntity>().clear(); // 退出登录清整个 box，比逐条删安全
}
```

## 五、sqflite：结构化数据与数据迁移（企业必考）

### 5.1 什么时候必须上 SQLite

判断标准只有一条：**这份数据需要"查询"吗？** 聊天记录按会话+时间分页、订单按状态+月份统计、搜索历史前缀匹配——SQL 一行的事，KV 里全是性能灾难。另外 sqflite 有本节主角——**最规范的版本迁移机制**，会长期演进的核心表值得为它买单。

```yaml
dependencies:
  sqflite: ^2.x
  path: ^1.x
```

### 5.2 建库与数据迁移框架（完整可抄）

```dart
// lib/core/storage/database/app_database.dart
import 'package:path/path.dart' as p;
import 'package:sqflite/sqflite.dart';

/// 迁移：from → to 的一个原子步骤
class DbMigration {
  const DbMigration({
    required this.fromVersion,
    required this.toVersion,
    required this.execute,
  });
  final int fromVersion; // 起始版本（不含）
  final int toVersion;   // 目标版本（含）
  final Future<void> Function(Transaction txn) execute; // 事务内执行
}

/// 全局唯一 Database 门面
class AppDatabase {
  AppDatabase._(this._db);
  static AppDatabase? _instance;

  static AppDatabase get instance {
    final ready = _instance;
    if (ready == null) {
      throw StateError('未初始化：请先在 main() 中 await AppDatabase.init()');
    }
    return ready;
  }

  final Database _db;
  Database get db => _db;

  /// schema 版本：每次结构变更必须 +1 并补充迁移，这是纪律
  static const int dbVersion = 3;

  /// 迁移注册表：顺序即执行顺序。
  /// 老用户按 from/to 逐级爬升，永远不需要写 "v1→v3、v2→v3" 的排列组合；
  /// 历史迁移一经发布永不修改，只追加。
  static const List<DbMigration> migrations = [
    // ---- v1 → v2：订单表增加状态列 ----
    DbMigration(
      fromVersion: 1,
      toVersion: 2,
      execute: (txn) async {
        await txn.execute("ALTER TABLE orders ADD COLUMN status TEXT DEFAULT 'pending'");
      },
    ),
    // ---- v2 → v3：拆出会话表并回填 ----
    DbMigration(
      fromVersion: 2,
      toVersion: 3,
      execute: (txn) async {
        await txn.execute('''
          CREATE TABLE conversations (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            peer_id INTEGER NOT NULL,
            last_message TEXT,
            updated_at INTEGER NOT NULL
          )
        ''');
        // 回填：把聊天记录中的会话聚合出来
        await txn.execute('''
          INSERT INTO conversations (peer_id, updated_at)
          SELECT peer_id, MAX(created_at) FROM messages GROUP BY peer_id
        ''');
        await txn.execute('CREATE INDEX idx_messages_peer ON messages(peer_id)');
      },
    ),
  ];

  static Future<AppDatabase> init() async {
    if (_instance != null) return _instance!;
    final db = await openDatabase(
      p.join(await getDatabasesPath(), 'app.db'),
      version: dbVersion,
      onConfigure: _onConfigure,
      onCreate: _onCreate,
      onUpgrade: _onUpgrade,
      onDowngrade: _onDowngrade,
    );
    return _instance = AppDatabase._(db);
  }

  /// SQLite 外键约束默认关闭，必须手动开
  static Future<void> _onConfigure(Database db) async {
    await db.execute('PRAGMA foreign_keys = ON');
  }

  /// 新用户：一步建终态表（onUpgrade 只对老库触发，无需重放迁移）
  static Future<void> _onCreate(Database db, int version) async {
    await db.execute('''
      CREATE TABLE orders (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        title TEXT NOT NULL,
        status TEXT NOT NULL DEFAULT 'pending',
        created_at INTEGER NOT NULL
      )
    ''');
    await db.execute('''
      CREATE TABLE messages (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        peer_id INTEGER NOT NULL,
        content TEXT NOT NULL,
        created_at INTEGER NOT NULL
      )
    ''');
    await db.execute('''
      CREATE TABLE conversations (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        peer_id INTEGER NOT NULL,
        last_message TEXT,
        updated_at INTEGER NOT NULL
      )
    ''');
    await db.execute('CREATE INDEX idx_messages_peer ON messages(peer_id)');
  }

  /// 老用户：逐版本执行 pending 迁移（企业必考）
  static Future<void> _onUpgrade(Database db, int oldV, int newV) async {
    final pending = migrations
        .where((m) => m.fromVersion >= oldV && m.toVersion <= newV)
        .toList()
      ..sort((a, b) => a.fromVersion.compareTo(b.fromVersion));
    for (final m in pending) {
      // 每个迁移一个事务：失败整体回滚，库停在旧版本，下次启动重试
      await db.transaction(m.execute);
    }
  }

  /// 降级（灰度包回滚）不许静默丢数据：明确报错比装没事更企业
  static Future<void> _onDowngrade(Database db, int oldV, int newV) async {
    throw UnsupportedError('数据库不支持降级：$oldV → $newV');
  }
}
```

这套框架的三个企业细节：

1. **迁移注册表**：`from/to` 逐级爬升，任何老版本都能升到最新，新需求只追加一条 `DbMigration`，**永远不改历史迁移**；
2. **每条迁移一个事务**：中途失败回滚，库停在上一个完整版本，不会出现"半新半旧"；
3. **降级显式抛错**：灰度发布让新版本 DB 落到老版本 App 上是真实事故，明确失败远好于静默丢数据。

### 5.3 CRUD 封装：订单 DAO

```dart
// lib/features/order/data/local/order_dao.dart
import 'package:sqflite/sqflite.dart';
import '../../../../core/storage/database/app_database.dart';

/// 订单 DAO（Data Access Object）：只写 SQL 与行↔对象转换，不含业务规则
class OrderDao {
  OrderDao(this._db);
  final AppDatabase _db;

  Future<void> insert(OrderRow order) async =>
      _db.db.insert('orders', _toMap(order), conflictAlgorithm: ConflictAlgorithm.replace);

  /// 分页查询：SQL 一行搞定，KV 方案做不到
  Future<List<OrderRow>> pageByStatus(String status, {int page = 1, int size = 20}) async {
    final rows = await _db.db.query('orders',
        where: 'status = ?',
        whereArgs: [status],
        orderBy: 'created_at DESC',
        limit: size,
        offset: (page - 1) * size);
    return rows.map(_fromMap).toList();
  }

  Future<int> countByStatus(String status) async {
    final res = await _db.db.rawQuery('SELECT COUNT(*) AS c FROM orders WHERE status = ?', [status]);
    return (res.first['c'] as int?) ?? 0;
  }

  Map<String, Object?> _toMap(OrderRow o) =>
      {'id': o.id, 'title': o.title, 'status': o.status, 'created_at': o.createdAt};

  OrderRow _fromMap(Map<String, Object?> map) => OrderRow(
      id: map['id'] as int,
      title: map['title'] as String,
      status: map['status'] as String,
      createdAt: map['created_at'] as int);
}

/// 订单行实体（与表结构一一对应；领域模型由上层 Mapper 转换，见 07 篇 5.4 节）
class OrderRow {
  const OrderRow({this.id, required this.title, required this.status, required this.createdAt});
  final int? id;
  final String title;
  final String status;
  final int createdAt;
}
```

## 六、文件存储：path_provider 的目录学

### 6.1 三个目录，三种命运

| 目录 | 获取方式 | 系统回收 | 被备份 | 放什么 |
|---|---|---|---|---|
| documents | `getApplicationDocumentsDirectory()` | ❌ | ✅ | 用户资产：下载的合同 PDF、导出的报表 |
| cache / tmp | `getTemporaryDirectory()` | ✅ 磁盘紧张时系统直接清 | ❌ | 图片缓存、解压的临时资源 |
| Application Support | `getApplicationSupportDirectory()` | ❌ | 视配置 | 数据库文件等"删了就要重造"的内部数据 |

**企业注意三条**：

1. **别把重要数据放 cache**。系统磁盘紧张时随时清空它，"下载的发票突然没了"就是这么来的——重要文件进 documents；
2. **别把可再生的缓存放 documents**。图片磁盘缓存属于 cache，放 documents 会撑爆 iCloud/自动备份，用户会投诉"你们 App 占了 20GB"；
3. **对 cache 的正确心智是"读的时候可能不存在，永远走 miss 分支"**——Android 清理时机被厂商定制得碎片化，别赌。

### 6.2 下载文件管理

```dart
// lib/core/storage/file/local_file_store.dart
import 'dart:io';
import 'package:path/path.dart' as p;
import 'package:path_provider/path_provider.dart';

/// 下载文件管理：目录规范 + 体积统计
class LocalFileStore {
  /// 下载根目录：documents/downloads（重要文件，不进 cache）
  Future<Directory> downloadsDir() async {
    final root = await getApplicationDocumentsDirectory();
    final dir = Directory(p.join(root.path, 'downloads'));
    if (!dir.existsSync()) dir.createSync(recursive: true);
    return dir;
  }

  Future<File> saveDownload(String fileName, List<int> bytes) async {
    final dir = await downloadsDir();
    final file = File(p.join(dir.path, fileName));
    await file.writeAsBytes(bytes, flush: true);
    return file;
  }

  /// 设置页"清除缓存"的真正实现。
  /// 只清 cache 目录，绝不能碰 downloads——很多 App 在这里翻过车。
  Future<int> clearCache() async {
    final tmp = await getTemporaryDirectory();
    var freed = 0;
    if (tmp.existsSync()) {
      for (final e in tmp.listSync()) {
        final size = _sizeOf(e);
        e.deleteSync(recursive: true);
        freed += size;
      }
    }
    return freed;
  }

  int _sizeOf(FileSystemEntity e) {
    try {
      return e.statSync().size;
    } catch (_) {
      return 0;
    }
  }
}
```

## 七、缓存策略设计：离线优先与 TTL

### 7.1 离线优先（offline-first）：读缓存 → 网络 → 写缓存

地铁里打开 App 是对体验最真实的考验。读取顺序：**先回缓存（秒开）→ 再发网络（拿新数据）→ 成功后写缓存**。对照前端：Service Worker 的 stale-while-revalidate 是同一个思想。

```dart
// lib/core/storage/cache/offline_first.dart
import '../../network/app_exception.dart';
import '../../result.dart';
import '../hive_boxes.dart';

/// 给仓库混入离线优先能力。
/// 泛型：F 为网络返回的领域模型，L 为缓存实体（需已注册 TypeAdapter）。
mixin OfflineFirst<F, L> {
  String get cacheKey; // 进 StorageKeys 统一登记
  L Function(F fresh) get toLocal; // 域模型 → 缓存实体
  F Function(L local) get toFresh; // 缓存实体 → 域模型
  Future<Result<F>> fetchFromNetwork(); // 网络请求（内部已完成错误映射）

  /// 缓存写入点：默认写通用 cache box，子类可覆写
  Future<void> writeCache(L local) async => HiveBoxes.cache().put(cacheKey, local);

  L? readCache() {
    final raw = HiveBoxes.cache().get(cacheKey);
    return raw is L ? raw : null;
  }

  /// 离线优先读取。[onFresh] 在"缓存命中"与"网络成功"时各回调一次——
  /// 调用方（通常是 Notifier）拿它驱动 UI 先秒开、后更新。
  Future<Result<F>> load({void Function(F data)? onFresh}) async {
    // 1. 缓存先行：命中立即吐出（列表秒开）
    final cached = readCache();
    if (cached != null) onFresh?.call(toFresh(cached));

    // 2. 网络刷新
    final fresh = await fetchFromNetwork();

    // 3. 成功：写穿缓存（write-through）
    if (fresh is Ok<F>) {
      await writeCache(toLocal(fresh.data));
      onFresh?.call(fresh.data);
      return fresh;
    }

    // 4. 失败：有缓存则静默降级，用户无感
    final error = (fresh as Err<F>).error;
    final offline = error is NetworkUnreachableException || error is TimeoutException;
    return offline && cached != null ? Result.ok(toFresh(cached)) : fresh;
  }
}
```

行为：有网时列表秒开（缓存）→ 一瞬后更新（网络）；没网时列表依然打开（缓存）——**用户感知不到"失败"**。第八节用手写版把同一套编排接进 Riverpod。首次启动无缓存才走纯网络等待，所以首启体验才需要 loading/skeleton——**不要做"强制预取全部数据再进首页"**，拉长启动时间是最差的首启体验。进阶玩法（首帧后异步预热）见 [应用架构设计](09-应用架构设计.md)。

### 7.2 TTL 缓存封装：过期自动失效

热搜榜、开屏配置这类数据要求"新鲜度"——缓存可用但过期必须拉新。给 Hive 包一层 TTL（Time To Live，存活时间）：

```dart
// lib/core/storage/cache/ttl_cache.dart
import '../hive_boxes.dart';

/// 带过期时间的缓存条目
class TtlEntry {
  TtlEntry({required this.value, required this.expireAt});
  final dynamic value;
  final DateTime expireAt;

  bool get isExpired => DateTime.now().isAfter(expireAt);

  Map<String, dynamic> toJson() =>
      {'value': value, 'expireAt': expireAt.toIso8601String()};
  factory TtlEntry.fromJson(dynamic raw) {
    final map = (raw as Map).cast<String, dynamic>();
    return TtlEntry(value: map['value'], expireAt: DateTime.parse(map['expireAt'] as String));
  }
}

/// TTL 缓存：读时惰性清理，不依赖后台定时器
class TtlCache {
  /// 写缓存：ttl 为存活时长，如 const Duration(minutes: 10)
  Future<void> put(String key, dynamic value, Duration ttl) async =>
      HiveBoxes.cache().put('ttl.$key',
          TtlEntry(value: value, expireAt: DateTime.now().add(ttl)).toJson());

  /// 读缓存：命中未过期条目才返回，否则返回 null 并顺手清理
  dynamic get(String key) {
    final raw = HiveBoxes.cache().get('ttl.$key');
    if (raw == null) return null;
    final entry = TtlEntry.fromJson(raw);
    if (entry.isExpired) {
      HiveBoxes.cache().delete('ttl.$key');
      return null;
    }
    return entry.value;
  }
}
```

选**惰性清理**（读时检查）而非定时清理：定时器需要后台常驻、复杂化包体；没人读的缓存多占的磁盘会在系统清 cache 或用户清理时回收——**用最简单的机制满足需求**。

## 八、数据层与状态管理联动：Repository → Riverpod 完整示例

把本篇与 07 篇的能力拼起来：一个"缓存兜底 + 网络刷新"的用户详情页。

```dart
// lib/features/user/presentation/profile_provider.dart
import 'package:flutter_riverpod/flutter_riverpod.dart';
import '../../../core/network/api_client.dart';
import '../../../core/network/app_exception.dart';
import '../../../core/result.dart';
import '../data/local/user_cache_entity.dart';
import '../data/user_cache_repository.dart';
import '../data/user_repository.dart';
import '../domain/user.dart';

/// 依赖装配：provider 层钉死"用哪个实现"，UI 与仓库互不认识
final userCacheRepoProvider = Provider((ref) => UserCacheRepository());
final userRepositoryProvider =
    Provider<UserRepository>((ref) => UserRepositoryImpl(ApiClient.instance));

class ProfileState {
  const ProfileState({this.user, this.loading = true, this.error, this.fromCache = false});
  final User? user;
  final bool loading;
  final AppException? error;

  /// 数据来源：缓存兜底时 UI 可标注"数据可能不是最新"
  final bool fromCache;

  ProfileState copyWith({User? user, bool? loading, AppException? error, bool? fromCache}) =>
      ProfileState(
        user: user ?? this.user,
        loading: loading ?? this.loading,
        error: error,
        fromCache: fromCache ?? this.fromCache,
      );
}

class ProfileNotifier extends AutoDisposeNotifierFamily<ProfileState, int> {
  late UserRepository _repo;
  late UserCacheRepository _cache;

  @override
  ProfileState build(int userId) {
    _repo = ref.watch(userRepositoryProvider);
    _cache = ref.watch(userCacheRepoProvider);
    Future.microtask(load);
    return const ProfileState(loading: true);
  }

  Future<void> load() async {
    // 1. 缓存先行：命中立即上屏，标记 fromCache
    final cached = await _cache.read(userId);
    if (cached != null) {
      state = state.copyWith(
          user: User(id: cached.id, name: cached.name, avatar: cached.avatar),
          loading: false,
          fromCache: true);
    }

    // 2. 网络刷新
    switch (await _repo.fetchProfile(userId)) {
      case Ok(:final data):
        // 3. 写穿缓存：网络成功即更新本地
        await _cache.save(UserCacheEntity(id: data.id, name: data.name, avatar: data.avatar));
        state = state.copyWith(user: data, loading: false, fromCache: false);
      case Err(:final error):
        // 4. 失败但有缓存：保留数据，不打扰用户；无缓存才展示错误
        final offline = error is NetworkUnreachableException || error is TimeoutException;
        state = state.copyWith(
            loading: false,
            error: cached != null && offline ? null : error);
    }
  }
}

final profileProvider =
    AutoDisposeNotifierProviderFamily<ProfileNotifier, ProfileState, int>(ProfileNotifier.new);
```

```dart
// lib/features/user/presentation/profile_page.dart（节选）
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';

class ProfilePage extends ConsumerWidget {
  const ProfilePage({super.key, required this.userId});
  final int userId;

  @override

    return Scaffold(

          const Center(child: CircularProgressIndicator()),
```

## 九、存储通用原则：可测试、可维护、可清理

1. **可测试：依赖注入贯穿始终**。`PrefsRepository.overrideForTests`、`TokenStore` 面向抽象、Repository 只依赖接口——单测全部换内存实现，不碰真实磁盘（详见 [测试体系](12-测试体系.md)）。
2. **统一 StorageKey 常量管理**。所有 key 集中在 `storage_keys.dart`，命名带前缀分组（`pref.` / `secure.` / `box.`）。散落的魔法字符串 key 是"删不敢删、改不敢改"的根源。
3. **清理策略分层**：退出登录清"用户维度"数据（token、业务 box、用户偏好）；"清除缓存"只清 cache 目录与 TTL 缓存；**绝不提供"全量清库"按钮**——迁移框架好不容易保住的数据，一个按钮就没了。
4. **敏感数据只进 secure_storage**：token、手机号、第三方 secret，shared_preferences / Hive 里一律禁止出现。
5. **大对象不入 KV**：超过几十 KB 的结构化数据要么进 sqflite（要查询）要么进文件（不要查询）。
6. **写入语义想清楚再动手**：`box.put` 幂等、`db.insert(replace)` 覆盖、`box.add` 追加——选错语义比不写更糟。
