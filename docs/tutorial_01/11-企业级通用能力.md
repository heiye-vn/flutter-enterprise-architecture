# 11 - 企业级通用能力

**本篇目标**：把一个"能跑的 App"升级为"能上架、能运营、能迭代的企业级 App"——国际化、主题、权限、推送、图片、适配、埋点、升级、启动页，一个不落。

## 1. 国际化 i18n

企业红线先立住：**禁止硬编码中文字符串进生产包**。文案必须统一管理，原因不只是翻译——运营改一句提示语，你不希望为此发一次版。

### 1.1 工具链配置

```yaml
# pubspec.yaml
dependencies:
  flutter:
    sdk: flutter
  flutter_localizations:
    sdk: flutter
  intl: any

flutter:
  generate: true  # 开启 gen-l10n 代码生成

# l10n.yaml（项目根目录）
arb-dir: lib/l10n
template-arb-file: app_zh.arb      # 中文是模板语言（国内团队反着来更顺手）
output-localization-file: app_localizations.dart
```

ARB 文件（`lib/l10n/app_zh.arb`）：

```json
{
  "@@locale": "zh",
  "appTitle": "企业工作台",
  "helloUser": "你好，{name}",
  "@helloUser": {
    "placeholders": { "name": { "type": "String" } }
  },
  "unreadMessages": "{count, plural, =0{暂无未读} other{有 {count} 条未读消息}}",
  "@unreadMessages": {
    "placeholders": { "count": { "type": "int" } }
  }
}
```

`lib/l10n/app_en.arb`（只翻译，`@` 元数据不用重复写）：

```json
{
  "@@locale": "en",
  "appTitle": "Workbench",
  "helloUser": "Hello, {name}",
  "unreadMessages": "{count, plural, =0{No unread messages} other{{count} unread messages}}"
}
```

执行 `flutter gen-l10n`（配置了 `generate: true` 后 `flutter run` / `flutter build` 也会自动生成）。

> **⚠️ 生成位置在 3.32 变了，这是老教程最大的坑**
>
> 3.32 之前，`gen-l10n` 生成的是一个**合成包** `package:flutter_gen`，产物在 `.dart_tool/flutter_gen/gen_l10n/`，代码里要写 `import 'package:flutter_gen/gen_l10n/app_localizations.dart';`。
> 从 **3.32 起合成包被取消**（后续稳定版直接移除），文案默认生成到**源码目录** `lib/l10n/`，用相对路径 import；并且 `pubspec.yaml` 里的 `generate: true` 变成**必需项**。
> 老项目迁移：`l10n.yaml` 里加 `synthetic-package: false`，把 import 改成相对路径即可。
>
> ```yaml
> # l10n.yaml（3.32+ 推荐配置）
> arb-dir: lib/l10n
> output-dir: lib/l10n/generated      # 可选：把生成物收进子目录，便于 .gitignore 之外的管理
> template-arb-file: app_zh.arb
> output-localization-file: app_localizations.dart
> nullable-getter: false              # 让 context.l10n 返回非空，少写 !
> ```

```dart
// lib/main.dart（MaterialApp 处的 i18n 接线；3.32+ 用相对路径 import 生成文件）
import 'package:flutter/material.dart';
import 'package:flutter_localizations/flutter_localizations.dart';

import 'l10n/generated/app_localizations.dart';   // 老版本是 package:flutter_gen/gen_l10n/...

MaterialApp(
  localizationsDelegates: const [
    AppLocalizations.delegate,
    GlobalMaterialLocalizations.delegate,
    GlobalWidgetsLocalizations.delegate,
    GlobalCupertinoLocalizations.delegate,
  ],
  supportedLocales: const [Locale('zh'), Locale('en')],
  home: const DemoPage(),
);
```

> **用了 `material_ui` 独立包的话**（见 [04 篇 4.1](04-Widget与布局.md)）：Material/Cupertino 的本地化委托随之从 `flutter_localizations` 搬进了设计包，四个 delegate 合并成一个 —— `localizationsDelegates: GlobalMaterialLocalizations.delegates`，它会自动包含 Cupertino 与 Widgets 的委托，接线更短。

```dart
// lib/l10n_service.dart —— 全局便捷访问（放在 core 层，全项目复用）
extension L10nX on BuildContext {
  AppLocalizations get l10n => AppLocalizations.of(this)!;
  // 上面的 l10n.yaml 若配了 nullable-getter: false，可写成 AppLocalizations.of(this)
}
```

用法：`context.l10n.helloUser('张三')` 输出"你好，张三"（带参数）；`context.l10n.unreadMessages(42)` 输出"有 42 条未读消息"（复数，ICU MessageFormat 语法）。英文要写全 `=0{...} =1{...} other{...}`，中文没有单复数变化，`=0` + `other` 就够。

### 1.2 语言切换 + 持久化

语言切换本质是改 `MaterialApp.locale`。用 Riverpod 管理（第 6 篇方案），配合 `shared_preferences` 持久化：

```dart
// lib/providers/locale_provider.dart
import 'dart:ui';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:shared_preferences/shared_preferences.dart';

/// locale state：null 表示跟随系统
final localeProvider = NotifierProvider<LocaleNotifier, Locale?>(LocaleNotifier.new);

class LocaleNotifier extends Notifier<Locale?> {
  static const _key = 'app_locale';

  @override
  Locale? build() {
    _loadSaved();
    return null; // 启动默认跟随系统
  }

  Future<void> _loadSaved() async {
    final code = (await SharedPreferences.getInstance()).getString(_key);
    if (code != null) state = Locale(code);
  }

  Future<void> setLocale(Locale? locale) async {
    state = locale;
    final prefs = await SharedPreferences.getInstance();
    if (locale == null) {
      await prefs.remove(_key);
    } else {
      await prefs.setString(_key, locale.languageCode);
    }
  }
}

// MaterialApp 处挂上（ConsumerWidget 中）：
// locale: ref.watch(localeProvider),
```

### 1.3 团队协作建议

- **文案统一管理**：ARB 文件是唯一事实来源，新增文案走 MR，key 命名如 `order_detail_empty_tip`（页面_位置_含义）。
- **CI 卡硬编码中文**：脚本 grep dart 源码里的中文字符串（排除注释/测试），有则卡住合并——低成本高收益。
- 翻译协作交给翻译平台或同事维护 `app_en.arb`，别机翻直接上生产；日期/数字本地化用 `intl` 的 `DateFormat` / `NumberFormat`，别手拼。

## 2. 主题与暗黑模式

### 2.1 Material 3 ColorScheme.fromSeed

```dart
// lib/theme/app_theme.dart
import 'package:flutter/material.dart';

class AppTheme {
  /// 种子色取品牌色，自动派生整套 ColorScheme
  static ThemeData light() => _build(ColorScheme.fromSeed(
      seedColor: const Color(0xFF2F6BFF), brightness: Brightness.light));

  static ThemeData dark() => _build(ColorScheme.fromSeed(
      seedColor: const Color(0xFF2F6BFF), brightness: Brightness.dark));

  static ThemeData _build(ColorScheme scheme) {
    return ThemeData(
      // useMaterial3 自 3.16 起默认 true，这里显式写上只为兼容非常老的 SDK，可删
      useMaterial3: true,
      colorScheme: scheme,
      scaffoldBackgroundColor: scheme.surface,
      // 组件样式集中在这里调，不要每个页面各写各的
      appBarTheme: AppBarTheme(
        backgroundColor: scheme.surface,     // 3.35 起 AppBarTheme.color 已废弃，用 backgroundColor
        foregroundColor: scheme.onSurface,
        centerTitle: true,
      ),
      // cardTheme 等其他组件样式按需集中在此调，不要页面里各写各的
    );
  }
}
```

要点：**页面里不许出现裸色值**（`Color(0xFF...)` / `Colors.blue`），一律 `Theme.of(context).colorScheme.xxx`——否则暗黑模式切过去就是白底黑字灾难。

**取色时避开三个已废弃的角色**（3.22 起，详见 [04 篇 9.1](04-Widget与布局.md)）：

| 别再用 | 改用它 |
|---|---|
| `background` / `onBackground` | `surface` / `onSurface` |
| `surfaceVariant` | `surfaceContainerHighest` |
| `color.withOpacity(x)` | `color.withValues(alpha: x)` |

做层级区分时优先用新增的 `surfaceContainerLowest / Low / High / Highest` 与 `surfaceDim / surfaceBright`，比手叠半透明更符合 M3 规范，也能自动适配暗色。另外 3.35 起 `ThemeData.dialogBackgroundColor` 移到了 `DialogThemeData.backgroundColor`、`ThemeData.indicatorColor` 移到了 `TabBarThemeData.indicatorColor`（3.32），老代码里出现这些参数会走废弃告警。

### 2.2 用 Riverpod 管理主题模式 + 持久化

```dart
// lib/providers/theme_mode_provider.dart
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'package:shared_preferences/shared_preferences.dart';

final themeModeProvider =
    NotifierProvider<ThemeModeNotifier, ThemeMode>(ThemeModeNotifier.new);

class ThemeModeNotifier extends Notifier<ThemeMode> {
  static const _key = 'theme_mode';

  @override
  ThemeMode build() {
    _load();
    return ThemeMode.system; // 默认跟随系统
  }

  Future<void> _load() async {
    final saved = (await SharedPreferences.getInstance()).getString(_key);
    if (saved != null) {
      state = ThemeMode.values
          .firstWhere((m) => m.name == saved, orElse: () => ThemeMode.system);
    }
  }

  Future<void> setMode(ThemeMode mode) async {
    state = mode;
    final prefs = await SharedPreferences.getInstance();
    await prefs.setString(_key, mode.name);
  }
}

// MaterialApp 侧接线（ConsumerWidget 中）：
// theme: AppTheme.light(), darkTheme: AppTheme.dark(),
// themeMode: ref.watch(themeModeProvider),  // system / light / dark 三态
```

**注意**：中文 App 的主流策略是"跟随系统 + 允许手动覆盖"，而不是英文 App 常见的"亮色为主、暗色可选"。理由很实际：国内用户换暗黑模式的意愿分化大，且很多企业 App 的暗色设计资源不全——跟随系统是最低成本的不出错方案。

## 3. 权限体系：permission_handler

### 3.1 权限分型

| 类型 | 行为 | 例子 |
| --- | --- | --- |
| 安装时/声明型 | 安装即授予或首次使用时系统弹窗 | Android 普通权限（INTERNET）、iOS Info.plist 描述型权限 |
| 运行时权限 | 使用时弹系统窗 | 相机、定位、麦克风、Android 13+ 通知 |
| 特殊权限 | 系统设置页手动开 | Android 悬浮窗、电池优化白名单 |

**对照 H5 差异**：H5 的权限（如 `Notification.requestPermission()`）申请一次、拒绝后再次调用直接静默返回 denied，引导手段几乎只有文案；原生 App 的运行时权限被拒后还能引导用户去系统设置手动开——这是原生体验的核心优势，也是下面封装要解决的问题。

### 3.2 运行时权限的企业级封装

```yaml
dependencies:
  permission_handler: ^11.3.1  # 以 pub.dev 为准
```

```dart
// lib/services/permission_service.dart
import 'package:flutter/material.dart';
import 'package:permission_handler/permission_handler.dart';

/// 权限请求结果：比裸 bool 更利于 UI 分支
enum PermissionOutcome {
  granted,      // 已授权
  deniedOnce,   // 本次拒绝（还能再弹）
  deniedForever // 永久拒绝（只能去系统设置）
}

/// 企业级权限流程封装：check -> request -> 被拒 -> 引导去系统设置
class PermissionService {
  /// 完整流程。调用方保证 App 在前台时才调用（涉及弹窗和上下文）
  static Future<PermissionOutcome> ensure(Permission permission) async {
    // 1. 先查状态：已授权直接过，不打扰用户
    final status = await permission.status;
    if (status.isGranted || status.isLimited) {
      return PermissionOutcome.granted;
    }

    // 2. 永久拒绝：再弹系统窗也不会显示，直接引导去设置
    if (status.isPermanentlyDenied) {
      return PermissionOutcome.deniedForever;
    }

    // 3. 首次/曾被拒但可再弹：发起系统申请
    //    （Google 建议的 rationale 解释文案由业务侧在申请前展示）
    final result = await permission.request();
    if (result.isGranted || result.isLimited) {
      return PermissionOutcome.granted;
    }
    return result.isPermanentlyDenied
        ? PermissionOutcome.deniedForever
        : PermissionOutcome.deniedOnce;
  }

  /// 被拒后的引导：弹对话框 -> 跳系统设置页
  static Future<bool> showSettingsDialog(
    BuildContext context, {
    String title = '权限被拒绝',
    String content = '请在系统设置中开启相关权限后重试',
  }) async {
    final goSettings = await showDialog<bool>(
      context: context,
      builder: (ctx) => AlertDialog(
        title: Text(title),
        content: Text(content),
        actions: [
          TextButton(
              onPressed: () => Navigator.pop(ctx, false),
              child: const Text('暂不')),
          FilledButton(
              onPressed: () => Navigator.pop(ctx, true),
              child: const Text('去设置')),
        ],
      ),
    );
    if (goSettings == true) {
      // openAppSettings：Android 跳应用详情页，iOS 跳本 App 设置页
      await openAppSettings();
    }
    return goSettings ?? false;
  }
}
```

业务侧用法（以扫码前的相机权限为例）：`ensure(Permission.camera)` 返回 `granted` 进扫码页；`deniedOnce` 轻提示即可（下次还能再申请）；`deniedForever` 调 `showSettingsDialog(context, content: '请在设置中开启相机权限，否则无法使用扫码功能')` 引导去系统设置。

**Android/iOS 差异与坑点**：

- Android 的权限组概念已弱化（Android 11+ 逐个权限申请）；iOS 首次拒绝后再次 `request` **不弹窗**，行为等同 Android 的永久拒绝——`permission_handler` 的 `isPermanentlyDenied` 在 iOS 上能正确识别（依赖其原生侧判断，以官方 README 为准）。
- Android 13 的 `POST_NOTIFICATIONS`、Android 12 的精确位置，都是"新版本新权限"，老 App 升级 targetSdk 后才触发——升 targetSdk 前务必回归权限流程。
- iOS 的 Info.plist 描述文案（`NSCameraUsageDescription` 等）缺失会**直接崩溃**，且文案质量影响审核。
- 权限申请要在**用户触发具体功能时**发起，不要 App 一启动全申请一遍——审核会被拒，用户会卸载。

## 4. 推送

### 4.1 整体架构

```
┌──────────┐   ┌──────────────┐   ┌─────────────────────────┐
│  服务端   │──▶│  推送通道     │──▶│  设备（App 客户端）       │
│ (业务后端)│   │              │   │                         │
└──────────┘   └──────┬───────┘   └───────────┬─────────────┘
        ┌─────────────┼─────────────┐         │ 展示通知/处理点击
        ▼             ▼             ▼         ▼
   厂商通道        FCM/APNs     聚合服务   (通知点击 -> 路由跳转)
   (小米/华为/    (海外/大陆     (极光/个推
    OPPO/vivo)    不稳定)       帮你封装以上)
```

### 4.2 国内特殊性：为什么 FCM 不好使

FCM（Firebase Cloud Messaging）在国内**长期不可达**（连接 Google 服务不稳定）。所以国内推送的现实是：**App 进程被杀后，只有厂商通道（小米/华为/荣耀/OPPO/vivo/魅族）能送达**——推送走厂商系统级服务，不依赖你的 App 进程存活。而 App 进程活着时，可以走自建长连接通道送达。这就是国内推送的二元结构。

### 4.3 选型建议（有观点）

| 方案 | 适合 | 说明 |
| --- | --- | --- |
| 聚合服务（极光 JPush / 个推） | 中小团队、快速上线 | 一套 SDK 封装厂商通道 + 在线长连接，服务端一个 API 全通道下发。缺点：付费解锁高级功能、SDK 体积、隐私合规要过一遍 |
| 自接厂商 SDK | 大厂/有推送团队 | 每家厂商单独申请后台、单独接 SDK、单独适配。送达率和成本最优，但 5+ 家通道的维护成本极高 |
| 只接 FCM | 纯海外产品 | 国内项目直接排除 |

我的建议：**没有专职客户端推送团队，就选聚合服务**，把精力花在业务上。自接厂商通道的 ROI 在日活几十万以下很难为正。

### 4.4 客户端接入要点与坑

- **Android**：聚合 SDK 要求在其后台配置各厂商 appId/appKey，并在原生工程里按文档加初始化代码和混淆规则（原生侧工作，以所选 SDK 文档为准）。
- **iOS**：需要 APNs 证书 / p8 密钥，`didRegisterForRemoteNotificationsWithDeviceToken` 回调里把 deviceToken 上报服务端。
- **设备标识绑定**：SDK 拿到 registrationId 后要绑定到自己的用户体系（userId + registrationId 上报自家后端），否则服务端没法给指定用户发推送。
- **隐私合规**：初始化推送 SDK 必须在用户同意隐私协议之后（工信部红线），初始化时机别放在 main() 第一行。

### 4.5 点击通知路由跳转（企业高频坑）

需求看着简单：点击通知打开订单详情页。坑在**冷启动与热启动的处理路径完全不同**：

```
冷启动（进程不存在）: 点击通知 -> 系统拉起 App -> main() 全量初始化
  问题：页面栈还没建好，直接 push 会黑屏/丢首页栈；通知数据在启动参数里
热启动（进程存活）: 点击通知 -> SDK 回调
  问题：直接操作 Navigator 可能跨 context，且不知道当前在哪个页面
```

解决方案：**通知点击统一转成"待处理路由事件"，由路由层消费**：

```dart
// lib/services/push_router_service.dart
import 'dart:async';

/// 通知点击事件：冷热启动统一收敛到这个流
class PushRouterService {
  PushRouterService._();

  static final _controller = StreamController<String>.broadcast();
  static Stream<String> get onNotificationTap => _controller.stream;

  /// SDK 通知点击回调（热启动路径）调用
  static void handleTap(String route) => _controller.add(route);

  /// 冷启动路径：main() 读启动参数中的路由灌入同一流，时机须在 GoRouter 就绪后
  static void seedColdStartRoute(String? route) {
    if (route != null && route.isNotEmpty) _controller.add(route);
  }

  static void dispose() => _controller.close();
}
```

```dart
// lib/app.dart（节选）：GoRouter 消费点击事件
import 'package:go_router/go_router.dart';

import 'services/push_router_service.dart';

final goRouter = GoRouter(
  routes: [ /* '/'、'/order/:id' 等业务路由 */ ],
);

// AppRoot（StatefulWidget）的 initState 里统一消费，冷热启动都走 go()：
PushRouterService.onNotificationTap.listen((route) {
  goRouter.go(route); // 用 go 而不是 push，避免连点通知堆叠页面栈
});
// build：MaterialApp.router(routerConfig: goRouter)
```

- **冷启动**：通知数据在启动参数（原生侧经通道传给 Dart，或 SDK 的 getLaunchNotification API），必须等首页就绪后再灌入跳转流，否则白屏/丢栈；**热启动**：SDK 点击回调直接进流。
- 通知 payload 与服务端约定协议（如 `{"route": "/order/123"}`），客户端只认协议不认 SDK 私有格式。

```dart
  borderRadius: BorderRadius.circular(8), // 圆角
  child: CachedNetworkImage(
    imageUrl: url,
    memCacheWidth: 300, // 解码尺寸限制：列表页必配，见下方"内存控制"
    // 占位：统一灰底，禁止空白闪屏
    placeholder: (_, __) => Container(color: Colors.grey.shade300),
    // 错误：统一兜底，禁止裂图图标裸奔
    errorWidget: (_, __, ___) => const Icon(Icons.broken_image_outlined),
  ),
);
```

**内存缓存上限配置**（列表页很多大图时必配）：

```dart
// lib/main.dart（main() 里，runApp 之前）
import 'package:flutter_cache_manager/flutter_cache_manager.dart';

// 磁盘缓存上限：最多 1000 个文件、30 天过期（按需调）
// 接入方式：CachedNetworkImage(imageCacheManager: 你的实例)
final imageCache = CacheManager(Config('app_image_cache',
    maxNrOfCacheObjects: 1000, // 最多缓存文件数
    stalePeriod: const Duration(days: 30))); // 过期时间
```

**大图列表内存控制**——**永远给图片声明尺寸或 `memCacheWidth`**：不给尺寸时按原图分辨率解码，一张 4000×3000 的照片解码后占约 45MB 内存；列表小图按"显示宽度 × 1~3 倍设备像素比"限制解码尺寸。

- 长列表配合 `ListView.builder` 惰性构建；超大图列表可收紧 `scrollCacheExtent`（3.44 起替代 `cacheExtent`）减少预渲染。


### 6.4 平板/横屏适配

对标 CSS 响应式的断点方案，用 `LayoutBuilder`：

```dart
// lib/widgets/adaptive_layout.dart
import 'package:flutter/material.dart';

/// 断点布局：对标 CSS media query
class AdaptiveLayout extends StatelessWidget {
  const AdaptiveLayout({
    super.key,
    required this.compact,   // 手机竖屏 < 600
    required this.medium,    // 折叠屏/小平板 600~840
    required this.expanded,  // 平板横屏 >= 840
  });

  final WidgetBuilder compact;
  final WidgetBuilder medium;
  final WidgetBuilder expanded;

  @override
  Widget build(BuildContext context) {
    return LayoutBuilder(builder: (context, constraints) {
      final width = constraints.maxWidth;
      if (width >= 840) return expanded(context);
      if (width >= 600) return medium(context);
      return compact(context);
    });
  }
}
```

企业实践：列表-详情双栏（横屏左列表右详情）、网格列数随宽度变化。**别用 `MediaQuery.sizeOf` 判断"是不是平板"**——折叠屏展开瞬间会切形态，用约束宽度做断点才是对的。横屏业务不支持就锁竖屏（`AndroidManifest` 的 `screenOrientation` + iOS 的 `UISupportedInterfaceOrientations`）。

## 7. 埋点体系

### 7.1 事件模型（先和后端定协议）

```dart
// lib/services/analytics/track_event.dart
/// 埋点事件模型：与后端约定统一协议；公共字段（时间/用户/设备）由上报器统一补充
class TrackEvent {
  TrackEvent({required this.name, this.params = const {}});

  final String name; // 事件名（snake_case，如 order_detail_view）
  final Map<String, dynamic> params; // 业务参数
}
```

```dart
// lib/services/analytics/analytics_service.dart —— 上报器
import 'package:flutter/foundation.dart';

import 'track_event.dart';

class AnalyticsService {
  AnalyticsService._();

  static Future<void> track(TrackEvent event) async {
    final payload = {
      'name': event.name,
      'params': event.params,
      'timestamp': DateTime.now().millisecondsSinceEpoch,
      'user_id': '...',     // 从用户服务取
      'device_id': '...',   // 首次启动生成并持久化
      'app_version': '...', // 从 package_info_plus 取（见第 8 节）
      'platform': defaultTargetPlatform.name,
    };
    // 真实实现：批量缓冲 + 定时/退出时上报，别一条一发
    debugPrint('track: $payload');
  }
}
```

### 7.2 路由曝光：GoRouter observer 自动 PV

```dart
// lib/services/analytics/route_observer.dart —— 页面进入自动上报 PV
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

import 'analytics_service.dart';
import 'track_event.dart';

class AnalyticsRouteObserver extends NavigatorObserver {
  @override
  void didPush(Route route, Route? previousRoute) => _track(route);

  @override
  void didReplace({Route? newRoute, Route? oldRoute}) {
    if (newRoute != null) _track(newRoute);
  }

  void _track(Route route) {
    final name = route.settings.name;
    if (name == null || name.isEmpty) return;
    AnalyticsService.track(TrackEvent(name: 'page_view', params: {'page': name}));
  }
}

// GoRouter 挂载（GoRouter 7+ 的 observers 参数，挂到根 Navigator）：
final goRouter = GoRouter(
  observers: [AnalyticsRouteObserver()],
  routes: [ /* ... */ ],
);
```

注意：使用 ShellRoute 嵌套子 Navigator 时，内层页面跳转需要在子路由 `observers` 里单独挂（以 GoRouter 文档为准）。**坑**：`route.settings.name` 依赖你给路由命名——没命名就全 null，团队规范必须给每条路由配 name。

### 7.3 点击事件：显式上报 vs 全局拦截

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 全局手势拦截（Listener 包 MaterialApp 监听 PointerDownEvent） | 无侵入、全量采集 | 坐标上报无业务语义，分析难，隐私合规风险 |
| 显式上报（封装 `TrackableInkWell`，埋点点位写代码） | 事件有业务语义、可精确分析 | 要开发自觉，漏埋常见 |

```dart
// lib/widgets/trackable_inkwell.dart —— 业务侧统一用它替代裸 InkWell
import 'package:flutter/material.dart';

import '../services/analytics/analytics_service.dart';
import '../services/analytics/track_event.dart';

class TrackableInkWell extends StatelessWidget {
  const TrackableInkWell({
    super.key,
    required this.child,
    required this.onTap,
    required this.trackName, // 必填：埋点事件名
    this.trackParams = const {},
  });

  final Widget child;
  final VoidCallback? onTap;
  final String trackName;
  final Map<String, dynamic> trackParams;

  @override
  Widget build(BuildContext context) {
    return InkWell(
      onTap: () {
        AnalyticsService.track(TrackEvent(name: trackName, params: trackParams));
        onTap?.call();
      },
      child: child,
    );
  }
}
```

**我的建议**：核心链路（注册、下单、支付）显式埋点 + 埋点评审（需求评审时把埋点当交付物）；PV 类自动采集交给路由 observer。全局手势拦截只作补充，坐标类数据只做热力图参考。

## 8. 应用升级

### 8.1 版本检查：服务端接口约定

```
GET /api/app/version?platform=android&version=1.2.3
响应：
{
  "latestVersion": "1.3.0",
  "minVersion": "1.0.0",       // 低于此版本 -> 强制更新
  "downloadUrl": "https://cdn.xxx.com/app-1.3.0.apk",
  "updateLog": "1. 新增xx功能\n2. 修复xx问题",
  "forceUpdate": false          // 也可由后端直接下发强制标记
}
```

判断逻辑：`当前版本 < minVersion` → 强制；`当前版本 < latestVersion` → 可忽略。**版本比较不能直接字符串比较**（`1.10.0 < 1.9.0` 会误判），要逐段数值比较：

```dart
// lib/services/upgrade_service.dart
import 'package:package_info_plus/package_info_plus.dart';

/// 版本号比较：a < b 返回 -1，相等 0，a > b 返回 1
int compareVersion(String a, String b) {
  final pa = a.split('.').map(int.parse).toList();
  final pb = b.split('.').map(int.parse).toList();
  for (var i = 0; i < pa.length || i < pb.length; i++) {
    final x = i < pa.length ? pa[i] : 0;
    final y = i < pb.length ? pb[i] : 0;
    if (x != y) return x < y ? -1 : 1;
  }
  return 0;
}

/// 检查结果：needUpdate 是否有新版，force 是否强制（低于 minVersion 或后端强制标记）
({bool needUpdate, bool force}) checkVersion({
  required String current,
  required String latest,
  required String minSupported,
  required bool serverForce,
}) {
  return (
    needUpdate: compareVersion(current, latest) < 0,
    force: compareVersion(current, minSupported) < 0 || serverForce,
  );
}

/// 当前版本号：来自构建配置（pubspec.yaml 的 version）
Future<String> currentVersion() async =>
    (await PackageInfo.fromPlatform()).version;
```

### 8.2 下载安装与跳商店（平台差异）

```dart
// lib/services/upgrade_actions.dart
import 'package:flutter/foundation.dart';
import 'package:url_launcher/url_launcher.dart';

class UpgradeActions {
  /// Android：浏览器下载 APK（企业常规做法）。应用内下载+安装需额外原生配置：
  /// Android 8+ 装 APK 要 REQUEST_INSTALL_PACKAGES 权限与用户引导，以官方文档为准
  static Future<void> androidDownload(String url) =>
      launchUrl(Uri.parse(url), mode: LaunchMode.externalApplication);

  /// iOS：只能跳 App Store（苹果不允许 APK 式安装），url 形如 apps.apple.com/cn/app/idXXXX
  static Future<void> iosGoStore(String url) async {
    final uri = Uri.parse(url);
    if (await canLaunchUrl(uri)) {
      await launchUrl(uri, mode: LaunchMode.externalApplication);
    }
  }

  static Future<void> start(String url) =>
      defaultTargetPlatform == TargetPlatform.android
          ? androidDownload(url)
          : iosGoStore(url);
}
```

### 8.3 强制/可忽略更新的 UI 与逻辑

```dart
// lib/widgets/upgrade_dialog.dart —— force=true 时不可关闭
import 'package:flutter/material.dart';

import '../services/upgrade_actions.dart';

void showUpgradeDialog(
  BuildContext context, {
  required bool force,
  required String url,
  required String updateLog,
}) {
  showDialog<void>(
    context: context,
    barrierDismissible: !force, // 强更不允许点外部关闭
    builder: (ctx) => PopScope(
      canPop: !force, // 强更拦截系统返回键/手势
      child: AlertDialog(
        title: const Text('发现新版本'),
        content: Text(updateLog),
        actions: [
          if (!force)
            TextButton(
                onPressed: () => Navigator.pop(ctx), child: const Text('暂不更新')),
          FilledButton(
              onPressed: () => UpgradeActions.start(url), child: const Text('立即更新')),
        ],
      ),
    ),
  );
}
```

**企业坑点**：

- 强更弹窗要在**首页渲染后**弹，别在 splash 阶段弹（上下文不稳）。进 App 时检查一次 +「我的-检查更新」手动入口，两处共用同一 service。
- iOS 审核期间（已提交未过审）严禁弹"去更新"引导下载 TestFlight/企业签——审核会被拒。
- Android 各厂商商店对"自更新"有政策限制（上架厂商商店的 App 引导 APK 下载可能被下架），分发策略要和运营对齐。

## 9. 启动页：flutter_native_splash

启动页是**原生层**的活（Dart 引擎初始化有耗时，默认白屏就是这段空窗），`flutter_native_splash` 帮你生成原生启动图配置：

```yaml
# pubspec.yaml
dev_dependencies:
  flutter_native_splash: ^2.4.3  # 以 pub.dev 为准

flutter_native_splash:
  color: "#FFFFFF"            # 纯色背景
  image: assets/splash_logo.png
  android_12:
    color: "#FFFFFF"
    image: assets/splash_logo_android12.png  # Android 12 规范要求图标
```

```bash
# 生成原生配置（写入 android/ios 工程）
dart run flutter_native_splash:create
```

**要点**：

- Android 12+ 的启动页是系统规范化的（中心图标 + 背景色，不支持全屏图），`android_12` 配置必须单独给，否则适配机型上体验割裂。
- iOS 启动图规范也在收严，全屏营销启动页基本进历史。企业惯例：原生启动页用 logo + 品牌色，进 App 后如需营销开屏再在 Flutter 层做一张可跳过的广告页——**原生启动页和广告开屏是两回事**，别混。
- 改完 splash 记得完整重新构建（它是原生资源，热重载无效）。
