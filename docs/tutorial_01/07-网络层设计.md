## 一、从 http 包说起：为什么企业项目几乎都用 dio

官方 `http` 包就像浏览器里的 `fetch`：能用，但企业项目不会裸用。前端从 `fetch` 迁移到 `axios`，核心原因从来不是"发不出请求"，而是**治理能力**。Flutter 生态的答案是 **dio**（版本以 pub.dev 为准）：

| 能力 | http | dio | 前端对照 |
|---|---|---|---|
| 拦截器 | ❌ | ✅ 请求/响应/错误 | axios interceptors |
| 超时控制 | 手写 | ✅ 连接/接收/发送三级 | axios `timeout` |
| 请求取消 | ❌ | ✅ `CancelToken` | AbortController |
| 自动重试 | ❌ | ✅ 拦截器实现 | axios-retry |
| FormData 上传 | 手拼 multipart | ✅ 内置 | FormData |

观点：**demo 用 http 没问题；超过 3 个页面、需要登录态的项目，dio 是唯一务实的选择**。

```yaml
# pubspec.yaml
dependencies:
  dio: ^5.x              # 版本以 pub.dev 为准
  flutter_riverpod: ^3.5.0   # 3.x；2.x 迁移差异见 06 篇 5.2.1
```

## 二、dio 基础封装：环境、单例与 BaseOptions

### 2.1 环境区分：--dart-define

企业项目至少 dev / staging / prod 三套环境，用 `--dart-define` 在编译期注入，**不要**把三套 baseUrl 写死在代码里 `if` 判断：

```bash
# 开发：flutter run --dart-define=APP_ENV=dev --dart-define=API_BASE_URL=https://dev.api.example.com
# 发布：--dart-define=APP_ENV=prod --dart-define=API_BASE_URL=https://api.example.com（由 CI 注入）
```

```dart
// lib/core/network/api_env.dart
enum AppEnv { dev, staging, prod }

/// 编译期注入的环境配置
class ApiEnv {
  ApiEnv._();
  static const String _envName = String.fromEnvironment('APP_ENV', defaultValue: 'dev');
  /// 服务端根地址，正式地址由 CI 注入
  static const String baseUrl =
      String.fromEnvironment('API_BASE_URL', defaultValue: 'https://dev.api.example.com');
  static const String appVersion = String.fromEnvironment('APP_VERSION', defaultValue: '0.0.0');
  static AppEnv get env => switch (_envName) {
        'staging' => AppEnv.staging,
        'prod' => AppEnv.prod,
        _ => AppEnv.dev,
      };
  static bool get isProd => env == AppEnv.prod;
}
```

### 2.2 ApiClient：一个项目只有一个 Dio 实例

Dio 实例很重（连接池、拦截器、配置），全局复用一个。但**单例 ≠ 不可替换**——为测试留注入口，用"启动时装配 + 惰性默认"：

```dart
// lib/core/network/api_client.dart
import 'package:dio/dio.dart';
import 'api_env.dart';
import 'interceptors/logger_interceptor.dart';

/// 统一网络客户端。Repository 层禁止自行 new Dio。
class ApiClient {
  ApiClient._(this.dio);
  final Dio dio;
  static ApiClient? _instance;

  /// 全局单例：main() 先 bootstrap() 则用装配好的拦截器
  static ApiClient get instance => _instance ??= create();

  /// 启动装配：注入需要运行时依赖的拦截器（鉴权），见第三节
  static void bootstrap(List<Interceptor> interceptors) {
    _instance = create(interceptors: interceptors);
  }

  static ApiClient create({String? baseUrl, List<Interceptor>? interceptors}) {
    final dio = Dio(BaseOptions(
      baseUrl: baseUrl ?? ApiEnv.baseUrl,
      connectTimeout: const Duration(seconds: 10),
      receiveTimeout: const Duration(seconds: 15),
      sendTimeout: const Duration(seconds: 10),
      headers: {
        'Content-Type': 'application/json',
        'X-App-Version': ApiEnv.appVersion, // 网关侧灰度/强升判断用
      },
      responseType: ResponseType.json,
    ));
    dio.interceptors.addAll(interceptors ?? [LoggerInterceptor()]);
    return ApiClient._(dio);
  }

  // Repository 层的快捷方法；put/delete 同 get 换动词即可
  Future<Response<T>> get<T>(String path,
          {Object? queryParameters, Options? options, CancelToken? cancelToken}) =>
      dio.get<T>(path,
          queryParameters: queryParameters, options: options, cancelToken: cancelToken);
  Future<Response<T>> post<T>(String path,
          {Object? data, Options? options, CancelToken? cancelToken}) =>
      dio.post<T>(path, data: data, options: options, cancelToken: cancelToken);
}
```

企业细节：**超时三级分离**（连接失败要快速反馈，下载慢数据要多容忍）；**公共 headers 收口**（版本头散落在调用点是事故源头）。

### 2.3 日志拦截器：debug 开关

日志拦截器必须受环境开关控制——**release 包打请求日志是事故**（token、用户数据直接进日志平台）：

```dart
// lib/core/network/interceptors/logger_interceptor.dart
import 'package:dio/dio.dart';
import '../api_env.dart';

/// 仅非生产环境生效
class LoggerInterceptor extends Interceptor {
  @override
  void onRequest(RequestOptions o, RequestInterceptorHandler h) {
    if (!ApiEnv.isProd) {
      final headers = Map<String, dynamic>.from(o.headers)..remove('Authorization'); // 防泄漏
      print('→ [${o.method}] ${o.uri}\n  headers: $headers');
    }
    h.next(o);
  }
  @override
  void onResponse(Response r, ResponseInterceptorHandler h) {
    if (!ApiEnv.isProd) print('← [${r.statusCode}] ${r.requestOptions.uri}');
    h.next(r);
  }
  @override
  void onError(DioException e, ErrorInterceptorHandler h) {
    if (!ApiEnv.isProd) print('✕ [${e.requestOptions.uri}] ${e.type} ${e.message}');
    h.next(e);
  }
}
```

## 三、拦截器实战（核心篇幅）

### 3.1 鉴权拦截器：Token 自动注入

UI / Repository 层**永远不手动拼 Authorization**。先定义 Token 存取抽象——网络层只依赖抽象，真实实现在 [08-本地存储](08-本地存储.md)：

```dart
// lib/core/network/token_store.dart
/// Token 存取抽象；生产实现（SecureTokenStore）与测试用 InMemoryTokenStore 见 08-本地存储.md
abstract class TokenStore {
  String? get accessToken;
  String? get refreshToken;
  Future<void> save({required String accessToken, required String refreshToken});
  Future<void> clear();
}
```

两个前置设计决策决定了代码结构：**刷新接口用独立的裸 Dio**（共用主 Dio，刷新请求自身 401 后会再触发拦截器，无限递归）；**重放也用独立的裸 Dio** + `extra` 标记双保险（保证每个请求最多经历一次"401 → 刷新 → 重放"）。

```dart
// lib/core/network/interceptors/auth_interceptor.dart
import 'package:dio/dio.dart';
import '../token_refresh_queue.dart';
import '../token_store.dart';

/// 自动注入 Token；401 单飞刷新并重放；刷新失败登出。
class AuthInterceptor extends Interceptor {
  AuthInterceptor(
      {required TokenStore store,
      required TokenRefreshQueue queue,
      required Future<void> Function() onLogout})
      : _store = store,
        _queue = queue,
        _onLogout = onLogout;

  final TokenStore _store;
  final TokenRefreshQueue _queue;
  final Future<void> Function() _onLogout;
  static const _replayedKey = 'auth.replayed';

  @override
  void onRequest(RequestOptions o, RequestInterceptorHandler h) async {
    // 闸门：正在刷新时挂起新请求，避免带旧 token 出去又吃一个 401
    final pending = await _queue.gate();
    final token = pending ?? _store.accessToken;
    if (token != null && token.isNotEmpty) o.headers['Authorization'] = 'Bearer $token';
    h.next(o);
  }

  @override
  void onError(DioException err, ErrorInterceptorHandler h) async {
    final status = err.response?.statusCode;
    final isRefreshCall = err.requestOptions.path.contains('/auth/refresh');
    final alreadyReplayed = err.requestOptions.extra[_replayedKey] == true;
    // 非 401 / 刷新接口自身出错 / 已重放过一次：直接透传
    if (status != 401 || isRefreshCall || alreadyReplayed) return h.next(err);
    try {
      final newToken = await _queue.refreshOnce(); // 单飞，见 3.2
      final options = err.requestOptions
        ..headers['Authorization'] = 'Bearer $newToken'
        ..extra[_replayedKey] = true;
      // 裸 Dio 重放：options 里已是解析完的完整 uri，不经过任何拦截器
      h.resolve(await _replayDio().fetch(options));
    } on DioException catch (e) {
      if (e.response?.statusCode == 401) {
        await _store.clear(); // 新 token 依然 401 ⇒ refresh token 已失效
        await _onLogout();
      }
      h.next(e);
    } catch (_) {
      await _store.clear();
      await _onLogout();
      h.next(err);
    }
  }

  static Dio? _cached;
  Dio _replayDio() => _cached ??= Dio(BaseOptions(
        connectTimeout: const Duration(seconds: 10),
        receiveTimeout: const Duration(seconds: 15),
      ));
}
```

### 3.2 401 单飞刷新：并发请求只刷一次（企业必考）

页面进来同时发 5 个请求 → token 过期 → 5 个 401 同时回来。天真实现会**刷新 5 次**，而多数后端 refresh token 一次性有效，第 2 次刷新就失败，用户被全量登出。这与前端 axios"并发 401 排队等同一个 refresh Promise"是同一个问题。正确思路是**单飞（single-flight）+ 闸门**：

```dart
// lib/core/network/token_refresh_queue.dart
import 'dart:async';

/// 单飞刷新控制器：任意时刻至多一个真实 refresh 请求；
/// 并发 401 共享这次刷新；刷新期间新请求先入队挂起，成功后放行、失败后透传。
class TokenRefreshQueue {
  TokenRefreshQueue(this._doRefresh);
  /// 真正执行刷新（main() 注入，内部发网络请求并写回 TokenStore）
  final Future<String> Function() _doRefresh;
  Completer<String>? _refreshing; // 非 null 表示刷新中
  final List<Completer<String>> _waiting = []; // 闸门挂起的请求

  /// 出发前的闸门：未在刷新返回 null；正在刷新则挂起等待唤醒
  Future<String?> gate() {
    final current = _refreshing;
    if (current == null) return Future.value(null);
    final waiter = Completer<String>();
    _waiting.add(waiter);
    return waiter.future;
  }

  /// 401 后调用：拿到"保证只执行一次"的刷新 Future
  Future<String> refreshOnce() {
    final current = _refreshing;
    if (current != null) return current.future; // 已在刷新：共享结果
    final completer = Completer<String>();
    _refreshing = completer;
    _doRefresh().then((newToken) {
      if (!completer.isCompleted) completer.complete(newToken);
      for (final w in _waiting) {
        if (!w.isCompleted) w.complete(newToken); // 唤醒闸门中排队的请求
      }
    }).catchError((Object e, StackTrace s) {
      if (!completer.isCompleted) completer.completeError(e, s);
      for (final w in _waiting) {
        if (!w.isCompleted) w.completeError(e, s);
      }
    }).whenComplete(() {
      _waiting.clear();
      _refreshing = null; // 解锁回空闲
    });
    return completer.future;
  }
}
```

### 3.3 main() 装配：接通刷新链路

```dart
// lib/main.dart（节选）
import 'package:dio/dio.dart';
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import 'core/network/api_client.dart';
import 'core/network/api_env.dart';
import 'core/network/interceptors/auth_interceptor.dart';
import 'core/network/interceptors/logger_interceptor.dart';
import 'core/network/token_refresh_queue.dart';
import 'core/storage/secure_token_store.dart'; // 实现在 08-本地存储.md

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  final store = await SecureTokenStore.create(); // 1. Token 存储
  final refreshDio = Dio(BaseOptions(baseUrl: ApiEnv.baseUrl)); // 2. 刷新专用裸 Dio
  final queue = TokenRefreshQueue(() async { // 3. 单飞队列
    final res = await refreshDio.post<Map<String, dynamic>>(
      '/auth/refresh',
      data: {'refreshToken': store.refreshToken},
    );
    final accessToken = (res.data?['accessToken'] ?? '') as String;
    final refreshToken = (res.data?['refreshToken'] ?? '') as String;
    await store.save(accessToken: accessToken, refreshToken: refreshToken);
    return accessToken; // 唤醒所有等待者
  });
  ApiClient.bootstrap([ // 4. 装配
    LoggerInterceptor(),
    AuthInterceptor(store: store, queue: queue, onLogout: () async => debugPrint('刷新失败，全局登出')),
  ]);
  runApp(const ProviderScope(child: MyApp()));
}
```

面试官最爱追问的三个边界：

| 问题 | 答案 |
|---|---|
| 为什么刷新接口用独立 Dio？ | 共用会再走 AuthInterceptor，刷新自身 401 触发递归 |
| 刷新失败怎么办？ | `refreshOnce` 抛错 → 排队的 401 全部失败 → 清 store + 统一登出 |
| 登录后新请求怎么带 token？ | 登录页写入 TokenStore，拦截器每次现读现注入，天然生效 |

### 3.4 错误映射：DioException → 业务异常分类

UI 层不应知道 DioException 的存在——组件里写 `if (err.response?.status === 500)` 是坏味道。**错误分类是企业网络层第二个必考**。约定五种异常：

```dart
// lib/core/network/app_exception.dart
/// sealed：外部文件无法继承，switch 可穷尽（Dart 3）
sealed class AppException implements Exception {
  const AppException(this.message, {this.cause});
  final String message;
  final Object? cause;
}

class NetworkUnreachableException extends AppException { // 无网/飞行模式/DNS 失败
  const NetworkUnreachableException(super.message, {super.cause});
}
class TimeoutException extends AppException { // 连接/发送/接收超时
  const TimeoutException(super.message, {super.cause});
}
class ServerException extends AppException { // 服务端 5xx
  const ServerException(super.message, {super.cause, this.statusCode});
  final int? statusCode;
}
class BusinessException extends AppException { // 200 但 code!=0，或 4xx 业务语义
  const BusinessException(super.message, {super.cause, required this.code});
  final int code;
}
class RequestCancelledException extends AppException { // 请求被取消
  const RequestCancelledException(super.message, {super.cause});
}
```

```dart
// lib/core/network/exception_mapper.dart
import 'package:dio/dio.dart';
import 'app_exception.dart';

/// DioException → AppException 的唯一转换入口
AppException mapDioException(DioException e) {
  switch (e.type) {
    case DioExceptionType.connectionError:
      return NetworkUnreachableException('网络不可用，请检查网络设置', cause: e);
    case DioExceptionType.connectionTimeout:
    case DioExceptionType.sendTimeout:
    case DioExceptionType.receiveTimeout:
      return TimeoutException('请求超时，请稍后重试', cause: e);
    case DioExceptionType.badResponse:
      final status = e.response?.statusCode ?? 0;
      final body = e.response?.data;
      if (status >= 500) {
        return ServerException('服务器开小差了（$status）', cause: e, statusCode: status);
      }
      final bizCode = body is Map<String, dynamic> ? (body['code'] as int? ?? status) : status;
      final bizMsg = body is Map<String, dynamic> ? (body['msg'] as String? ?? '请求失败') : '请求失败';
      return BusinessException(bizMsg, cause: e, code: bizCode);
    case DioExceptionType.cancel:
      return RequestCancelledException('请求已取消', cause: e);
    case DioExceptionType.badCertificate:
      return NetworkUnreachableException('证书校验失败', cause: e);
    default:
      return ServerException('未知网络错误', cause: e);
  }
}
```

## 四、统一响应模型：ApiResponse 与 Result sealed

### 4.1 ApiResponse<T>：包装 code/msg/data 约定

后端约定 `{"code": 0, "msg": "ok", "data": {...}}`，泛型包装后调用方只写一行解析器：

```dart
// lib/core/network/api_response.dart
class ApiResponse<T> {
  const ApiResponse({required this.code, required this.msg, this.data});
  final int code;
  final String msg;
  final T? data;

  bool get isOk => code == 0;

  factory ApiResponse.fromJson(Map<String, dynamic> json, T Function(dynamic json)? fromData) {
    final data = json['data'];
    return ApiResponse<T>(
      code: (json['code'] as num?)?.toInt() ?? -1,
      msg: (json['msg'] as String?) ?? '',
      data: data == null || fromData == null ? null : fromData(data),
    );
  }
}
```

### 4.2 Result<T>：把异常挡在 Repository 内部

Repository 不应把异常抛给 UI——UI 拿到异常也只能转成文案/Toast，那不如在仓库内转换。用 **Dart 3 sealed class + switch 模式匹配**（企业写法）。sealed 保证 switch 穷尽：编译器强制处理 Ok/Err 两个分支，不会出现"忘了处理失败"的线上事故：

```dart
// lib/core/result.dart
import 'app_exception.dart' show AppException;

sealed class Result<T> {
  const Result();
  factory Result.ok(T data) = Ok<T>;
  factory Result.err(AppException error) = Err<T>;
}

final class Ok<T> extends Result<T> {
  const Ok(this.data);
  final T data;
}

final class Err<T> extends Result<T> {
  const Err(this.error);
  final AppException error;
}
```

UI 侧穷尽匹配（漏写分支是编译警告而不是线上事故）：

```dart
// 五种异常各有专属文案与处理路径；生产中还可按需补 fold/guard 等扩展方法
switch (await userRepository.fetchProfile(userId)) {
  case Ok(:final data):
    setState(() => user = data);
  case Err(:final error):
    switch (error) {
      case NetworkUnreachableException(): // 联动 08 篇的缓存兜底
        showSnack('当前无网络，展示离线缓存');
      case RequestCancelledException():
        break; // 取消不是错误，静默
      default:
        showSnack(error.message);
    }
}
```

## 五、JSON 序列化：手写的痛与代码生成

### 5.1 手写 fromJson 为什么撑不住

`as int?` 写错只在运行时炸——没有编译期保护是手写最大的问题；后端下划线命名（`avatar_url`）忘做转换也是运行时才炸。方案：`json_serializable` 或 `freezed`。

### 5.2 json_serializable（推荐默认）

```yaml
dependencies:
  json_annotation: ^4.x
dev_dependencies:
  build_runner: ^2.x
  json_serializable: ^6.x
```

```dart
// lib/features/user/data/models/user_dto.dart
import 'package:json_annotation/json_annotation.dart';
part 'user_dto.g.dart'; // build_runner 生成

@JsonSerializable(fieldRename: FieldRename.snake)
class UserDto {
  const UserDto({required this.id, required this.name, this.avatarUrl});
  final int id;
  final String name;
  /// 后端可能不回传；给默认值，避免空判定散落各处
  @JsonKey(defaultValue: '')
  final String? avatarUrl;
  factory UserDto.fromJson(Map<String, dynamic> json) => _$UserDtoFromJson(json);
  Map<String, dynamic> toJson() => _$UserDtoToJson(this);
}
```

```bash
dart run build_runner build --delete-conflicting-outputs # 一次性生成
dart run build_runner watch                          # 开发时保存即生成
```

### 5.3 freezed 与选型结论

`freezed` 顺带解决"不可变 + copyWith + union 类型"，代价是生成链更重、part 文件更大。**选型观点**：普通业务 DTO 用 `json_serializable`（轻、快、够用）；核心领域模型（需要不可变、copyWith、sealed union，如支付状态机）上 `freezed`；两者混用完全没问题。

### 5.4 DTO 与领域模型分离

**DTO（Data Transfer Object，后端契约的镜像）不直接进 UI**：后端字段是 snake_case、可能有脏数据——Repository 负责转成干净的领域模型：

```dart
// lib/features/user/domain/user.dart
class User {
  const User({required this.id, required this.name, this.avatar = ''});
  final int id;
  final String name;
  final String avatar;
}

// lib/features/user/data/mapper/user_mapper.dart
import '../domain/user.dart';
import 'models/user_dto.dart';

/// DTO → 领域模型的唯一转换点
extension UserDtoMapper on UserDto {
  User toDomain() => User(id: id, name: name, avatar: avatarUrl ?? '');
}
```

## 六、REST 分页封装：泛型 Pageable + Riverpod

### 6.1 泛型分页模型与仓库基类

```dart
// lib/core/network/page_request.dart
class PageRequest {
  const PageRequest({this.page = 1, this.size = 20});
  final int page;
  final int size;
  Map<String, dynamic> toQuery() => {'page': page, 'size': size};
}

// lib/core/network/page_result.dart
/// 分页响应：{ list, total }（字段以后端为准）
class PageResult<T> {
  const PageResult({required this.items, required this.total, required this.page, required this.size});
  final List<T> items;
  final int total;
  final int page;
  final int size;

  bool get hasMore => page * size < total;

  static PageResult<T> fromJson<T>(
    Map<String, dynamic> json,
    T Function(Map<String, dynamic>) fromItem,
  ) {
    final rawList = json['list'] as List<dynamic>? ?? const [];
    return PageResult<T>(
      items: rawList.map((e) => fromItem(e as Map<String, dynamic>)).toList(),
      total: (json['total'] as num?)?.toInt() ?? 0,
      page: (json['page'] as num?)?.toInt() ?? 1,
      size: (json['size'] as num?)?.toInt() ?? 20,
    );
  }
}

// lib/core/network/paged_api.dart
import 'package:dio/dio.dart';
import 'api_client.dart';
import 'page_request.dart';
import 'page_result.dart';

/// 分页仓库基类：子类只提供 path 与单项解析器
abstract class PagedApi<T> {
  PagedApi(this._client);
  final ApiClient _client;
  String get path;
  T Function(Map<String, dynamic> json) get fromItem;

  Future<PageResult<T>> fetchPage(PageRequest req, {CancelToken? cancelToken}) async {
    final res = await _client.get<Map<String, dynamic>>(path,
        queryParameters: req.toQuery(), cancelToken: cancelToken);
    return PageResult.fromJson(res.data ?? const {}, fromItem);
  }
}

// lib/features/user/data/user_api.dart
import '../../../core/network/api_client.dart';
import '../../../core/network/paged_api.dart';
import 'models/user_dto.dart';

class UserApi extends PagedApi<UserDto> {
  UserApi(super.client);
  @override
  String get path => '/users';
  @override
  UserDto Function(Map<String, dynamic> json) get fromItem => UserDto.fromJson;
}
```

### 6.2 Riverpod 分页列表：下拉刷新 + 上拉加载
```dart
// lib/features/user/presentation/user_list_provider.dart
import 'package:dio/dio.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import '../../../core/network/api_client.dart';
import '../../../core/network/app_exception.dart';
import '../../../core/network/page_request.dart';
import '../../../core/network/page_result.dart';
import '../data/mapper/user_mapper.dart';
import '../data/user_api.dart';
import '../domain/user.dart';

/// 列表 UI 状态（不可变）
class PagingState<T> {
  const PagingState({this.items = const [], this.page = 0, this.total = 0, this.loading = false, this.error});
  final List<T> items;
  final int page;
  final int total;
  final bool loading;
  final String? error;

  bool get hasMore => items.length < total;

  PagingState<T> copyWith(
      {List<T>? items, int? page, int? total, bool? loading, String? error, bool clearError = false}) =>
      PagingState<T>(
        items: items ?? this.items,
        page: page ?? this.page,
        total: total ?? this.total,
        loading: loading ?? this.loading,
        error: clearError ? null : error,
      );
}

/// 分页 Notifier 基类：任何列表页继承即得下拉刷新/上拉加载/自动取消
/// 说明：这里沿用 2.x 的 AutoDisposeNotifier 写法，最直观；
/// Riverpod 3.x 已把 AutoDispose/Family 统一合并进 Notifier（见 06 篇 5.2.1），
/// 3.x 等价写法是 `class XxxNotifier extends Notifier<PagingState<T>>`，
/// 并在 provider 上声明 `NotifierProvider.autoDispose`。
abstract class PagingNotifier<T> extends AutoDisposeNotifier<PagingState<T>> {
  Future<PageResult<T>> fetchPage(PageRequest req); // 子类实现
  int get pageSize => 20;
  CancelToken? _cancelToken;

  @override
  PagingState<T> build() {
    // provider 销毁（页面退出）时取消在途请求，根治 setState after dispose
    ref.onDispose(() => _cancelToken?.cancel('provider disposed'));
    Future.microtask(refresh); // 首屏自动加载
    return PagingState<T>();
  }

  /// 下拉刷新：回第 1 页
  Future<void> refresh() async {
    _cancelToken?.cancel('refresh'); // 取消旧请求，防旧数据晚到覆盖新数据
    final token = _cancelToken = CancelToken();
    state = state.copyWith(clearError: true);
    try {
      final result = await fetchPage(PageRequest(page: 1, size: pageSize));
      if (_cancelToken != token) return; // 期间又触发过刷新，本次作废
      state = PagingState<T>(items: result.items, page: result.page, total: result.total);
    } catch (e) {
      if (_cancelToken == token) {
        state = state.copyWith(error: e is AppException ? e.message : '加载失败，请下拉重试');
      }
    }
  }

  /// 上拉加载下一页
  Future<void> loadMore() async {
    if (state.loading || !state.hasMore) return;
    state = state.copyWith(loading: true, clearError: true);
    try {
      final result = await fetchPage(PageRequest(page: state.page + 1, size: pageSize));
      state = state.copyWith(
          items: [...state.items, ...result.items], // 合并；防重复可按 id 去重
          page: result.page,
          total: result.total);
    } catch (e) {
      state = state.copyWith(loading: false, error: e is AppException ? e.message : '加载失败');
    }
  }
}

/// 用户列表 Provider
class UserListNotifier extends PagingNotifier<User> {
  @override
  Future<PageResult<User>> fetchPage(PageRequest req) async {
    final dto = await UserApi(ApiClient.instance).fetchPage(req);
    return PageResult<User>(
      items: dto.items.map((e) => e.toDomain()).toList(),
      total: dto.total, page: dto.page, size: dto.size,
    );
  }
}

final userListProvider =
    AutoDisposeNotifierProvider<UserListNotifier, PagingState<User>>(UserListNotifier.new);
```

```dart
// lib/features/user/presentation/user_list_page.dart（节选）

class UserListPage extends ConsumerWidget {

    final state = ref.watch(userListProvider);
    // 下拉：notifier.refresh()；上拉：列表滚到底时调 loadMore()
    // itemCount = items.length + (hasMore ? 1 : 0)，最后一个下标渲染加载指示器

      child: ListView.builder(

        itemCount: state.items.length + (state.hasMore ? 1 : 0),
        itemBuilder: (_, i) => i >= state.items.length
            ? const Padding(padding: EdgeInsets.all(16), child: CircularProgressIndicator())
            : ListTile(title: Text(state.items[i].name)),
      ),
    );
  }
}
```

## 七、请求取消与重试策略

### 7.1 CancelToken：根治 setState after dispose

搜索页输入联想、详情页秒退是两个高频炸点：请求回来时页面已销毁，`setState` 抛错。**企业规范：绑定页面的请求必须传 CancelToken，销毁时取消**。不依赖 Riverpod 的页面自己管理：

```dart
// lib/features/search/presentation/search_page.dart
import 'package:dio/dio.dart';
import 'package:flutter/material.dart';
import '../../../core/network/api_client.dart';

class _SearchPageState extends State<SearchPage> {
  final CancelToken _cancelToken = CancelToken(); // 页面级：多请求共用

  @override
  void dispose() {
    _cancelToken.cancel('SearchPage disposed'); // 在途请求全部作废
    super.dispose();
  }

  Future<void> _search(String keyword) async {
    try {
      await ApiClient.instance.get('/search',
          queryParameters: {'kw': keyword}, cancelToken: _cancelToken);
    } on DioException catch (e) {
      if (e.type == DioExceptionType.cancel) return; // 取消是正常路径
    }
  }

  @override
  Widget build(BuildContext context) => const SizedBox();
}
```

用 Riverpod 更优雅：`AutoDisposeNotifier.build()` 里 `ref.onDispose(cancel)`（6.2 已示范）。**能取消的请求才是可维护的请求**——同时省流量、省电量、防竞态。

### 7.2 重试策略：幂等才重试

铁律：**只对幂等请求（GET / PUT / DELETE）自动重试，POST 一律不重试**——POST 语义是创建，自动重试可能重复下单。类比 axios-retry，dio 同样在拦截器实现：

```dart
// lib/core/network/interceptors/retry_interceptor.dart
import 'dart:math';
import 'package:dio/dio.dart';

/// 对幂等请求的瞬时失败（超时/网络抖动）做指数退避重试
class RetryInterceptor extends Interceptor {
  RetryInterceptor(this._dio, {this.maxRetries = 2});
  final Dio _dio; // 用主 Dio 重放，保持 baseUrl/超时一致
  final int maxRetries;

  @override
  void onError(DioException err, ErrorInterceptorHandler handler) async {
    final options = err.requestOptions;
    const idempotent = {'GET', 'PUT', 'DELETE'}; // 幂等白名单
    final retried = options.extra['retried'] as int? ?? 0;
    final retriable = switch (err.type) {
      DioExceptionType.connectionTimeout || DioExceptionType.receiveTimeout || DioExceptionType.connectionError => true,
      _ => false,
    };
    if (!idempotent.contains(options.method) || !retriable || retried >= maxRetries) {
      return handler.next(err);
    }
    options.extra['retried'] = retried + 1;
    // 指数退避：500ms、1000ms...（生产建议加随机抖动，避免重试风暴）
    await Future<void>.delayed(Duration(milliseconds: 500 * pow(2, retried).toInt()));
    try {
      handler.resolve(await _dio.fetch(options));
    } on DioException catch (e) {
      handler.next(e); // 重试仍失败，进正常错误链路
    }
  }
}
```

## 八、与 UI 解耦：Repository 模式雏形 + Mock

### 8.1 分层：UI → Provider → Repository → ApiClient

回头看：UI 拿到的始终是 `Result<User>`、`PagingState<User>`，从没碰过 Dio——这就是 Repository（仓库层）的雏形。好处：UI 不关心网络实现，将来换掉 dio 不改一行 UI；Repository 是天然的 **Mock 切入点**。

```dart
// lib/features/user/data/user_repository.dart
import 'package:dio/dio.dart';
import '../../../core/network/api_client.dart';
import '../../../core/network/api_response.dart';
import '../../../core/network/app_exception.dart';
import '../../../core/network/exception_mapper.dart';
import '../../../core/result.dart';
import '../domain/user.dart';
import 'mapper/user_mapper.dart';
import 'models/user_dto.dart';

/// 仓库接口：UI / Provider 只认这个抽象
abstract class UserRepository {
  Future<Result<User>> fetchProfile(int userId);
  // 其余方法（updateUser 等）与 fetchProfile 完全同构，不再赘述
}

class UserRepositoryImpl implements UserRepository {
  UserRepositoryImpl(this._client);
  final ApiClient _client;

  @override
  Future<Result<User>> fetchProfile(int userId) async {
    try {
      final res = await _client.get<Map<String, dynamic>>('/users/$userId');
      final api = ApiResponse<UserDto>.fromJson(res.data ?? const {},
          (json) => UserDto.fromJson(json as Map<String, dynamic>));
      if (!api.isOk) return Result.err(BusinessException(api.msg, code: api.code));
      return Result.ok(api.data!.toDomain());
    } on DioException catch (e) {
      return Result.err(mapDioException(e)); // 网络异常在仓库层就被拦下
    }
  }
}
```
