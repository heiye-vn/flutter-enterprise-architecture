## 1. 先说结论（TL;DR）

企业项目直接用 **go_router**，不要只用 Navigator 1.0。理由：

1. **声明式**：路由配置是一份数据，可预测、可测试、可审查（和 React Router v6 的配置化思路一致）；
2. **深链开箱即用**：URL 即状态，Web 端 / App Links / 推送跳转统一处理；
3. **官方维护**：flutter.dev 团队出品，文档齐全（以 pub.dev/packages/go_router 文档为准）。

Navigator 1.0 仍然要学——它是底层 API，大量老代码和第三方库还在用，而且理解它能让你明白 go_router 到底帮你解决了什么。

## 2. Navigator 1.0：命令式路由的底层

### 2.1 push / pop 基本用法

Flutter 里"页面"本质是一个全屏 Widget，导航由 `Navigator` 这个 StatefulWidget 维护的一个**路由栈（Route Stack）**管理——概念上就是浏览器的历史栈，或者 vue-router 的 history 模式。

```dart
// 命令式跳转：直接往栈里压一个 MaterialPageRoute
Navigator.of(context).push(
  MaterialPageRoute(builder: (context) => const DetailPage()),
);

// pop 弹出栈顶，相当于浏览器"后退"
Navigator.of(context).pop();
```

对照前端：`Navigator.push` ≈ `router.push`（vue-router）或 `navigate()`（React Router），`Navigator.pop` ≈ `router.back()`。区别在于：**命令式路由直接操作栈，路由信息不体现在任何 URL 上**。

### 2.2 命名路由（路由表）

可以在 `MaterialApp` 里注册一张路由表，用字符串名字跳转：

```dart
// lib/main.dart —— 路由表：名字 → 页面构建器，类似 vue-router 的 routes 数组
MaterialApp(
  routes: {
    '/': (context) => const HomePage(),
    '/login': (context) => const LoginPage(),
  },
)
```

```dart
// 命名跳转；带参数：.arguments 是动态类型，类型安全全靠自觉
Navigator.of(context).pushNamed('/order', arguments: {'orderId': 'A001'});

// 取参数——这里没有任何编译期保障，拼错字段名运行时才炸
final args =
    ModalRoute.of(context)?.settings.arguments as Map<String, dynamic>?;
final orderId = args?['orderId'] as String?;
```

`arguments` 是 `Object?` 类型——这在前端里相当于 `this.$route.params` 全是 any。小项目无所谓，企业项目里这种"字符串 + 动态参数"的组合就是 bug 温床。

### 2.3 传参与返回值：`await push`

命令式路由有一个很好用的能力：**push 可以拿到下一页 pop 时的返回值**，这是一个 Future：

```dart
// lib/features/order/pages/order_list_page.dart
import 'package:flutter/material.dart';
import 'order_filter_page.dart';

Future<void> _openFilter(BuildContext context) async {
  // push 返回 Future<T?>，T 是 pop 时传入的泛型
  final result = await Navigator.of(context).push<String>(
    MaterialPageRoute(builder: (context) => const OrderFilterPage()),
  );
  // 用户在筛选页点"确定"返回 'ok'，点系统返回键返回 null
  debugPrint('筛选页返回：$result');
}
```

```dart
// lib/features/order/pages/order_filter_page.dart
import 'package:flutter/material.dart';

class OrderFilterPage extends StatelessWidget {
  const OrderFilterPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('筛选')),
      body: ElevatedButton(
        // pop 可以带返回值，相当于"函数 return"
        onPressed: () => Navigator.of(context).pop('ok'),
        child: const Text('确定'),
      ),
    );
  }
}
```

这个模式在"选择器"场景（选地址、选日期、选筛选条件）非常常用。go_router 里对应 `context.push<bool>(...)` 后 `await`，后面会讲。

### 2.4 为什么企业项目不要只用 Navigator 1.0

三个硬伤：

**① 深链（Deep Link）几乎没法做。** 命令式路由的路由栈是运行时一行行命令堆出来的，收到 `https://app.com/order/A001` 时，你没有任何机制把 URL 映射到栈上。你得自己写一层解析器，维护 URL ↔ 栈 的双向同步——每个团队自己造一遍，质量参差不齐。

**② Web 端 URL 不可预测。** Flutter 编译到 Web 后，命令式路由的地址栏要么不动，要么是一串 `/ Brazilian` 之类的路径（`Navigator.defaultRouteName` 派生），无法分享链接、无法 SEO、刷新即丢状态。

**③ 路由状态不可审查。** "当前用户处于哪个页面、从哪来"这个问题，命令式路由没有统一答案。埋点、权限拦截、退出登录清栈，全都得在各个 push 调用点各写一遍。

对照前端：这就像在 React 里不用 React Router，全部手写 `window.history.pushState` + 自己维护组件切换——能跑，但没有任何工程保障。声明式路由（React Router v6 的 `<Route>` 配置、vue-router 的 `routes` 表）之所以成为标准，正是因为**路由配置应该是一份可声明的数据，而不是散落在代码里的命令序列**。

Flutter 官方给出的答案就是 go_router。下面进入正题。

## 3. go_router：声明式路由（企业首选）

### 3.1 为什么声明式更好（对照 React Router v6）

go_router 的核心思想：**你声明一张"URL → 页面"的映射表，框架负责把当前 URL 解析成 Widget 树**。路由即状态（URL is the state），UI 是 URL 的函数。

这和 React Router v6 的思路完全同构：

| 概念 | React Router v6 | go_router |
|---|---|---|
| 路由配置 | `<Route path element>` JSX 树 | `GoRoute(path, builder)` 列表 |
| 路由实例 | `<BrowserRouter>` | `GoRouter` + `MaterialApp.router` |
| 声明式出口 | `<Outlet />` | `ShellRoute` 的 `navigator` / 子路由 |
| 路由守卫 | `loader` / 自定义 `<RequireAuth>` | `redirect` 回调 |
| 编程跳转 | `useNavigate()` | `context.push / go` |

声明式带来的工程收益：

- **可预测**：任何一个 URL，你对着路由表就能说出会渲染什么——code review 时路由表就是审查清单；
- **深链免费**：URL → Widget 的映射是框架核心功能，iOS/Android/Web 统一；
- **可测试**：路由表是纯数据，单测里直接构造 GoRouter 断言解析结果。

### 3.2 完整接入步骤

第一步，添加依赖（版本以 pub.dev 为准）：

```yaml
# pubspec.yaml
dependencies:
  flutter:
    sdk: flutter
  go_router: ^18.1.4   # 2026-11 当前版本；v18 起要求 Flutter 3.44 / Dart 3.12+
```

> **版本提醒（v15 → v18 的四处变化，升级老项目必看）**
>
> 1. **v15 起 URL 区分大小写**：`/Home` ≠ `/home`，`GoRouter` 新增 `caseSensitive` 参数（默认 `true`）。老项目里大小写混用的路径会 404。
> 2. **v16 起类型安全路由成熟**：`go_router_builder`（≥3.0）生成 `GoRouteData` 子类，用 `.go(context)` / `.location` 代替手写字符串，改路由时编译期就报错——大项目强烈建议上，见 3.6 节。
> 3. **v17 起 `ShellRoute` 的导航变化默认会通知根 `GoRouter` 的 observers**，新增 `notifyRootObserver` 参数。如果你做过"底部 Tab 切换不上报埋点"的定制，升级后要重设。
> 4. **v18 起依赖 `material_ui` / `cupertino_ui` 独立包**（SDK 基线 Flutter 3.44 / Dart 3.12），与 [04 篇 4.1](04-Widget与布局.md) 讲的是同一件事。

第二步，创建路由配置，用 `MaterialApp.router` 接管：

```dart
// lib/core/router/app_router.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

import '../../features/auth/pages/login_page.dart';
import '../../features/home/pages/home_page.dart';
import '../../features/order/pages/order_detail_page.dart';

/// 全局唯一的 GoRouter 实例。
/// 企业项目建议：路由表集中在一个文件，路由路径用常量类管理（见第 9 节）。
final GoRouter appRouter = GoRouter(
  // 初始路由：App 冷启动时解析的 URL
  initialLocation: '/',

  // 路由表：一张数据，描述"URL → 页面"
  routes: [
    GoRoute(
      path: '/',
      name: 'home',
      builder: (context, state) => const HomePage(),
    ),
    GoRoute(
      path: '/login',
      name: 'login',
      builder: (context, state) => const LoginPage(),
    ),
    GoRoute(
      path: '/order/:id', // :id 是路径参数，类似 vue-router 的动态路由
      name: 'orderDetail',
      builder: (context, state) {
        // pathParams 是强类型 Map<String, String>，比 1.0 的 arguments 安全
        final orderId = state.pathParameters['id']!;
        return OrderDetailPage(orderId: orderId);
      },
    ),
  ],

  // 路由观察者：所有跳转都会经过这里，埋点入口（见第 9 节）
  observers: [AppRouteObserver()],

  // 全局重定向：登录守卫（见第 5 节）
  redirect: _guard,
);

/// 简化的守卫：未登录且目标不是 /login 时，强制去登录页
String? _guard(BuildContext context, GoRouterState state) {
  final loggedIn = AuthSession.instance.isLoggedIn; // 假设的会话单例
  final goingToLogin = state.matchedLocation == '/login';
  if (!loggedIn && !goingToLogin) {
    return '/login';
  }
  return null; // null 表示放行
}

/// 路由观察者：自动埋点的标准挂载点
class AppRouteObserver extends NavigatorObserver {
  @override
  void didPush(Route<dynamic> route, Route<dynamic>? previousRoute) {
    // 这里上报 PV 埋点；更完整的方案见《11-企业级通用能力》
    debugPrint('路由进入: ${route.settings.name}');
  }
}

/// 假设的会话持有者，第 5 节会给出完整实现
class AuthSession {
  AuthSession._();
  static final AuthSession instance = AuthSession._();
  bool isLoggedIn = false;
}
```

第三步，`MaterialApp` 换成 `MaterialApp.router`：

```dart
// lib/main.dart
import 'package:flutter/material.dart';
import 'core/router/app_router.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    // 关键：MaterialApp.router + routerConfig，把导航权交给 GoRouter
    return MaterialApp.router(
      routerConfig: appRouter,
      title: 'Enterprise App',
      theme: ThemeData(primarySwatch: Colors.blue),
    );
  }
}
```

用了 `MaterialApp.router` 之后，**不要再调用 `Navigator.push`**——两套路由系统混用会导致栈状态错乱，这是企业项目中最常见的接入事故。

### 3.3 路由传参：path 参数、query 参数、extra

go_router 的传参有三条通道，各有用途：

```dart
// ① path 参数：URL 的一部分，可分享、可深链，永远是 String
// 路由表声明 /order/:id
context.push('/order/A001');
// 页面内取：state.pathParameters['id'] → 'A001'

// ② query 参数：可选过滤条件，适合列表页筛选状态
context.push('/orders?status=paid&page=2');
// 页面内取：state.uri.queryParameters['status'] → 'paid'

// ③ extra：任意 Dart 对象，不进 URL，只在内存里传递
context.push('/order/A001', extra: orderModel);
// 页面内取：state.extra as OrderModel
```

选型建议（直接给结论）：

- **能进 URL 的尽量进 URL**（path + query）：可分享、可深链、Web 端刷新不丢；
- **extra 只用于"同一会话内传递的复杂对象"**：比如把列表页已请求到的 model 直接传给详情页省一次请求。注意 Web 端刷新后 extra 会变成 null——**页面必须能只靠 path 参数自洽**，extra 只做加速，不做唯一数据源。这是很多团队踩过的坑。

### 3.4 push / go / pushNamed：三个跳转方法的区别

```dart
// push：压栈，保留当前页面，可返回。对应"详情页""编辑页"等需要回退的场景
context.push('/order/A001');

// go：清栈直达，不留回退路径。对应登录成功、退出登录、Tab 切换
context.go('/home');

// pushNamed：按名字跳转，路径重构时不改调用方代码
context.pushNamed('orderDetail', pathParameters: {'id': 'A001'});

// pop / maybePop：返回；maybePop 在栈底时会返回 false 而不是崩溃
context.pop();
if (context.canPop()) context.pop();
```

使用场景对照表：

| 方法 | 栈行为 | 典型场景 |
|---|---|---|
| `push` | 压栈 | 列表 → 详情、打开编辑页 |
| `go` | 清栈替换 | 登录成功进主页、退出登录、Tab 间切换 |
| `pushNamed` | 压栈（按名） | 团队约定用名字解耦路径字符串 |
| `pop` | 弹栈 | 返回上一页、关闭弹层 |

命名路由 vs 直接路径：小团队直接写路径字符串更快；**中大型团队建议统一用 `name`**——路径重构（比如 `/order/:id` 改成 `/orders/:id`）时只改路由表，调用点零改动。配合路由常量类（第 9 节）效果最好。

### 3.5 push 拿返回值

go_router 保留了 1.0 的"页面间函数调用"能力：

```dart
// 发起方：泛型声明期望的返回类型
final picked = await context.push<String>('/city-picker');
if (picked != null) {
  // 用户确认返回
}

// 接收方：pop 时带返回值
context.pop('深圳市');
```

### 3.6 类型安全路由：把字符串换成编译期校验

手写 `'/order/:id'` 有三个长期痛点：改了路径常量忘了改跳转、参数名拼错到运行时才炸、取值全靠 `state.pathParameters['id']!` 强转。go_router 自 v16 起把 type-safe routing 补齐，企业大项目建议直接上：

```yaml
dependencies:
  go_router: ^18.1.4
  go_router_builder: ^4.0.0   # 需 ≥3.0 且与 go_router 大版本匹配，具体版本以 pub.dev 为准
dev_dependencies:
  build_runner: ^2.4.0
```

```dart
// lib/core/router/routes.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

import '../../features/home/pages/home_page.dart';
import '../../features/order/pages/order_detail_page.dart';

part 'routes.g.dart';   // build_runner 生成

@TypedGoRoute<HomeRoute>(path: '/')
class HomeRoute extends GoRouteData with _$HomeRoute {
  const HomeRoute();

  @override
  Widget build(BuildContext context, GoRouterState state) => const HomePage();
}

@TypedGoRoute<OrderDetailRoute>(path: 'orders/:id')
class OrderDetailRoute extends GoRouteData with _$OrderDetailRoute {
  const OrderDetailRoute({required this.id, this.tab});

  final String id;
  final String? tab;   // 未出现在 path 里的字段自动映射为 query 参数

  @override
  Widget build(BuildContext context, GoRouterState state) =>
      OrderDetailPage(orderId: id, initialTab: tab);
}
```

```dart
// 使用：参数类型、必填性都由编译器把关
const OrderDetailRoute(id: 'A1001', tab: 'log').go(context);
const OrderDetailRoute(id: 'A1001').push(context);

final location = const OrderDetailRoute(id: 'A1001').location; // '/orders/A1001'
```

生成入口是 `$appRoutes`，直接 `GoRouter(routes: $appRoutes)`。**什么时候值得上**：路由超过 15 条、多人协作、或需要 Web 分享链接时收益明显；三条路由的小项目手写也完全可以。注意路径依旧大小写敏感（v15 起）。

## 4. 重定向与路由守卫：完整的登录拦截

### 4.1 redirect 的工作机制

`redirect` 是 GoRouter 在**每次路由解析时**都会调用的回调：返回 `null` 放行，返回一个路径字符串则改跳该路径。它和 vue-router 的 `router.beforeEach` 定位完全一致——一个集中的、全局的导航拦截点。

关键差异：vue-router 的守卫是命令式的 `next()` 风格，go_router 的 `redirect` 是**纯函数**——输入当前状态，输出目标路由，无副作用。这让守卫逻辑可以单测。

### 4.2 完整实现：未登录跳登录页 + 登录后回跳

需求（企业标配）：

1. 未登录访问任何受保护页面 → 跳登录页，且记录原目标；
2. 登录成功 → 回到原目标页面；
3. 已登录访问 `/login` → 直接进主页（防止登录页残留）；
4. token 失效（401）任意时刻发生 → 清栈回登录页。

```dart
// lib/core/router/app_router.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

import '../../features/auth/controllers/auth_controller.dart';

final GoRouter appRouter = GoRouter(
  initialLocation: '/',
  routes: [
    GoRoute(
      path: '/login',
      name: RouteNames.login,
      builder: (context, state) => const LoginPage(),
    ),
    GoRoute(
      path: '/home',
      name: RouteNames.home,
      builder: (context, state) => const HomePage(),
    ),
    // ...其余路由
  ],
  redirect: _authGuard,
);

/// 登录守卫：对照 vue-router 的 router.beforeEach((to, from) => {...})
String? _authGuard(BuildContext context, GoRouterState state) {
  final auth = AuthController.instance;
  final loggedIn = auth.isLoggedIn;
  final loggingIn = state.matchedLocation == '/login';

  // 情况 1：未登录，且目标不是登录页 → 携带原始路径去登录页
  if (!loggedIn && !loggingIn) {
    final from = state.matchedLocation;
    return '/login?from=$from'; // 用 query 参数记住"来处"
  }

  // 情况 2：已登录，却访问登录页 → 直接进主页
  if (loggedIn && loggingIn) {
    return '/home';
  }

  // 其余情况放行
  return null;
}
```

```dart
// lib/features/auth/pages/login_page.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

import '../controllers/auth_controller.dart';

class LoginPage extends StatefulWidget {
  const LoginPage({super.key});

  @override
  State<LoginPage> createState() => _LoginPageState();
}

class _LoginPageState extends State<LoginPage> {
  final _usernameCtrl = TextEditingController();
  final _passwordCtrl = TextEditingController();
  bool _submitting = false;

  Future<void> _submit() async {
    // 边界情况 1：参数校验先挡一层，别把垃圾请求发给后端
    final username = _usernameCtrl.text.trim();
    final password = _passwordCtrl.text;
    if (username.isEmpty || password.length < 6) {
      if (mounted) {
        ScaffoldMessenger.of(context).showSnackBar(
          const SnackBar(content: Text('用户名不能为空，密码至少 6 位')),
        );
      }
      return;
    }

    setState(() => _submitting = true);
    try {
      await AuthController.instance.login(username, password);
      if (!mounted) return;

      // 登录成功：读取守卫带来的 from 参数，回跳原页面
      final from = GoRouterState.of(context).uri.queryParameters['from'];
      // 边界情况 2：from 可能被恶意构造为外部地址或空值，这里只允许站内路径
      final target = (from != null && from.startsWith('/') && from != '/login')
          ? from
          : '/home';
      // 用 go 清栈：登录成功后不应该能"返回"回登录页
      context.go(target);
    } catch (e) {
      if (mounted) {
        ScaffoldMessenger.of(context)
            .showSnackBar(SnackBar(content: Text('登录失败：$e')));
      }
    } finally {
      if (mounted) setState(() => _submitting = false);
    }
  }

  @override
  void dispose() {
    _usernameCtrl.dispose();
    _passwordCtrl.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('登录')),
      body: Padding(
        padding: const EdgeInsets.all(24),
        child: Column(
          children: [
            TextField(
              controller: _usernameCtrl,
              decoration: const InputDecoration(labelText: '用户名'),
            ),
            const SizedBox(height: 16),
            TextField(
              controller: _passwordCtrl,
              obscureText: true,
              decoration: const InputDecoration(labelText: '密码'),
            ),
            const SizedBox(height: 24),
            FilledButton(
              onPressed: _submitting ? null : _submit,
              child: Text(_submitting ? '登录中...' : '登录'),
            ),
          ],
        ),
      ),
    );
  }
}
```

### 4.3 登录态失效：任意时刻 401 的处理

`redirect` 只在**路由跳转时**触发。如果用户停在页面上，此时 token 过期、接口返回 401，需要主动通知路由清栈。做法：在 AuthController 里持有 router 引用（或通过全局 key），登出时调用 `go()`：

```dart
// lib/features/auth/controllers/auth_controller.dart
import 'package:go_router/go_router.dart';

import '../../core/router/app_router.dart';

class AuthController {
  AuthController._();
  static final AuthController instance = AuthController._();

  String? _token;
  bool get isLoggedIn => _token != null;

  Future<void> login(String username, String password) async {
    // 实际项目：dio 请求后端，持久化 token（见《06-状态管理》AuthNotifier 完整版）
    _token = 'mock-token';
  }

  /// 任意位置可调用：token 失效时清栈回登录页
  void logout() {
    _token = null;
    // go 会清空整个路由栈并触发 redirect 守卫 → 落到 /login
    appRouter.go('/login');
  }
}
```

网络层统一拦截 401 后调用 `AuthController.instance.logout()` 即可——路由守卫会自动接管后续跳转。这种"守卫管跳转时机、控制器管状态"的分工，就是第 8 节"路由与状态的边界"的一次实战预演。

## 5. ShellRoute：底部导航 + 每 Tab 独立栈

### 5.1 需求与难点

企业 App 标配：底部 4~5 个 Tab（首页/订单/消息/我的），要求：

1. 每个 Tab 内部有自己的导航栈：在"订单"Tab 进了 3 层详情，切到"首页"再切回来，订单栈还在；
2. URL 可表达：`/home/orders/A001` 能直接打开"订单 Tab 的详情页"（深链场景）；
3. 底部导航栏不参与页面转场。

用 Navigator 1.0 + `IndexedStack` 手搓当然可以（老项目都这么干），但深链和 URL 同步要自己写。go_router 的 `StatefulShellRoute.indexedStack` 就是官方解决方案——对照 Web 前端，它相当于 React Router v6 的嵌套 `<Route>` + `<Outlet>` 布局路由，外加每个分支保留独立状态的强化版。

### 5.2 完整实现

```dart
// lib/core/router/app_router.dart（节选：替换第 3 节的 routes）
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

import '../../features/home/pages/home_page.dart';
import '../../features/order/pages/order_list_page.dart';
import '../../features/order/pages/order_detail_page.dart';
import '../../features/message/pages/message_page.dart';
import '../../features/profile/pages/profile_page.dart';
import 'root_scaffold.dart';

final GoRouter appRouter = GoRouter(
  initialLocation: '/home',
  routes: [
    GoRoute(
      path: '/login',
      name: 'login',
      builder: (context, state) => const LoginPage(),
    ),

    // StatefulShellRoute：外壳（底部导航）+ 多个并行分支（每个 Tab 一个栈）
    StatefulShellRoute.indexedStack(
      builder: (context, state, navigationShell) {
        // navigationShell 是分支切换器；外壳只 build 一次，切 Tab 不重建
        return RootScaffold(navigationShell: navigationShell);
      },
      branches: [
        // 分支 1：首页 Tab。每个 branch 是一份独立的路由表 + 独立栈
        StatefulShellBranch(
          routes: [
            GoRoute(
              path: '/home',
              name: 'home',
              builder: (context, state) => const HomePage(),
            ),
          ],
        ),
        // 分支 2：订单 Tab，有自己的嵌套路由
        StatefulShellBranch(
          routes: [
            GoRoute(
              path: '/orders',
              name: 'orderList',
              builder: (context, state) => const OrderListPage(),
              routes: [
                // 嵌套子路由：完整路径是 /orders/:id
                GoRoute(
                  path: ':id',
                  name: 'orderDetail',
                  builder: (context, state) =>
                      OrderDetailPage(id: state.pathParameters['id']!),
                ),
              ],
            ),
          ],
        ),
        // 分支 3：消息 Tab
        StatefulShellBranch(
          routes: [
            GoRoute(
              path: '/messages',
              name: 'messages',
              builder: (context, state) => const MessagePage(),
            ),
          ],
        ),
        // 分支 4：我的 Tab
        StatefulShellBranch(
          routes: [
            GoRoute(
              path: '/profile',
              name: 'profile',
              builder: (context, state) => const ProfilePage(),
            ),
          ],
        ),
      ],
    ),
  ],
);
```

```dart
// lib/core/router/root_scaffold.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

/// 底部导航外壳：只负责画 TabBar 和分发分支切换
class RootScaffold extends StatelessWidget {
  const RootScaffold({super.key, required this.navigationShell});

  final StatefulNavigationShell navigationShell;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: navigationShell, // 当前分支的导航栈在这里渲染，类似 <Outlet />
      bottomNavigationBar: BottomNavigationBar(
        type: BottomNavigationBarType.fixed,
        currentIndex: navigationShell.currentIndex,
        onTap: (index) {
          // goBranch：切到第 index 个分支。
          // initialLocation: true 表示"重复点击 Tab 回到该 Tab 首页"（抖音式），
          // 传 false 则保留该 Tab 的内部栈
          navigationShell.goBranch(
            index,
            initialLocation: index == navigationShell.currentIndex,
          );
        },
        items: const [
          BottomNavigationBarItem(icon: Icon(Icons.home), label: '首页'),
          BottomNavigationBarItem(icon: Icon(Icons.receipt), label: '订单'),
          BottomNavigationBarItem(icon: Icon(Icons.message), label: '消息'),
          BottomNavigationBarItem(icon: Icon(Icons.person), label: '我的'),
        ],
      ),
    );
  }
}
```

要点说明：

- **每 Tab 独立栈**由 `StatefulShellRoute.indexedStack` 保证：内部用 IndexedStack 保持各分支的 Navigator 状态，切 Tab 不销毁；
- **URL 与 Tab 对齐**：`/orders/A001` 自动激活订单分支并压入详情页——深链直接可用；
- **嵌套子路由**（`/orders` 下的 `:id`）：父页面不会自动渲染子页面（这点和 Web 嵌套路由不同），子路由是压在该分支栈上的新页面；如果需要"父页面内嵌子视图"（Web 式嵌套），用 `ShellRoute` 或 `Page` 自定义，具体以 go_router 文档为准。

### 5.3 页面转场动画定制

企业 App 通常要统一转场规范（比如 iOS 风格右滑、Android 底部弹出）。go_router 通过 `pageBuilder` 定制：

```dart
// lib/core/router/app_router.dart（节选）
GoRoute(
  path: '/orders',
  pageBuilder: (context, state) {
    // NoTransitionPage：无转场，常用于 Shell 内部或 Tab 切换
    return NoTransitionPage(
      key: state.pageKey,
      child: const OrderListPage(),
    );
  },
  routes: [
    GoRoute(
      path: ':id',
      pageBuilder: (context, state) {
        // CustomTransitionPage：完全自定义转场
        return CustomTransitionPage(
          key: state.pageKey,
          child: OrderDetailPage(id: state.pathParameters['id']!),
          // transitionDuration 控制时长，反向时长用 reverseTransitionDuration
          transitionDuration: const Duration(milliseconds: 250),
          transitionsBuilder: (context, animation, secondaryAnimation, child) {
            // 组合：轻微上移 + 淡入
            final curved =
                CurvedAnimation(parent: animation, curve: Curves.easeOutCubic);
            return SlideTransition(
              position: Tween<Offset>(
                begin: const Offset(0, 0.04),
                end: Offset.zero,
              ).animate(curved),
              child: FadeTransition(opacity: curved, child: child),
            );
          },
        );
      },
    ),
  ],
),
```

全局默认转场：给 `GoRouter` 传 `pageBuilder` 之外的方案是在每个 route 上写，比较繁琐；社区做法是封装一个 `AppPage.build(state, child, transition)` 工厂函数统一产出 `CustomTransitionPage`，团队所有路由必须经过它——规范靠约定，也可靠 lint（见《11-企业级通用能力》）。

## 6. 深链 DeepLink / App Links 基础

### 6.1 概念：三种"从外部打开 App"的方式

| 方式 | 形态 | 平台 | 特点 |
|---|---|---|---|
| URL Scheme | `myapp://order/A001` | iOS/Android | 配置最简单；缺点是**不校验归属**，任何 App 都能注册同一个 scheme，且浏览器里输入 scheme 没有兜底 |
| Universal Links (iOS) | `https://app.example.com/order/A001` | iOS 9+ | 走 HTTPS 域名，系统校验域名与 App 的关联（apple-app-site-association 文件），安全 |
| App Links (Android) | `https://app.example.com/order/A001` | Android 6+ | 同上，通过 assetlinks.json 校验（官方名称 Android App Links） |

企业建议：**URL Scheme 只做开发调试，生产环境必须上 Universal Links / App Links**——否则你的 scheme 可能被竞品抢注，用户点广告直接进了别人的 App。

### 6.2 配置要点

**Android**（`android/app/src/main/AndroidManifest.xml`）：

```xml
<!-- URL Scheme 方式（调试用） -->
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="myapp" />
</intent-filter>

<!-- App Links 方式（生产）：声明 HTTPS 域名 -->
<intent-filter android:autoVerify="true">
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="https" android:host="app.example.com" />
</intent-filter>
```

同时在 `https://app.example.com/.well-known/assetlinks.json` 部署签名关联文件（内容为 App 的 SHA256 指纹 + 包名，用 Android Studio 的 App Links Assistant 生成）。

**iOS**：Xcode → Targets → Signing & Capabilities → 添加 Associated Domains，填 `applinks:app.example.com`；并在该域名 `/.well-known/apple-app-site-association` 部署关联 JSON（含 teamID + bundleID）。

go_router 侧不用额外写代码：App 收到链接后，Flutter 引擎把 URL 交给 GoRouter 解析，命中路由表即完成跳转。**前提是你的路由表已经用完整路径建模**——这也是第 3 节"能进 URL 的尽量进 URL"的原因。

### 6.3 测试方法

```bash
# Android：adb 模拟深链（URL Scheme）
adb shell am start -a android.intent.action.VIEW \
  -d "myapp://order/A001"

# Android：App Links 调试，先验证系统是否已关联域名
adb shell pm get-app-links com.example.app

# iOS 模拟器（Xcode 附带工具）
xcrun simctl openurl booted "https://app.example.com/order/A001"
```

Web 端测试最简单：直接改地址栏 URL，GoRouter 实时响应——这也是声明式路由的红利。

企业落地建议：深链路径要纳入路由表评审，**新增路由时同步检查深链可达性**；推送/短信营销链接统一走一个短链服务再 302 到 App Links，别在各业务里手拼 URL。

## 7. 路由与状态管理的边界

这是企业项目里最容易出现"架构腐烂"的决策点。先给结论表：

| 数据 | 放哪里 | 理由 |
|---|---|---|
| 订单 ID、Tab index、筛选条件 | 路由参数（path/query） | 需要可分享、可深链、刷新不丢 |
| 登录态、用户信息、token | 全局状态（Riverpod/Provider） | 全局唯一、需响应式刷新、持久化 |
| 表单草稿、输入框内容 | 页面内状态（setState/控制器） | 生命周期跟页面走，页面销毁即丢 |
| 主题、语言 | 全局状态 + 持久化 | 全局生效，跨会话保留 |
| "登录后回跳地址" | 路由 query（from 参数） | 见第 4 节，随导航流转 |

判断口诀：**这个状态需不需要出现在 URL 里？需要 → 路由参数；全局只读/多页共享 → 全局状态；只在这一页活 → 页面状态。**

反面案例：把订单详情对象塞进全局单例 `OrderStore.currentOrder` 再跳页——用户直接深链进来时 `currentOrder` 是 null，页面白屏。正确做法：路由只带 `orderId`，详情页自己（或通过 Riverpod family）按 id 取数。

路由与状态的联动（登录态变化自动重定向）在《06-状态管理》的 AuthNotifier 示例中会完整实现——go_router 的 `refreshListenable` 挂接 Riverpod 状态，是两者协作的标准姿势。

## 8. 企业实践建议

### 8.1 集中式路由表 + 路由常量类

路由字符串散落各处是重构地狱。规范做法：**路径常量 + 名称常量集中在一个文件，路由表单独一个文件，按 feature 拆分 builder**。

```dart
// lib/core/router/route_names.dart

/// 路由常量类：所有路径与名称的唯一出处（Single Source of Truth）
/// 禁止在业务代码里硬编码 '/orders/...' 字符串，code review 卡死
abstract final class AppRoutes {
  static const login = '/login';
  static const home = '/home';
  static const orderList = '/orders';
  // 拼接 path 参数的辅助方法：调用方不用手写字符串模板
  static String orderDetail(String id) => '/orders/$id';
  static const messages = '/messages';
  static const profile = '/profile';
}
```

```dart
// lib/core/router/app_router.dart（使用常量后的路由表节选）
routes: [
  GoRoute(
    path: AppRoutes.login,
    name: 'login',
    builder: (context, state) => const LoginPage(),
  ),
  StatefulShellRoute.indexedStack(
    /* ... 第 5 节的完整配置，路径全部引用 AppRoutes ... */
  ),
],
```

### 8.2 路由观察者：埋点入口

所有页面 PV 都该在统一出口上报。`NavigatorObserver` 是挂载点：

```dart
// lib/core/router/app_route_observer.dart
import 'package:flutter/material.dart';

import '../analytics/analytics_service.dart';

/// 全局路由观察者：PV 埋点的唯一出口。
/// 注意 ShellRoute 的分支内部导航也会触发 didPush/didPop。
class AppRouteObserver extends NavigatorObserver {
  @override
  void didPush(Route<dynamic> route, Route<dynamic>? previousRoute) {
    if (route.settings.name != null) {
      AnalyticsService.instance.track('page_view', {
        'page': route.settings.name,
        'from': previousRoute?.settings.name,
      });
    }
  }

  @override
  void didPop(Route<dynamic> route, Route<dynamic>? previousRoute) {
    if (route.settings.name != null) {
      AnalyticsService.instance.track('page_exit', {
        'page': route.settings.name,
      });
    }
  }
}
```

提醒：go_router 下 `route.settings.name` 的取值行为和 1.0 命名路由不完全一样（取决于版本与是否设置 `name`），上报前先在真机验证一遍实际值；埋点体系的完整设计（含曝光、点击、公共属性）见《11-企业级通用能力》。

### 8.3 checklist：路由模块的团队规范

- [ ] `MaterialApp.router` 全局唯一，禁止混用 `Navigator.push`
- [ ] 所有路径进 `AppRoutes` 常量类，PR 里出现裸字符串直接打回
- [ ] 受保护路由靠 `redirect` 统一拦截，禁止在每个页面 `initState` 里手写登录检查
- [ ] 页面必须能仅靠 path/query 参数完成渲染，`extra` 只做优化
- [ ] 转场动画经统一工厂函数产出，禁止各页面随手 `CustomTransitionPage`
- [ ] 新增路由同步验证：Web 地址栏直达、深链、未登录重定向三链路
