# 真机调试指南（Android / iOS · Windows / macOS）

> 本篇目标：把"在电脑上点一下就能跑"变成"插上手机就能调"。覆盖 Android 与 iOS 双端连接、热重载、断点调试、无线调试、日志与 DevTools、局域网联调，以及国产 ROM 与 Xcode 签名上那些让人卡半天的坑。
>
> 前置阅读：[03 - Flutter 工程入门](../tutorial_01/03-Flutter工程入门.md)（了解 `flutter run` 即可）、[14 - 工程化与发布](../tutorial_01/14-工程化与发布.md)（环境变量与打包）。
>
> 用例工程：`project/scjh_app`（本仓库内的企业 App 骨架）。

---

## 一、先搞清楚：Flutter 为什么没有"基座"

如果你从 uni-app 过来，最不习惯的一点是：**Flutter 没有标准基座 / 自定义基座这套东西**。

这源于两者根本不同的运行模型：

|          | uni-app                                | Flutter                        |
| -------- | -------------------------------------- | ------------------------------ |
| 业务代码在哪   | 打包进 App 的 JS 资源，运行时由 JSCore/WebView 加载 | 编译期 AOT 编译成 `libapp.so`，直接是机器码 |
| 改代码怎么生效  | 替换 JS 资源包                              | 重新编译并安装 APK                    |
| 原生插件怎么进包 | 必须重打**自定义基座**                          | 编进 APK 即可，无需额外配置               |
| 首次运行成本   | 下载/安装基座                                | 编译（Gradle）+ 安装                 |

所以 Flutter 的"真机调试"其实就是一句话：

> `flutter run` —— 编译 → 安装 → 建立 Dart VM Service 连接 → 开始热重载。

没有基座，没有云打包，不需要因为"加了原生插件"而重新配置任何东西。

## 二、设备连接：Android 与 iOS

### 2.1 Android · 手机端准备

1. **开启开发者选项**：设置 → 关于手机 → 连点「版本号」7 次
2. **打开 USB 调试**：设置 → 系统 → 开发者选项 → USB 调试
3. **USB 连接模式改成「传输文件 / MTP」**  
   选「仅充电」时，很多机型不会暴露 ADB 接口，表现为电脑完全看不到设备。

### 2.2 Android · 国产 ROM 的额外开关（最常见的卡点）

各家 ROM 在标准开关之外又加了一层保护，不打开就永远停在 `unauthorized` 或安装失败：

| 品牌                        | 额外的开关                                     | 典型报错                             |
| ------------------------- | ----------------------------------------- | -------------------------------- |
| 小米 / Redmi                | 「USB 安装」、「USB 调试（安全设置）」，部分系统还需关闭「MIUI 优化」 | `INSTALL_FAILED_USER_RESTRICTED` |
| 华为 / 荣耀                   | 「仅充电模式下允许 ADB 调试」                         | `unauthorized`                   |
| OPPO / vivo / 一加 / realme | 「USB 调试（安全设置）」**需要登录账号**才能开启              | `INSTALL_FAILED_USER_RESTRICTED` |
| 三星 / Pixel / 原生           | 无需额外设置                                    | —                                |

### 2.3 Android · 电脑端验证

```bash
adb devices
# List of devices attached
# 3A21FDH2001234        device        ← 状态必须是 device
```

三种状态的含义：

| 状态             | 含义      | 处理                                            |
| -------------- | ------- | --------------------------------------------- |
| `device`       | 正常，可以调试 | —                                             |
| `unauthorized` | 手机没确认授权 | 看手机屏幕弹窗，勾「一律允许」；没弹窗就拔插一次                      |
| `offline`      | 连接异常    | `adb kill-server && adb start-server`，再不行换线换口 |

> Windows 上如果 `adb` 命令不存在：它通常在 `%LOCALAPPDATA%\Android\Sdk\platform-tools\`，把该目录加进 PATH，或用完整路径调用。

再确认 Flutter 也能看到设备：

```bash
flutter devices
```

### 2.4 Android · 跑起来

```bash
cd project/scjh_app

flutter run                 # 只连一台设备时直接跑
flutter run -d <device-id>  # 多台设备时指定
```

首次运行会比较慢（Gradle 要下载依赖、编译引擎产物），耐心等；之后增量运行通常在 20 秒到 2 分钟之间。

### 2.5 iOS · 为什么必须有 Mac

`xcodebuild`、`codesign`、iOS SDK 只存在于 macOS。云端 Mac 能构建，但调试体验很差——看不到设备日志、断点要远程连。家里有 Mac 就直接本地跑，那是唯一顺畅的路径。

一次性把工具链装齐：

```bash
xcode-select --install                    # 命令行工具
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -license accept
brew install cocoapods                    # Flutter 的 iOS 依赖走 CocoaPods

flutter doctor -v                         # Xcode 与 CocoaPods 两项都要打勾
```

> Apple Silicon 机器上如果 `pod install` 报 ffi 相关错误：
> `sudo gem install ffi -- --enable-libffi-alloc`，或直接用 `brew install cocoapods` 装的版本。

### 2.6 iOS · 签名配置（免费 Apple ID 够用）

1. 用 Xcode 打开 **`ios/Runner.xcworkspace`**（是 `.xcworkspace`，不是 `.xcodeproj`）
2. 左侧选中 `Runner` → `Signing & Capabilities`
3. `Team` 选你的 Apple ID；没有就去 Xcode → Settings → Accounts 添加，**免费账号即可**
4. `Bundle Identifier` 改成全局唯一的，例如 `com.zsp.enterprise.scjhapp`
   —— 免费账号最容易撞 ID，报 `Failed to register bundle identifier` 就是它
5. 勾上 `Automatically manage signing`

免费账号的限制，提前知道免得白折腾：

| 限制 | 说明 |
|---|---|
| 证书 7 天过期 | 到期后重新 `flutter run` 会自动重签，但每次都得连 Mac |
| 最多 3 台设备 | 一个自然年内 |
| 不支持推送 | APNs 需要付费开发者账号（$99/年） |
| 不能上架 | 仅限真机自用 |

真要做推送、要上架，再考虑花这 $99。学习阶段完全不必。

### 2.7 iOS · 手机端准备与运行

1. **iOS 16+ 必须打开开发者模式**：设置 → 隐私与安全性 → 开发者模式 → 打开 → **重启手机**
   （这个开关不打开，`flutter devices` 永远看不到设备，而且没有任何提示）
2. 首次插线时手机点「信任此电脑」
3. 首次安装后如果提示"不受信任的开发者"，去 设置 → 通用 → VPN与设备管理 → 信任你的证书

```bash
flutter devices
flutter run -d <ios-device-id>
```

第一次会跑 `pod install` 再编译 iOS 端，比 Android 更慢（5–10 分钟），之后增量正常。

### 2.8 iOS · 常见报错

| 报错 | 原因 | 处理 |
|---|---|---|
| `CocoaPods not installed` | 没装 pod | `brew install cocoapods` |
| `Signing for "Runner" requires a development team` | 没选 Team | 见 2.6 |
| `Failed to register bundle identifier` | Bundle ID 被占用 | 换一个更独特的 |
| `Unable to install "Runner"` | 证书未信任 | 设置 → 通用 → VPN与设备管理 |
| `No such module 'xxx'` | pod 缓存脏 | `cd ios && pod repo update && pod install` |
| 设备列表里看不到 iPhone | 开发者模式没开 | iOS 16+ 见 2.7 第 1 步 |
| 启动后白屏、日志无输出 | 证书过期 | 重跑 `flutter run` 自动重签 |

### 2.9 顺带：macOS 桌面端调试

有 Mac 的话，桌面端是最快的调试环境——启动比模拟器快，热重载一样生效，还不用插线。日常调 UI 布局时非常舒服。

```bash
flutter config --enable-macos-desktop
cd project/scjh_app
flutter create --platforms=macos .      # 只补 macos/ 目录，不动现有代码
flutter run -d macos
```

> `flutter create --platforms=macos .` 只会生成缺失的平台目录，已有的 `lib/`、`android/`、`ios/` 不会被覆盖。

**这里有个必踩的坑**：macOS 应用默认开启 App Sandbox，网络请求会直接失败（表现为接口超时或 `Operation not permitted`）。需要在两个 entitlements 文件里放开：

```xml
<!-- macos/Runner/DebugProfile.entitlements 和 Release.entitlements 都要加 -->
<key>com.apple.security.network.client</key>
<true/>
```

调试阶段两个文件都改。只改 Debug 的话，打 release 包时接口会全部失败——这个 bug 只在最后打包才暴露，很难查。

## 三、热重载与热重启

`flutter run` 跑起来之后，终端会进入交互模式：

| 按键  | 作用                           | 什么时候用                         |
| --- | ---------------------------- | ----------------------------- |
| `r` | **热重载**：保留页面状态，只换代码          | 改 UI、改逻辑，期望保持当前页面状态           |
| `R` | **热重启**：重置所有状态，从头执行 `main()` | 改了 `main()`、全局单例、provider 初始值 |
| `v` | 打开 DevTools                  | 看性能、查 Widget 树                |
| `s` | 截取当前真机屏幕                     | 写文档、提 bug                     |
| `w` | 打印 Widget 树                  | 排查布局嵌套问题                      |
| `p` | 显示布局网格                       | 对齐调间距                         |
| `b` | 切换亮/暗主题                      | 验证深色模式                        |
| `h` | 列出全部命令                       | 忘了快捷键时                        |
| `q` | 退出并卸载 App                    | —                             |

热重载和 HBuilderX 的"保存即刷新"最大的区别：**热重载保留状态**。

举个实际场景：你在填一个长表单，想调按钮颜色。uni-app 刷新后表单清空，得重填；Flutter 按 `r`，颜色变了，表单内容还在。这个差异在开发后期会节省大量时间。

**什么时候必须热重启（`R`）甚至完全重跑：**

| 改动类型                                           | 需要              |
| ---------------------------------------------- | --------------- |
| 普通 Widget 结构、样式、逻辑                             | `r` 热重载         |
| `initState` 里的初始化逻辑、`main()`、全局变量              | `R` 热重启         |
| `pubspec.yaml` 里的依赖（新增/升级插件）                   | 完全重跑（会重新编译原生部分） |
| `android/` `ios/` 下的原生代码、`AndroidManifest.xml` | 完全重跑            |

## 四、断点调试

### 4.1 VS Code（推荐）

装 **Flutter** 扩展和 **Dart** 扩展，然后：

1. 左侧「运行和调试」→ 顶部选择一个已连接的设备
2. 按 `F5` 启动
3. 在 Dart 文件的行号左侧点一下，打红点断点
4. 命中断点后可以看：变量（LOCALS / WATCH）、调用栈（CALL STACK）、逐步执行（F10 单步跳过 / F11 单步进入）

断点在**热重载后会保留**，不需要重新打断点。

### 4.2 一份能直接用的 launch.json

在 `.vscode/launch.json` 里放多套配置，切换环境不用记命令行参数：

```jsonc
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "scjh_app · Mock",
      "request": "launch",
      "type": "dart",
      "program": "lib/main.dart",
      "args": ["--dart-define=USE_MOCK=true"]
    },
    {
      "name": "scjh_app · 本地后端",
      "request": "launch",
      "type": "dart",
      "program": "lib/main.dart",
      "args": [
        "--dart-define=USE_MOCK=false",
        "--dart-define=API_BASE_URL=http://192.168.1.100:8080/api/v1"
      ]
    },
    {
      "name": "scjh_app · Profile 性能分析",
      "request": "launch",
      "type": "dart",
      "program": "lib/main.dart",
      "profile": true
    }
  ]
}
```

### 4.3 Android Studio

直接点工具栏的绿色虫子图标（Debug）。优势是 DevTools 集成更顺，劣势是启动慢、吃内存。

## 五、无线调试（Android 11+）

插线调试最大的问题是手机一动就断。无线调试能解决，而且热重载照样可用。

**手机端**：开发者选项 → 无线调试 → 打开 → 「使用配对码配对设备」，会显示一组 `IP:端口` 和 6 位配对码。

**电脑端**：

```bash
# 1. 配对（端口是"配对"弹窗里那个，不是无线调试主界面的端口）
adb pair 192.168.1.23:37105
# 按提示输入 6 位配对码
# Successfully paired to 192.168.1.23:37105

# 2. 连接（端口是无线调试主界面显示的端口）
adb connect 192.168.1.23:5555

# 3. 确认
flutter devices
```

> 手机重启或切换网络后需要重新连接；配对信息会保留，但 `adb connect` 要重来一次。

## 六、日志与 DevTools

### 6.1 三种日志来源，各有用途

| 来源          | 命令 / 位置                                                | 能看到什么                        |
| ----------- | ------------------------------------------------------ | ---------------------------- |
| Dart 层      | `print()` / `debugPrint()` → 终端或 VS Code DEBUG CONSOLE | 业务日志、Dart 异常与堆栈              |
| Flutter 运行时 | `flutter logs`                                         | 应用日志流（含部分原生日志）               |
| 原生层         | `adb logcat`                                           | Android 崩溃堆栈、系统事件、第三方 SDK 日志 |

查 Android 端崩溃（比如接入了原生 SDK 后闪退），只能靠 `adb logcat`：

```bash
adb logcat -s flutter:V AndroidRuntime:E
```

### 6.2 DevTools 能做什么

`flutter run` 启动后会打印一个 DevTools 地址，或在终端按 `v` 直接打开。四个最常用的面板：

| 面板                   | 解决什么问题                                  |
| -------------------- | --------------------------------------- |
| **Widget Inspector** | 点击界面上的元素，直接跳到对应 Widget 的源码；排查"这个间距是哪来的" |
| **Performance**      | 帧时间线，找出掉帧的帧和对应耗时；`--profile` 模式下才有意义    |
| **Memory**           | 内存曲线、对象分配；排查页面反复进出后的泄漏                  |
| **Network**          | 请求列表、耗时、响应体；不用抓包就能看接口                   |

> 注意：Performance 面板在 debug 模式下的数据基本没有参考价值（JIT + 断言开销太大），必须用 `--profile`。

## 七、实战：真机连局域网后端

默认配置走内存 Mock，装完就能登录。要连真实后端，需要两个 `--dart-define`：

```bash
flutter run \
  --dart-define=USE_MOCK=false \
  --dart-define=API_BASE_URL=http://192.168.1.100:8080/api/v1
```

### 坑 1：不能用 localhost

真机上的 `localhost` / `127.0.0.1` 指向**手机自己**，不是你的电脑。必须写电脑的局域网 IP，并且：

- 手机和电脑连同一个 Wi-Fi / 同一网段
- 后端服务监听 `0.0.0.0` 而不是 `127.0.0.1`
- 电脑防火墙放行该端口（Windows Defender 会拦）

查本机局域网 IP：

```bash
ipconfig | findstr IPv4
```

### 坑 2：Android 9+ 默认禁止明文 HTTP

如果后端是 `http://`（不是 https），请求会直接失败，日志里通常看不出明显原因。需要在**仅 debug** 的清单里放开：

```xml

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.INTERNET"/>

    
    <application android:usesCleartextTraffic="true" />
</manifest>
```

**不要把这个属性加到 `src/main/AndroidManifest.xml`**，否则 release 包也会允许明文传输，属于安全问题（应用商店审核也会标记）。

## 八、常见问题速查

| 现象                                   | 原因                       | 处理                                       |
| ------------------------------------ | ------------------------ | ---------------------------------------- |
| `flutter devices` 看不到设备              | USB 模式是「仅充电」             | 改成「传输文件 / MTP」                           |
| 同上                                   | 数据线只能充电                  | 换一根能传数据的线                                |
| `unauthorized`                       | 手机没确认授权                  | 看手机弹窗勾「一律允许」；无弹窗则拔插                      |
| `INSTALL_FAILED_USER_RESTRICTED`     | 小米/OPPO 的「USB 安装」没开      | 见 2.2 表格                                 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 手机上装过签名不同的同包名应用          | 先卸载旧包                                    |
| 连接频繁断开                               | 前置 USB 口供电不足             | 换主板后面的 USB 口，或换短一点的线                     |
| 热重载没反应                               | 改了必须重启的内容                | 按 `R`；改依赖则完全重跑                           |
| 真机连不上后端                              | 用了 localhost 或明文 HTTP 被拦 | 见第七节                                     |
| 中文显示成方框                              | 极少数定制 ROM 字体缺失           | 在 `ThemeData` 里显式指定 `fontFamilyFallback` |

## 九、性能验证：debug 不代表真实水平

很多人第一次真机跑会觉得"怎么有点卡"，其实是被 debug 模式骗了。

| 模式      | 命令                      | 体积（本项目实测） | 性能            | 用途             |
| ------- | ----------------------- | --------- | ------------- | -------------- |
| debug   | `flutter run`           | 200 MB    | 差（JIT + 断言全开） | 日常开发、断点调试      |
| profile | `flutter run --profile` | ~50 MB    | 接近 release    | **性能分析、流畅度评估** |
| release | `flutter run --release` | 18 MB     | 真实水平          | 验收、给他人试用       |

判断"这个页面滑起来卡不卡"，必须用 `--profile`。debug 下的掉帧八成是调试器本身的锅。
