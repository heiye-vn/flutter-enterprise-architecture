# 04 企业级状态管理全景实战

在现代 GUI 应用开发中，状态管理始终是工程架构的核心战场。在 Flutter 生态中，企业级开发主要由两大方案统治：
1. **Riverpod 2.x**：由 Provider 原作者重构的**现代响应式声明式方案**，依托代码生成（Code Generation）与编译期安全，极度契合敏捷迭代与复杂异步状态管理。
2. **BLoC 8.x (Business Logic Component)**：大厂金融级、强规范体系推崇的**严格事件驱动流式架构**，通过严格的单向数据流与状态机机制，具备极高的可审计性与可预测性。

本篇将对两大顶尖方案进行**同等深度的工业级实操剖析**，涵盖核心概念、代码生成、异步状态处理、副作用拦截与单测规范。

---

## 1. 方案选型与架构对照表

```mermaid
flowchart LR
    subgraph Riverpod["Riverpod 2.x 响应式模型"]
        UI1["Widget / ConsumerWidget"] -->|ref.read() 触发动作| Notifier["Notifier / AsyncNotifier"]
        Notifier -->|状态变更| StateFlow["AsyncValue (Loading/Data/Error)"]
        StateFlow -->|ref.watch() 驱动局部刷新| UI1
    end

    subgraph BLoC["BLoC 8.x 单向事件流模型"]
        UI2["Widget"] -->|add(Event) 派发事件| Bloc["BLoC (Event -> Transformer -> State)"]
        Bloc -->|emit(State) 状态发射| StateStream["State 状态流"]
        StateStream -->|BlocBuilder / BlocListener| UI2
    end
```

| 维度对比 | Riverpod 2.x (推荐现代标准) | BLoC 8.x (推荐金融/大厂重规范) |
| :--- | :--- | :--- |
| **设计范式** | **响应式数据流 / 声明式依赖注入** | **单向数据流 / 事件驱动状态机** |
| **Context 依赖** | **完全解耦**：无需 `BuildContext` 即可读取/变更状态 | **弱解耦**：UI 层读取通常需要 `context.read<T>()` 向上溯源 |
| **样板代码量** | 极少（借助 `@riverpod` 注解与代码生成） | 较多（必须分别定义 Event、State、Bloc 类） |
| **异步状态机制** | 原生内置 `AsyncValue`（自动统一加载、报错、重试） | 需手动声明 Loading / Success / Failure 状态类 |
| **事件拦截治理** | 依赖 RxDart 或手动控制异步节流 | 原生支持 `EventTransformer`（防抖 debounce、丢弃 droppable） |
| **状态持久化** | 需结合本地存储中间件自行管理 | 原生生态集成 `HydratedBloc`（零配置开箱缓存） |
| **测试便利度** | 依赖 `ProviderContainer`，极易 Mock | 官方提供 `bloc_test`，语法极其优雅断言 |

## 2. 深度实战一：Riverpod 2.x 企业级标准

Riverpod 2.x 彻底废弃了手写繁琐 Provider 的旧模式，全面拥抱 **`riverpod_annotation` + 代码生成**。

### 2.1 依赖引入与环境准备

```yaml
# pubspec.yaml
dependencies:
  flutter:
    sdk: flutter
  flutter_riverpod: ^2.5.1
  riverpod_annotation: ^2.3.5

dev_dependencies:
  build_runner: ^2.4.9
  riverpod_generator: ^2.4.0
```

在应用入口根节点包裹 `ProviderScope`：

```dart
// main.dart
void main() {
  runApp(
    // 根节点注入 Provider 容器
    const ProviderScope(child: MyApp()),
  );
}
```

### 2.2 生产级 AsyncNotifier（异步分页/数据流控制器）

以企业级电商商品列表为例，支持异步加载、搜索参数联动与刷新：

```dart
// lib/features/product/presentation/controllers/product_controller.dart
import 'package:riverpod_annotation/riverpod_annotation.dart';
import '../../domain/entities/product_entity.dart';
import '../../../../core/di/service_locator.dart';

// 声明代码生成部分文件
part 'product_controller.g.dart';

// @riverpod 注解自动生成带生命周期的 ProductControllerProvider
// family 参数允许在构造时动态传入 categoryId
@riverpod
class ProductController extends _$ProductController {
  @override
  FutureOr<List<ProductEntity>> build({required String categoryId}) async {
    // build 方法在初次 watch 时执行，返回初始状态
    return _fetchProducts(categoryId);
  }

  Future<List<ProductEntity>> _fetchProducts(String categoryId) async {
    // 模拟调用 UseCase 或仓库
    await Future.delayed(const Duration(milliseconds: 600));
    return [
      ProductEntity(id: '101', name: 'MacBook Pro', price: 12999.0),
      ProductEntity(id: '102', name: 'iPad Pro', price: 6799.0),
    ];
  }

  // 业务动作：刷新
  Future<void> refresh() async {
    // 1. 设置状态为 loading（同时保留上一轮的旧数据以便平滑展示）
    state = const AsyncLoading();
    // 2. 重新拉取并更新 state
    state = await AsyncValue.guard(() => _fetchProducts(categoryId));
  }

  // 业务动作：添加商品
  Future<void> addProduct(String name, double price) async {
    // 乐观更新或调用接口
    final previousState = state;
    try {
      final newProduct = ProductEntity(id: DateTime.now().toString(), name: name, price: price);
      // 成功后追加到当前列表中
      state = AsyncData([...state.value ?? [], newProduct]);
    } catch (e, st) {
      // 出现异常回滚
      state = previousState;
    }
  }
}
```

运行代码生成命令：
```bash
dart run build_runner build --delete-conflicting-outputs
```

### 2.3 UI 消费层：精准局部刷新与模式匹配

```dart
// lib/features/product/presentation/pages/product_list_page.dart
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import '../controllers/product_controller.dart';

// 继承 ConsumerWidget 取代普通的 StatelessWidget
class ProductListPage extends ConsumerWidget {
  final String categoryId;
  const ProductListPage({super.key, required this.categoryId});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    // 1. ref.watch 监听状态改变。一旦列表有变动，仅当前 build 方法重绘
    final productState = ref.watch(productControllerProvider(categoryId: categoryId));

    return Scaffold(
      appBar: AppBar(
        title: const Text('商品列表'),
        actions: [
          IconButton(
            icon: const Icon(Icons.refresh),
            // 2. ref.read 用于在点击等回调事件中触发动作，绝不要在 build 中使用 ref.read 监听
            onPressed: () => ref.read(productControllerProvider(categoryId: categoryId).notifier).refresh(),
          ),
        ],
      ),
      // 3. AsyncValue 的模式匹配：优雅统一处理 loading / error / data 态
      body: productState.when(
        loading: () => const Center(child: CircularProgressIndicator()),
        error: (err, stack) => Center(
          child: Column(
            mainAxisSize: MainAxisSize.min,
            children: [
              Text('加载失败: $err', style: const TextStyle(color: Colors.red)),
              ElevatedButton(
                onPressed: () => ref.read(productControllerProvider(categoryId: categoryId).notifier).refresh(),
                child: const Text('重试'),
              ),
            ],
          ),
        ),
        data: (products) {
          if (products.isEmpty) {
            return const Center(child: Text('暂无商品'));
          }
          return ListView.separated(
            itemCount: products.length,
            separatorBuilder: (_, __) => const Divider(),
            itemBuilder: (context, index) {
              final product = products[index];
              return ListTile(
                title: Text(product.name),
                trailing: Text('¥\${product.price.toStringAsFixed(2)}'),
              );
            },
          );
        },
      ),
    );
  }
}
```

## 3. 深度实战二：BLoC 8.x 企业级标准

BLoC 依托响应式流（Streams），强调“**事件进入（Event In），状态产出（State Out）**”。

### 3.1 依赖引入

```yaml
# pubspec.yaml
dependencies:
  flutter_bloc: ^8.1.5
  equatable: ^2.0.5      # 用于值对象比对，避免不必要的重复重绘
  bloc_concurrency: ^0.2.5 # 事件并发控制器 (防抖、丢弃)
  hydrated_bloc: ^9.1.5   # 自动持久化状态中间件
```

### 3.2 严密的事件与状态定义

```dart
// lib/features/order/presentation/bloc/order_event.dart
import 'package:equatable/equatable.dart';

sealed class OrderEvent extends Equatable {
  const OrderEvent();
  @override
  List<Object?> get props => [];
}

// 事件1：拉取订单列表
final class OrderFetchStarted extends OrderEvent {
  final String status;
  const OrderFetchStarted({required this.status});
  @override
  List<Object?> get props => [status];
}

// 事件2：取消订单（防重复点击）
final class OrderCancelRequested extends OrderEvent {
  final String orderId;
  const OrderCancelRequested({required this.orderId});
  @override
  List<Object?> get props => [orderId];
}

// lib/features/order/presentation/bloc/order_state.dart
import 'package:equatable/equatable.dart';
import '../../domain/entities/order_entity.dart';

sealed class OrderState extends Equatable {
  const OrderState();
  @override
  List<Object?> get props => [];
}

final class OrderInitial extends OrderState {}

final class OrderLoading extends OrderState {}

final class OrderSuccess extends OrderState {
  final List<OrderEntity> orders;
  final bool hasReachedMax;

  const OrderSuccess({required this.orders, this.hasReachedMax = false});

  // copyWith 便于不可变对象的增量变更
  OrderSuccess copyWith({List<OrderEntity>? orders, bool? hasReachedMax}) {
    return OrderSuccess(
      orders: orders ?? this.orders,
      hasReachedMax: hasReachedMax ?? this.hasReachedMax,
    );
  }

  @override
  List<Object?> get props => [orders, hasReachedMax];
}

final class OrderFailure extends OrderState {
  final String errorMessage;
  const OrderFailure({required this.errorMessage});
  @override
  List<Object?> get props => [errorMessage];
}
```

### 3.3 生产级 BLoC 实现与高级 EventTransformer

```dart
// lib/features/order/presentation/bloc/order_bloc.dart
import 'package:flutter_bloc/flutter_bloc.dart';
import 'package:bloc_concurrency/bloc_concurrency.dart';
import 'order_event.dart';
import 'order_state.dart';
import '../../domain/repositories/order_repository.dart';

class OrderBloc extends Bloc<OrderEvent, OrderState> {
  final OrderRepository _orderRepository;

  OrderBloc({required OrderRepository orderRepository})
      : _orderRepository = orderRepository,
        super(OrderInitial()) {
    
    // 1. 注册事件处理管道
    // 使用 droppable(): 若上一次拉取尚未完成，后续连点派发的事件直接丢弃，彻底杜绝并发重复请求！
    on<OrderFetchStarted>(
      _onOrderFetchStarted,
      transformer: droppable(),
    );

    // 2. 取消订单事件
    on<OrderCancelRequested>(_onOrderCancelRequested);
  }

  Future<void> _onOrderFetchStarted(
    OrderFetchStarted event,
    Emitter<OrderState> emit,
  ) async {
    try {
      emit(OrderLoading());
      final result = await _orderRepository.getOrders(status: event.status);
      emit(OrderSuccess(orders: result));
    } catch (e) {
      emit(OrderFailure(errorMessage: e.toString()));
    }
  }

  Future<void> _onOrderCancelRequested(
    OrderCancelRequested event,
    Emitter<OrderState> emit,
  ) async {
    final currentState = state;
    if (currentState is OrderSuccess) {
      try {
        await _orderRepository.cancelOrder(event.orderId);
        // 本地移除该订单并产生新不可变状态
        final updatedList = currentState.orders.where((o) => o.id != event.orderId).toList();
        emit(currentState.copyWith(orders: updatedList));
      } catch (e) {
        emit(OrderFailure(errorMessage: '取消订单失败: $e'));
      }
    }
  }
}
```

### 3.4 UI 消费层：BlocConsumer 拆解渲染与副作用

在实际业务开发中，经常面临“既要根据数据重绘列表，又要在失败时弹出 Toast 提示框”的场景。
- **`BlocBuilder`**：专职负责纯 UI 构建，必须是纯函数，严禁在里面弹出 Dialog / Toast！
- **`BlocListener`**：专职监听状态变更以触发副作用（Navigation 跳转、弹出 SnackBar）。
- **`BlocConsumer`**：二合一组件，清晰分离两者：

```dart
// lib/features/order/presentation/pages/order_list_page.dart
import 'package:flutter/material.dart';
import 'package:flutter_bloc/flutter_bloc.dart';
import '../bloc/order_bloc.dart';
import '../bloc/order_event.dart';
import '../bloc/order_state.dart';

class OrderListPage extends StatelessWidget {
  const OrderListPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('我的订单')),
      body: BlocConsumer<OrderBloc, OrderState>(
        // 1. listener 只在状态改变时触发一次，专用于执行副作用
        listener: (context, state) {
          if (state is OrderFailure) {
            ScaffoldMessenger.of(context).showSnackBar(
              SnackBar(content: Text(state.errorMessage), backgroundColor: Colors.red),
            );
          }
        },
        // 2. builder 负责纯视图渲染
        builder: (context, state) {
          return switch (state) {
            OrderInitial() => const Center(child: Text('请点击加载订单')),
            OrderLoading() => const Center(child: CircularProgressIndicator()),
            OrderFailure(errorMessage: var msg) => Center(child: Text('错误: $msg')),
            OrderSuccess(orders: var items) => items.isEmpty
                ? const Center(child: Text('暂无订单'))
                : ListView.builder(
                    itemCount: items.length,
                    itemBuilder: (context, index) {
                      final item = items[index];
                      return ListTile(
                        title: Text('订单号: ${item.orderNo}'),
                        subtitle: Text('金额: ¥${item.totalAmount}'),
                        trailing: TextButton(
                          onPressed: () => context.read<OrderBloc>().add(
                                OrderCancelRequested(orderId: item.id),
                              ),
                          child: const Text('取消订单', style: TextStyle(color: Colors.red)),
                        ),
                      );
                    },
                  ),
          };
        },
      ),
    );
  }
}
```

## 4. 单元测试深度对比

企业级项目必须保障核心业务状态流 100% 可测。

### 4.1 测试 Riverpod Notifier

```dart
// test/product_controller_test.dart
import 'package:flutter_test/flutter_test.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';

void main() {
  test('ProductController should emit loading and then data', () async {
    // 实例化独立的容器，完全独立于 UI
    final container = ProviderContainer();
    addTearDown(container.dispose);

    // 读取并监听 provider
    final subscription = container.listen(
      productControllerProvider(categoryId: 'tech'),
      (previous, next) {},
      fireImmediately: true,
    );

    // 初始状态应处于加载中
    expect(subscription.read(), const AsyncLoading<List<ProductEntity>>());

    // 等待异步加载完成
    final data = await container.read(productControllerProvider(categoryId: 'tech').future);
    expect(data.length, 2);
    expect(data.first.name, 'MacBook Pro');
  });
}
```

### 4.2 测试 BLoC (`bloc_test`)

```dart
// test/order_bloc_test.dart
import 'package:bloc_test/bloc_test.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:mocktail/mocktail.dart';

class MockOrderRepository extends Mock implements OrderRepository {}

void main() {
  late MockOrderRepository mockRepo;

  setUp(() {
    mockRepo = MockOrderRepository();
  });

  // blocTest 提供了结构化的 build/act/expect 管道
  blocTest<OrderBloc, OrderState>(
    'emits [OrderLoading, OrderSuccess] when OrderFetchStarted is added',
    build: () {
      when(() => mockRepo.getOrders(status: 'all'))
          .thenAnswer((_) async => [const OrderEntity(id: '1', orderNo: 'ORD001', totalAmount: 99.0)]);
      return OrderBloc(orderRepository: mockRepo);
    },
    act: (bloc) => bloc.add(const OrderFetchStarted(status: 'all')),
    expect: () => [
      isA<OrderLoading>(),
      isA<OrderSuccess>().having((s) => s.orders.length, 'orders.length', 1),
    ],
  );
}
```

## 5. 企业级选型决策准则

1. **若团队偏敏捷交付、追求快速迭代、追求轻量与代码生成**：
   - 坚决选择 **Riverpod 2.x**。其 `AsyncValue` 对网络请求与异步刷新的封装无出其右，声明式与函数式响应心智高度统一。
2. **若系统属于金融、证券、电商核心支付结算链路、团队规模大、对审计和状态溯源有极端要求**：
   - 坚决选择 **BLoC 8.x**。BLoC 能够接入全局 `BlocObserver` 打印全链路事件追踪日志，严格的事件拦截器能够从物理机制上彻底扼制重复提交与并发竞态缺陷。
