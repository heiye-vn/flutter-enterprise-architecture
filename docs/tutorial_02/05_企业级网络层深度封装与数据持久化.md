# 05 企业级网络层深度封装与数据持久化

在企业级客户端架构中，网络层不仅是“发个请求拿 JSON”，更需要承担**双 Token 无感刷新**、**并发请求重放队列**、**防重复提交**、**统一业务异常映射**以及**离线数据持久化与缓存穿透治理**。

本篇将手把手带你使用 **Dio** 打造生产级网络客户端，结合 **Freezed** 打造强类型不可变模型，并系统对比 **MMKV**、**Hive** 与 **Drift (SQLite)** 的持久化选型与落地实操。

---

## 1. 工业级 Dio 架构设计全景

```mermaid
flowchart TD
    Req([发起业务请求]) --> HeaderInter[Header / 设备信息拦截器]
    HeaderInter --> AntiDupInter[防重复提交拦截器 (CancelToken)]
    AntiDupInter --> LogInter[安全日志拦截器 (PrettyLogger)]
    LogInter --> NetworkCall[物理网络传输 (HttpAdapter)]
    
    NetworkCall --> RespCheck{HTTP 状态码 / 业务码检查}
    RespCheck -- 正常 200 --> DataTransform[JSON 转换与 Model 序列化] --> Success([返回业务数据])
    
    RespCheck -- 401 令牌过期 --> LockCheck{并发刷新锁已占用?}
    LockCheck -- 否 (首个触发者) --> AcquireLock[加锁并调用 RefreshToken API]
    AcquireLock --> RefreshSuccess{刷新成功?}
    RefreshSuccess -- 是 --> SaveToken[更新本地 Token] --> ReplayQueue[重放待发队列所有请求] --> Unlock[释放锁] --> Success
    RefreshSuccess -- 否 --> ClearSession[清空本地登录态] --> ForceLogout([强制跳回登录页])
    
    LockCheck -- 是 (后续并发者) --> WaitQueue[将当前请求挂起压入重试队列]
    WaitQueue -.-> ReplayQueue
```

## 2. 生产级双 Token 无感刷新拦截器（完整源码）

在多并发请求同时遇到 Token 过期时，若不加控制，会导致客户端同时发出十几次刷新 Token 请求导致后端黑名单封禁。以下是生产环境验证过的“**单飞刷新锁 + 请求挂起重放队列**”拦截器实现：

```dart
// lib/core/network/interceptors/auth_interceptor.dart
import 'dart:async';
import 'package:dio/dio.dart';

abstract class TokenStorage {
  Future<String?> getAccessToken();
  Future<String?> getRefreshToken();
  Future<void> saveTokens({required String accessToken, required String refreshToken});
  Future<void> clearTokens();
}

class AuthInterceptor extends QueuedInterceptor {
  final Dio _dio;
  final TokenStorage _tokenStorage;
  final String _refreshEndpoint;
  
  // 刷新锁：确保全局同时仅有一个刷新请求在执行
  bool _isRefreshing = false;
  // 挂起重试请求队列
  final List<({RequestOptions options, ErrorInterceptorHandler handler})> _retryQueue = [];

  AuthInterceptor({
    required Dio dio,
    required TokenStorage tokenStorage,
    String refreshEndpoint = '/api/v1/auth/refresh',
  })  : _dio = dio,
        _tokenStorage = tokenStorage,
        _refreshEndpoint = refreshEndpoint;

  @override
  Future<void> onRequest(
    RequestOptions options,
    RequestInterceptorHandler handler,
  ) async {
    // 1. 注入 Access Token 到请求头
    final accessToken = await _tokenStorage.getAccessToken();
    if (accessToken != null && accessToken.isNotEmpty) {
      options.headers['Authorization'] = 'Bearer $accessToken';
    }
    options.headers['X-Device-Platform'] = 'flutter-cross-platform';
    return handler.next(options);
  }

  @override
  Future<void> onError(
    DioException err,
    ErrorInterceptorHandler handler,
  ) async {
    final response = err.response;
    
    // 2. 检查是否为 401 未授权错误，且并非当前正在刷新的接口本身报错
    if (response?.statusCode == 401 && !err.requestOptions.path.contains(_refreshEndpoint)) {
      if (_isRefreshing) {
        // 如果当前正在刷新，将后续请求挂起压入队列
        _retryQueue.add((options: err.requestOptions, handler: handler));
        return;
      }

      _isRefreshing = true;
      try {
        final refreshToken = await _tokenStorage.getRefreshToken();
        if (refreshToken == null) {
          throw Exception('No refresh token available');
        }

        // 3. 使用独立的 Dio 发起刷新请求，避免拦截器死循环
        final refreshDio = Dio(BaseOptions(baseUrl: _dio.options.baseUrl));
        final refreshResponse = await refreshDio.post(
          _refreshEndpoint,
          data: {'refresh_token': refreshToken},
        );

        final newAccessToken = refreshResponse.data['access_token'] as String;
        final newRefreshToken = refreshResponse.data['refresh_token'] as String;

        // 4. 持久化新 Token
        await _tokenStorage.saveTokens(
          accessToken: newAccessToken,
          refreshToken: newRefreshToken,
        );

        // 5. 立即重放当前触发 401 的请求
        final originOptions = err.requestOptions;
        originOptions.headers['Authorization'] = 'Bearer $newAccessToken';
        final originResponse = await _dio.fetch(originOptions);
        handler.resolve(originResponse);

        // 6. 依次重放等待队列中的所有请求
        for (final item in _retryQueue) {
          item.options.headers['Authorization'] = 'Bearer $newAccessToken';
          final retriedResponse = await _dio.fetch(item.options);
          item.handler.resolve(retriedResponse);
        }
        _retryQueue.clear();
      } catch (refreshError) {
        // 刷新彻底失败：通知全局清退登录态
        await _tokenStorage.clearTokens();
        for (final item in _retryQueue) {
          item.handler.reject(err);
        }
        _retryQueue.clear();
        handler.reject(err);
      } finally {
        _isRefreshing = false;
      }
      return;
    }

    return handler.next(err);
  }
}
```

## 3. 防重复提交拦截器（Anti-Duplicate）

```dart
// lib/core/network/interceptors/anti_duplicate_interceptor.dart
import 'package:dio/dio.dart';

class AntiDuplicateInterceptor extends Interceptor {
  // 维护活跃请求的哈希池
  final Set<String> _inFlightRequests = {};

  String _generateRequestKey(RequestOptions options) {
    return '${options.method}:${options.path}:${options.data?.toString()}';
  }

  @override
  void onRequest(RequestOptions options, RequestInterceptorHandler handler) {
    // 仅针对非幂等请求（POST/PUT/DELETE）进行防重拦截
    if (options.method.toUpperCase() != 'GET') {
      final key = _generateRequestKey(options);
      if (_inFlightRequests.contains(key)) {
        // 判定为重复连击，立即取消本次请求
        return handler.reject(
          DioException(
            requestOptions: options,
            type: DioExceptionType.cancel,
            error: 'Duplicate request blocked: Please do not submit repeatedly.',
          ),
        );
      }
      _inFlightRequests.add(key);
    }
    handler.next(options);
  }

  @override
  void onResponse(Response response, ResponseInterceptorHandler handler) {
    _inFlightRequests.remove(_generateRequestKey(response.requestOptions));
    handler.next(response);
  }

  @override
  void onError(DioException err, ErrorInterceptorHandler handler) {
    _inFlightRequests.remove(_generateRequestKey(err.requestOptions));
    handler.next(err);
  }
}
```

## 4. 不可变数据模型：Freezed 最佳实践

在 Dart 中手写带有 `copyWith`、`equals`、`hashCode` 以及序列化的模型极其冗长。现代 Flutter 企业开发标配 **`freezed` + `json_serializable`**。

### 4.1 引入依赖

```yaml
dependencies:
  freezed_annotation: ^2.4.4
  json_annotation: ^4.9.0

dev_dependencies:
  build_runner: ^2.4.9
  freezed: ^2.5.2
  json_serializable: ^6.8.0
```

### 4.2 强类型不可变模型定义

```dart
// lib/features/order/data/models/order_detail_model.dart
import 'package:freezed_annotation/freezed_annotation.dart';

part 'order_detail_model.freezed.dart';
part 'order_detail_model.g.dart';

@freezed
class OrderDetailModel with _$OrderDetailModel {
  const factory OrderDetailModel({
    required String orderId,
    required double totalPrice,
    @Default('CREATED') String status,
    @JsonKey(name: 'created_timestamp') required int createdTimestamp,
    @Default([]) List<String> skuList,
  }) = _OrderDetailModel;

  // 配合 json_serializable 实现自动从 JSON 反序列化
  factory OrderDetailModel.fromJson(Map<String, dynamic> json) =>
      _$OrderDetailModelFromJson(json);
}
```

执行生成代码：
```bash
dart run build_runner build --delete-conflicting-outputs
```

#### 使用不可变特性的优势：
```dart
void testFreezed() {
  const orderA = OrderDetailModel(orderId: 'A001', totalPrice: 99.0, createdTimestamp: 167000000);
  
  // 1. 结构性全等比对（基于字段值，而非内存指针）
  const orderB = OrderDetailModel(orderId: 'A001', totalPrice: 99.0, createdTimestamp: 167000000);
  print(orderA == orderB); // true! (如果是普通类则是 false)

  // 2. 局部增量不可变更新 (copyWith)
  final updatedOrder = orderA.copyWith(totalPrice: 199.0, status: 'PAID');
  print(updatedOrder.status); // 'PAID'
}
```

## 5. 本地数据持久化选型与实战

企业级跨端开发有四种主要持久化存储，选型决策矩阵如下：

| 技术方案 | 底层驱动 | 读写吞吐 | 适用场景 | 多端支持度 |
| :--- | :--- | :--- | :--- | :--- |
| **`shared_preferences`** | 原生平台存储 (NSUserDefaults / SharedPreferences / Web LocalStorage) | 中等偏低（异步全量写） | 保存用户偏好设置（如深色模式开关、引导页标记、语言环境） | 优秀 (全端支持) |
| **`flutter_mmkv`** | 腾讯 MMKV (mmap 内存映射物理文件) | **极致极高** | 高频高吞吐键值缓存、日志写入、Token、即时消息草稿 | 移动与桌面端优秀 (Web 降级) |
| **`drift` (推荐关系型)** | SQLite (C 语言轻量数据库) + 响应式 Stream | 强一致、支持复杂多表关联索引与亿级数据筛选 | 离线协同、复杂 CRM/ERP 离线表单、即时通讯聊天记录库 | 优秀 (全端支持，Web 借助 WASM) |
| **`hive` / `isar`** | 纯 Dart / 原生 NoSQL | 极快（无需 SQL 解析） | 纯文档/JSON 对象的持久化缓存 | 优秀 |

### 5.1 生产级 Drift 响应式数据库实操

`drift`（原名 Moor）是目前 Flutter 最健壮的类型安全 SQLite 封装，支持直接将 SQL 查询转化为强类型 Dart Stream。

```dart
// lib/core/database/app_database.dart
import 'package:drift/drift.dart';
import 'package:drift/native.dart';
import 'dart:io';
import 'package:path_provider/path_provider.dart';
import 'package:path/path.dart' as p;

part 'app_database.g.dart';

// 1. 定义数据表 (Schema)
class CachedArticles extends Table {
  TextColumn get id => text()();
  TextColumn get title => text().withLength(min: 1, max: 200)();
  TextColumn get content => text()();
  RealColumn get rating => real().withDefault(const Constant(0.0))();
  DateTimeColumn get savedAt => dateTime().withDefault(currentDateAndTime)();

  @override
  Set<Column> get primaryKey => {id};
}

// 2. 数据库容器类
@DriftDatabase(tables: [CachedArticles])
class AppDatabase extends _$AppDatabase {
  AppDatabase() : super(_openConnection());

  @override
  int get schemaVersion => 1;

  // 响应式查询：直接返回 Stream！当表中数据有任何增删改，UI 自动收到实时通知！
  Stream<List<CachedArticle>> watchAllArticles() {
    return (select(cachedArticles)..orderBy([(t) => OrderingTerm.desc(t.savedAt)])).watch();
  }

  // 写入或更新 (Upsert)
  Future<int> insertOrUpdateArticle(CachedArticlesCompanion article) {
    return into(cachedArticles).insertOnConflictUpdate(article);
  }
}

LazyDatabase _openConnection() {
  return LazyDatabase(() async {
    final dbFolder = await getApplicationDocumentsDirectory();
    final file = File(p.join(dbFolder.path, 'app_enterprise.sqlite'));
    return NativeDatabase.createInBackground(file);
  });
}
```

在 UI 中监听 Drift 数据库极度自然：
```dart
StreamBuilder<List<CachedArticle>>(
  stream: db.watchAllArticles(),
  builder: (context, snapshot) {
    final articles = snapshot.data ?? [];
    return ListView.builder(
      itemCount: articles.length,
      itemBuilder: (_, i) => Text(articles[i].title),
    );
  },
);
```

## 6. 统一错误处理与领域异常映射

Dio 抛出的是底层网络错误 `DioException`。若将其直接抛给 UI，会导致 UI 充斥 `SocketException` 或 `HttpException` 等杂乱报错。在 Data 层必须统一转译为领域异常：

```dart
// lib/core/network/exceptions/app_exception.dart
sealed class AppException implements Exception {
  final String message;
  const AppException(this.message);
}

class NetworkException extends AppException {
  const NetworkException([super.message = '网络连接超时，请检查网络']);
}

class UnauthorizedException extends AppException {
  const UnauthorizedException([super.message = '登录状态已失效，请重新登录']);
}

class ServerBusinessException extends AppException {
  final int businessCode;
  const ServerBusinessException(this.businessCode, super.message);
}

// 工具函数：拦截并转译
AppException mapDioExceptionToDomain(DioException e) {
  return switch (e.type) {
    DioExceptionType.connectionTimeout ||
    DioExceptionType.sendTimeout ||
    DioExceptionType.receiveTimeout => const NetworkException(),
    DioExceptionType.badResponse => switch (e.response?.statusCode) {
      401 => const UnauthorizedException(),
      _ => ServerBusinessException(
          e.response?.statusCode ?? 500,
          e.response?.data?['message']?.toString() ?? '服务器异常',
        ),
    },
    _ => const NetworkException('未知网络异常'),
  };
}
```

## 7. 架构总结

1. **Token 刷新防雪崩**：必须依托 `QueuedInterceptor` 并配置全局互斥锁与挂起重试队列。
2. **不可变数据红线**：所有网络传输 DTO 模型统一使用 `freezed` 生成，杜绝引用变更造成的隐蔽 Bug。
3. **分级持久化**：轻量配置用 `shared_preferences`；高吞吐高频 KV 用 `mmkv`；复杂结构化离线协同数据库坚定采用 `drift`。
